核心问题与动机

RLVR（Reinforcement Learning with Verifiable Rewards）已成为提升 VLM 推理能力的关键技术，但其结果级（outcome-level）奖励信号过于粗糙，无法定位推理链中具体哪一步出了错。VLM 在多步推理中频繁出现感知幻觉（插入不存在的物体、错误的空间关系），但只有最终奖励才给出反馈，导致严重的信用分配问题。

本文提出核心问题：能否构建一个以感知为中心的过程奖励模型（PRM），在 token 级别定位并惩罚幻觉，从而提供更细粒度的训练监督和推理纠错？

方法概述

Perceval：感知级过程奖励模型

Perceval 是一个生成式过程奖励模型，给定图像 v、问题 q、模型回答 o，输出结构化的验证结果：

  1. …：逐条分析回答中每个感知 claim 是否与图像视觉证据一致
  2. …：若无错误输出 "The response is correct."；否则输出一个 Python 列表，包含被识别为幻觉的原文子串

这种设计直接定位错误 span，而非给出单一标量分数。

PRM 训练流程（四阶段）

  1. 查询选择：主要来自视觉搜索数据集（如 V*、DeepEyes），辅以少量数学推理和通用理解数据
  2. Rollout 生成：用 Qwen2.5-VL-7B 生成回答（其不完美的感知对齐天然产生丰富的幻觉样本）
  3. 自动标注与验证：使用强模型（如 Gemini-2.5-Pro）进行幻觉检测的逐步验证，生成结构化标注
  4. 监督微调：在聚合数据上 SFT 训练 Perceval 模型

RLVR 中的过程级监督

标准 GRPO 的优势值 Âi 是序列级的，对同一回答中所有 token 一视同仁。Perceval 的改进：

  1. 用 Perceval 识别每个回答中的幻觉 token span，构建二值掩码 Mi
  2. 将序列级优势改为token 级优势：

  • 正确 token (m = 0)：保持原优势 Âi
  • 幻觉 token (m = 1)：优势被削弱——winner 序列变为 Âi(1 − α)，loser 序列变为 Âi(1 + α)（惩罚更重）
  1. 将 Â′i, t 替换进 GRPO 目标函数

关键设计：仅在感知相关数据上使用 Perceval 干预，数学推理等其他数据仍使用标准 GRPO。这使得可以验证感知增强是否能泛化到其他推理领域。

推理时的 Test-Time Scaling

Perceval 在推理阶段也可用于迭代纠错，设计了两种策略：

  1. Truncate–then–Regenerate：检测到幻觉后，截断错误 span 之前的内容，保留已验证的前缀，让模型从该位置重新生成
  2. Truncate–Thinking–then–Regenerate：在截断后插入反思提示（如 “Wait, I need to reconsider…”），引导模型反思后再生

两种策略均可迭代最多 k 次，直到 Perceval 不再检测到错误。

图 3：定性分析案例

任务：判断高分辨率图中蓝色车辆与白色车辆的相对位置

  • GRPO 基线：跳过感知步骤，直接输出 “left”（典型幻觉）
  • Perceval 方法：逐步定位白色车辆 → 搜索蓝色车辆 → 正确推断相对位置

优势

  1. 细粒度监督：token 级优势重分配，比序列级 GRPO 奖励更精准地定位和纠正幻觉
  2. 抗 reward hacking：不直接输出标量分数，而是通过修改优势值间接干预，更难被策略模型利用
  3. 感知泛化：仅在感知数据上施加 PRM 干预，但数学/图表推理也获得一致提升——“能力迁移”效应显著
  4. 推理时可扩展：Truncate 策略在推理阶段也能使用，且随迭代次数增加持续提升
  5. 无需外部工具：7B 模型在视觉搜索上媲美使用外部工具（如 DeepEyes、Pixel-Reasoner）的 SOTA 方法

局限性

  1. PRM 训练依赖强教师模型：标注质量受 Gemini-2.5-Pro 等闭源模型限制
  2. 感知任务为主：PRM 设计聚焦感知错误检测，对逻辑推理错误的检测能力有限
  3. Truncate 策略的序列开销：迭代截断-再生需要多次前向传播，增加推理延迟
  4. 模型规模探索有限：主要在 3B/7B 上实验，更大规模的扩展行为未验证
  5. 反思策略效果弱于 Truncate：可能因训练数据中缺少反思样例，导致模型对反思 prompt 的遵循质量不足

复现 / 实现要点

  • 基础模型：Qwen2.5-VL（3B / 7B）作为 PRM 和策略模型的骨干
  • PRM 训练数据：来自 DeepEyes 和 SophiaVL-R1，每条 rollout 3 次
  • RL 训练数据：来自 DeepEyes，包含感知数据和部分通用推理数据
  • 条件干预策略：仅感知数据使用 Perceval 进行 token 级优势重分配，其他数据使用标准 GRPO
  • 超参数：α=0.1（惩罚强度），评估使用 greedy decoding + EM judge + GPT-4o-mini 二次验证
  • 评估设置：8 个基准涵盖视觉搜索（V*）、感知推理（BLINK, MMStar, MME-RealWorld, RealWorldQA）、数学/图表（MathVision, MathVista, ChartQA）

未来工作启发

  1. 扩展 PRM 到逻辑推理：当前 PRM 仅检测感知幻觉，扩展到逻辑错误检测（如数学推理中的因果错误）可进一步提升推理能力
  2. 更强的自反思训练：在 RL 训练数据中加入反思样例，可能提升 Truncate-Thinking 策略的效果
  3. PRM 与工具调用结合：将 Perceval 的检测结果与外部视觉工具（放大、裁剪）结合，形成检测-修正闭环
  4. 更大规模验证：在 70B+ 模型上验证 token 级监督的收益是否更大
  5. 自动化 PRM 数据构建：减少对闭源强模型的依赖，探索自蒸馏或对抗训练方案
  6. 多模态 PRM 统一：将感知检测、逻辑检测、事实检测统一到一个 PRM 框架中
