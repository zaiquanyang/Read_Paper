方法与框架

本文首次系统性地挑战 semi-AR 解码中的固定 block 大小设置，识别出两个根本性问题：

问题一：Late Decoding Overhead（延迟解码开销）

  • 当固定 block 较小时，当前 block 外存在高置信度 token 本可立即解码，但受限于 block 边界必须等待下一轮
  • 被延迟的高置信度 token 需要额外的去噪计算，造成不必要的算力开销
  • 一个完整语义单元（如一个简单句子）可能被分割到多个 block 中

问题二：Premature Decoding Error（过早解码错误）

  • Block 级自回归约束要求采样器在进入下一 block 前必须解码当前 block 内所有 MASK 位置
  • 这迫使采样器在当前 block 内提交低置信度 token，而非推迟它们以等待更高置信度的位置
  • 过早提交的错误 token 通过 block 级自回归依赖传播到后续步骤，导致系统性误差
  • 在推理任务（如 GSM8K 数学推理）中尤为严重

VB 区域的置信度波动和宽度差异表明，固定 block 大小无法适应不同样本的解码需求。小 block 导致延迟解码，大 block 迫使过早提交低置信度 token。需要一种能够在运行时感知语义边界、动态调整 block 大小的调度策略。

AdaBlock-dLLM 是一个训练无关（training-free）、即插即用（plug-and-play）的自适应 block 大小调度器，在进入每个 block 的第一个 token 采样之前，动态确定当前 block 大小，使得 block 边界与语义步骤（semantic steps）对齐。

核心思想：利用语义分隔 token（如换行符 \n、句号、逗号）的置信度信号来判断语义步骤边界——当模型对某个分隔 token 有高置信度预测时，说明它"确信"此处应该是语义单元的终点。

实验与结论

以 LLaDA-Instruct 在 GSM8K 上为例（B_0=32）：

| 方法 | GSM8K Acc. (%) | HumanEval Acc. (%) | MATH Acc. (%) |

|------|---------------|-------------------|---------------|

| Vanilla | 76.7 | 43.9 | 36.9 |

| Dynamic (Fast-dLLM) | 77.6 | 43.9 | 36.9 |

| +Ada (AdaBlock) | 80.6 (+3.0) | 43.3 (-0.6) | 37.3 (+0.4) |

| +Cache (Fast-dLLM) | 74.5 | 46.3 | 35.8 |

| +Ada+Cache | 78.5 (+4.0) | 46.3 (0.0) | 35.3 (-0.5) |

关键结果：

  • GSM8K 上 LLaDA-Instruct 最高提升 5.3%（B_0=64 时 +Ada+Cache 从 75.4 提升到 80.7）
  • KV Cache 场景下提升更显著：Cache 本身引入近似误差导致精度下降，AdaBlock 通过增强 block 内语义局部性、减少 block 间依赖性来弥补这一损失
  • 跨 LLaDA-Instruct、LLaDA-1.5、Dream-Base 三个模型，多数配置获得正收益

以 LLaDA-Instruct GSM8K 为例（生成预算 L=512，无 Cache）：

| B_0 | Vanilla Acc./TPS | Dynamic Acc./TPS | +Ada Acc./TPS |

|-----|-----------------|-----------------|---------------|

| 4 | 80.9 / 16.1 | 81.2 / 43.0 | 81.6 / 51.3 |

| 8 | 80.5 / 16.1 | 80.6 / 60.0 | 81.8 / 63.9 |

| 16 | 78.8 / 16.1 | 79.1 / 74.7 | 80.6 / 73.9 |

| 32 | 76.8 / 16.1 | 77.6 / 85.0 | 80.6 / 83.5 |

| 64 | 76.8 / 16.1 | 77.3 / 89.4 | 79.5 / 87.9 |

| 128 | 71.0 / 16.0 | 70.7 / 81.2 | 72.8 / 80.6 |

关键发现：

  • 小 B_0（4, 8）时 AdaBlock 同时提升精度和吞吐（有效缓解延迟解码开销）
  • 大 B_0（16, 32, 64, 128）时精度提升显著，吞吐仅有微小下降（~1-2 TPS）
  • TPS × NFE 乘积在所有方法/block 大小下几乎恒定（~8.2 × 10³），说明吞吐与 NFE 呈近似反比
  • 增大 B_0 最初提升吞吐（缓解延迟解码），但过大时吞吐反而下降（block 内语义凝聚力减弱，动态采样每步解码 token 减少）

价值、局限与启发

本文首次系统性地挑战 semi-AR 解码中的固定 block 大小设置，识别出两个根本性问题：

问题一：Late Decoding Overhead（延迟解码开销）

  • 被延迟的高置信度 token 需要额外的去噪计算，造成不必要的算力开销
  • 一个完整语义单元（如一个简单句子）可能被分割到多个 block 中

问题二：Premature Decoding Error（过早解码错误）

  • Block 级自回归约束要求采样器在进入下一 block 前必须解码当前 block 内所有 MASK 位置
  • 这迫使采样器在当前 block 内提交低置信度 token，而非推迟它们以等待更高置信度的位置
  • 过早提交的错误 token 通过 block 级自回归依赖传播到后续步骤，导致系统性误差
  • 在推理任务（如 GSM8K 数学推理）中尤为严重
  • 首次系统性挑战固定 block 大小：在此之前，semi-AR 解码的 block 大小选择被默认为固定超参数，本文首次分析其根本缺陷并提出自适应方案。
  • 训练无关、即插即用：不需要任何额外训练或微调，可直接插入现有的 Fast-dLLM 等 semi-AR 解码管线。
  • 置信度动态分析深刻：波动带（VB）、置信度局部性、全局自回归倾向等概念为理解 dLLM 解码行为提供了有价值的分析框架。
  • 与 KV Cache 方法协同增效：在 Cache 场景下增益更大（最高 5.3%），因为 AdaBlock 降低了 Cache 近似误差的影响。
  • 跨模型/任务泛化好：LLaDA-8B-Instruct、LLaDA-1.5、Dream-7B 上均有正收益；覆盖数学推理、代码生成、指令遵循等多类任务。
  • 实现简单、计算开销极小：仅需在每 block 首步额外检查分隔 token 置信度，几乎不引入额外延迟。
  • 小生成预算场景（如选择题）收益有限：semi-AR 解码本身在这种场景下优势不大，AdaBlock 的改进空间也受限。
  • 受限于去噪器质量：当去噪器预测分布不可靠时，自适应 block 大小无法恢复质量。
  • Dream 系列改进幅度小于 LLaDA：对从 AR 适配而来的 dLLM，局部随机性弱，VB 方差大，语义步骤信号较弱。
  • 分隔符和阈值需手动设定：当前使用固定的 D 和 τ_D，未来需要自动化的分隔 token 选择和阈值调整机制。...
