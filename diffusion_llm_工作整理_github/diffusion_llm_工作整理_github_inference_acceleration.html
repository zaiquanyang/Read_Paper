方法与框架

现有 dLLM 解码策略几乎都采用全局置信度阈值（global confidence threshold）来决定每一步解码哪些 token，主要包括：

  • Top-k 策略（LLaDA, Lumina-DiMOO）：每步选择置信度最高的固定数量 token 解码
  • 固定阈值策略（Fast-dLLM）：预定义统一的置信度阈值
  • 双阈值锚点策略（LocalLeap）：先用高阈值确定锚点 token，再用低阈值解码锚点周围的 token

上述策略存在两个关键缺陷：

(i) 对空间信息的利用不足（Limited usage of spatial information）。 全局阈值策略完全忽略 token 之间的空间位置关系。虽然 LocalLeap 利用高置信度 token 作为锚点来带动周围 token 的解码，但它并未充分利用已被解码 token 的局部密度信息为每个 masked token 单独调整阈值。

(ii) 缺乏时序建模（Lack of temporal modeling）。 现有方法几乎不考虑 token 在历史去噪步骤中被预测的 ID 是否保持一致，遗漏了重要的时序稳定性信号——很多 token 在尚未被正式解码之前，其预测 ID 已经连续多步保持不变。

作者通过实证分析发现 dLLM 解码过程存在两个强稳定性特征：

空间稳定性（Spatial Stability）： 当前步骤被解码的 token 通常出现在已解码 token 的邻域附近。在 HumanEval 和 GSM8K 上，超过 90% 的被解码 token 在半径为 2 的邻域内至少有一个已被解码的邻居。被已解码 token 包围的位置本质上是更容易和更安全的解码候选。

时序稳定性（Temporal Stability）： 大量 token 在正式解码之前，其 Top-1 预测 ID 已经连续多步保持不变。接近 95% 的被解码 token 在解码前至少 1 步内 ID 已稳定；即使要求更多步仍有相当比例的 token 提前稳定。关键观察：token ID 首次稳定时的置信度往往低于其被正式解码时的置信度，说明现有高全局阈值策略过度保守，未能充分利用时序稳定性带来的提前解码机会。

受此启发，STDec 提出将全局阈值替换为 token 自适应阈值（token-adaptive thresholds），利用空间和时间两个维度的稳定性信号，在不牺牲生成质量的前提下大幅提升吞吐量。STDec 是训练无关（training-free）的纯解码策略，且可与已有的缓存加速方法（如 dKV-Cache, Prefix-DLM）叠加使用。

STDec 的核心思想是将传统的全局阈值 tau_t 替换为 token 自适应阈值 tau_t^st = {tau_t^st(i)}_{i=1}^L，每个 masked token 的阈值由其局部空间上下文和跨步时序一致性共同决定。STDec 包含两个核心模块：

  • 空间感知解码（Spatial-aware Decoding）：根据周围已解码 token 的密度动态调整阈值
  • 时序感知解码（Temporal-aware Decoding）：根据历史 ID 一致性对阈值进行松弛

最终 token 自适应阈值为两者乘积：tau_t^st(i) = tau_t^s(i) * r_t(i)

方法与框架

本文首次系统性地挑战 semi-AR 解码中的固定 block 大小设置，识别出两个根本性问题：

问题一：Late Decoding Overhead（延迟解码开销）

  • 当固定 block 较小时，当前 block 外存在高置信度 token 本可立即解码，但受限于 block 边界必须等待下一轮
  • 被延迟的高置信度 token 需要额外的去噪计算，造成不必要的算力开销
  • 一个完整语义单元（如一个简单句子）可能被分割到多个 block 中

问题二：Premature Decoding Error（过早解码错误）

  • Block 级自回归约束要求采样器在进入下一 block 前必须解码当前 block 内所有 MASK 位置
  • 这迫使采样器在当前 block 内提交低置信度 token，而非推迟它们以等待更高置信度的位置
  • 过早提交的错误 token 通过 block 级自回归依赖传播到后续步骤，导致系统性误差
  • 在推理任务（如 GSM8K 数学推理）中尤为严重

VB 区域的置信度波动和宽度差异表明，固定 block 大小无法适应不同样本的解码需求。小 block 导致延迟解码，大 block 迫使过早提交低置信度 token。需要一种能够在运行时感知语义边界、动态调整 block 大小的调度策略。

AdaBlock-dLLM 是一个训练无关（training-free）、即插即用（plug-and-play）的自适应 block 大小调度器，在进入每个 block 的第一个 token 采样之前，动态确定当前 block 大小，使得 block 边界与语义步骤（semantic steps）对齐。

核心思想：利用语义分隔 token（如换行符 \n、句号、逗号）的置信度信号来判断语义步骤边界——当模型对某个分隔 token 有高置信度预测时，说明它"确信"此处应该是语义单元的终点。

方法与框架

dLLM 面临严重的推理效率瓶颈：

  • 计算复杂度高：自回归 LLM 解码复杂度为 O(L)，而 dLLM 每个推理步骤都需要对整个序列（包括 prompt、已生成 token、掩码 token）重新计算 QKV 状态，复杂度高达 O(L²)。
  • 现有 KV Cache 方案内存开销大：近期工作（dLLM-Cache、dKV-Cache、Fast-dLLM）将 AR LLM 的 KV Cache 机制适配到 dLLM，利用"相邻解码步骤的 KV 状态几乎相同"的观察，在多个步骤中复用同一份缓存 KV 状态。但这些方法都存储所有层的完整 KV 表示，导致显著的内存开销（比 vanilla dLLM 高 10%-30%），严重限制了长上下文场景的实用部署。
  • 缺少对 dLLM 内部注意力稀疏性的利用：现有方法仅引入 KV Cache 机制，未对其内部属性进行分析或进一步稀疏化。

作者对 dLLM 的注意力模式进行了系统分析（Figure 2），发现两个关键特征：

  • 跨层稀疏性（Sparsity Across Layers）：dLLM 各层注意力呈现显著稀疏性，表现为局部注意力（邻近 token 关注强）和垂直注意力（所有 query 集中在少数 pivotal tokens 上）两种稳定模式。与自回归模型不同，dLLM 没有对初始 token 的异常关注。
  • 跨步一致性（Consistency Across Steps）：虽然 QKV 状态每步重新计算，但获得显著关注的具体 token 在解码步骤间保持显著稳定——低重要性 token 在早期步骤被识别后，整个解码过程中持续保持低相关性。

这两个观察直接催生了核心策略：在早期步骤选择性淘汰不重要的 KV cache 条目，仅保留关键子集。

Sparse-dLLM 是首个训练无关（training-free）的 dLLM 动态 Cache 淘汰框架，核心包含两大策略：

  • 动态双向 Cache 淘汰（Dynamic Bidirectional Cache Eviction）：利用 token 重要性在步骤间的一致性，基于注意力引导的稀疏模式，动态淘汰前缀（prefix）和后缀（suffix）位置的低重要性 KV 条目。
  • 延迟 Cache 更新（Delayed Cache Updates）：缓存更新故意延迟一个步骤以提高稳定性。当进入新的解码 block 时，缓存完全清空并刷新。

  • 计算复杂度高：自回归 LLM 解码复杂度为 O(L)，而 dLLM 每个推理步骤都需要对整个序列（包括 prompt、已生成 token、掩码 token）重新计算 QKV 状态，复杂度高达 O(L²)。

  • 极优的效率-内存-精度权衡：吞吐最高提升 10×（长上下文），内存几乎不增加，精度几乎不损失甚至略有提升。

DepCap: Adaptive Block-Wise Parallel Decoding for Efficient Diffusion LM Inference

作者：Xiang Xia, Wuyang Zhang, Jiazheng Liu, Cheng Yan, Yanyong Zhang

机构：University of Science and Technology of China; Institute of Artificial Intelligence, Hefei Comprehensive National Science Center

一句话总结

DepCap 是一个 training-free 的 block-wise DLM 推理加速框架：它用上一个 decoded block 对未来位置预测分布的 KL 变化来动态决定下一个 block 的边界，并用 conflict score 过滤当前 block 内可安全并行提交的 token，从而在 LLaDA/Dream 等 DLM 和 GSM8K、Math-500、MBPP、HumanEval 等任务上获得更好的 speed-quality trade-off，最高报告 5.63x speedup，且可与现有 KV-cache 技术叠加。

背景与动机

Diffusion Language Models (DLMs) 的潜力在于可以并行更新多个 token，并对整段序列进行 global refinement。为了把这种并行潜力转化为实际推理速度，近年的 DLM inference 通常采用 block-wise decoding：把待生成序列切成若干 block，按 block 顺序解码，每个 block 内再做扩散式并行更新。

但 block-wise DLM inference 有两个关键决策：

  • 下一个 block 应该扩多长，也就是 block boundary 如何决定。
  • 当前 block 内哪些 masked positions 可以安全地并行解码。

已有方法在这两点上都偏保守或不够匹配 DLM 的动态特征：

  • Fast-dLLM 等方法多用固定 block size，忽略不同样本、不同生成阶段的依赖范围变化。
  • AdaBlock、Swordsman、GeoBlock 等动态 block 方法主要依赖当前 step 的语义符号、entropy 或 attention 几何信号，没有充分利用多步 denoising 中“上一个 decoded block 对未来位置的影响”。
  • confidence-based parallel decoding 只看单点 confidence，高 confidence 并不保证多个 token 可以同时提交，因为它们之间可能存在相互依赖或冲突。

DepCap 的核心观点是：block-wise DLM 的两个决策需要不同、更合适的信号。block boundary 应该用跨 step 的 last-block influence；block 内并行提交应该用 token-level conflict signal。

方法与框架

DepCap 是一个 training-free、plug-and-play 的 DLM 推理框架，由两个模块组成：

  • DepGA-Block: Dependency-Guided Adaptive Block Partitioning，用上一个 decoded block 对未来位置预测分布的影响，动态决定下一个 block 的边界。
  • CAP-Decoding: Conflict-Aware Parallel Decoding，在当前 block 内筛选 conflict-free token subset，避免把互相依赖或冲突的 token 同时解码。

图中左侧是传统 block-wise DLM：固定 block size，并用 confidence-only parallel decoding。右侧是 DepCap：先用 last-block influence 和 predictive uncertainty 决定 block boundary，再用 conflict-aware 策略过滤当前 block 内可并行提交的 token。

背景与动机

Uniform Diffusion Language Models (UDLM) 用均匀随机采样的 token 替代 [MASK] 符号，训练模型从任意噪声 token 中恢复干净 token。这天然支持 token-to-token 去噪（所有位置在每步都可重新评估），提供自纠错能力。

但 UDLM 从完全随机序列开始解码，使得去噪困难、生成不稳定。

方法与框架

当前 mask-based dLLMs（MDLM 范式）的解码是二值的、单向的 mask-to-token 过程：

  • 位置要么是 [MASK]，要么是已提交的 token
  • 一旦 masked 位置被解码为 token，该 token 就被固定，作为后续解码步骤的上下文
  • 无法修正：早期预测错误会作为不可更改的上下文传播到后续步骤，引发级联误差累积
  • 在激进并行解码下，误差不可避免，最终导致语义崩溃

与 speculative decoding 不同，dLLMs 缺乏从错误预测中恢复的机制，这从根本上限制了高并行度下的性能。

本文的动机是：保留 MDLM 稳定的全 mask 初始化 + 获得 UDLM 的自纠错能力。

  • 用全 masked 序列作为 UDLM 解码的初始化（保持稳定性）
  • 在后续步骤中，对所有已解码的 token 进行重新预测（获得自纠错能力）

关键洞察：传统 UDLM 训练使用均匀随机 token 构造噪声序列，但推理时遇到的噪声来自模型自身的预测分布，存在严重的 train-inference mismatch。

DMax 包含两个核心组件：

  • On-Policy Uniform Training (OPUT)：训练策略，将预训练 MDLM 扩展为具有自纠错能力的 UDLM
  • Soft Parallel Decoding (SPD)：推理策略，在 embedding 空间进行迭代自修正

背景与动机

这篇论文关注 Diffusion Language Models (DLMs) 的推理瓶颈。DLM 与 autoregressive LM 的关键差异是: DLM 通常用 iterative denoising / iterative unmasking，在每个 decoding step 中用双向上下文更新序列状态，因此生成顺序不是固定的 left-to-right。这个性质带来了并行生成、任意顺序生成、多模态和 reasoning 方面的潜力，但也直接破坏了标准 AR 模型中 KV cache 的使用条件。

在 AR 模型里，第 t 步生成只依赖过去 token，历史 token 的 K/V 可以稳定复用；但 DLM 的任意位置 token 都可能在后续 step 被更新，全局 bidirectional attention 会让之前位置的 hidden states 随着上下文变化继续漂移。因此如果每一步都完整重算长度为 N 的序列，复杂度会接近 O(T x N^2)，推理延迟很高。

已有 DLM cache 方案试图只更新部分 token，但存在两个主要问题:

  • update identification 开销大。比如 dLLM-Cache 用 Value states 的漂移来判断哪些 token 需要更新，但需要对整段序列做高维 Value projection 和 cosine similarity，序列变长后这个识别本身会成为瓶颈。
  • update budget 分配僵硬。已有方法常用固定更新比例，例如每一层都更新 25% token。但论文发现不同 layer 的 hidden state drift 频率差异很大: 早层较稳定，中层漂移更强，后层又趋于稳定。统一预算会在稳定层浪费计算，降低预算又会伤害中间不稳定层的质量。

SPA-Cache 的目标就是把这两个问题一起处理: 用低维 singular proxy 降低 update identification 成本，用 layer-wise adaptive budget allocation 把更新预算集中到更需要更新的层。

  • TTFT 基本不变但 decoding TPS 大幅提升，适合长生成阶段。

一句话总结

SparseD 是一篇很干净的 DLM sparse attention 论文：它不做 KV cache，而是基于 head-specific、跨 step 稳定、early-step 敏感 这三条观察，提出了 先 full、后 sparse、一次建图、多步复用 的 attention 稀疏化方案。它最大的价值在于证明了 DLM 的 attention 确实可以被结构化稀疏化，而且比 AR 的固定稀疏模板更需要“按 head 定制 + 按 step 分阶段使用”；同时它也恰好反衬出你的研究空间：如果想更贴近 FlashAttention 原生路径，就需要进一步摆脱对 attention score 本身的依赖。

背景与动机

这篇工作关注的是 DLM inference 中 attention 本身的二次复杂度，而不是 KV cache 的复用问题。

作者的基本判断是：

  • DLM 虽然是并行去噪，但每一步都要对整段上下文做双向 attention。
  • 随着上下文长度增长，attention 的代价随序列长度二次增长，成为长上下文推理的核心瓶颈。
  • AR-LLM 中已经有很多 sparse attention 方法，但这些方法不能直接照搬到 DLM。

作者认为 AR sparse attention 不适合 DLM，主要因为 DLM 有三个特殊现象：

  • Head-specific attention patterns
  • 不同 attention head 的稀疏结构差异很大。
  • 有些 head 像 sliding window，有些更像 column / sink / 混合结构。
  • 所以 AR 里那种固定模板式稀疏模式很难覆盖 DLM。
  • Attention similarity across denoising steps
  • 同一个 head 在不同 denoising step 的 attention pattern 很相似。
  • 这说明没必要每一步都重新算 sparse pattern。
  • Early denoising steps are critical
  • 在 DLM 里，早期 denoising step 对最终生成质量影响特别大。
  • 如果过早把 full attention 替换成 sparse attention，会明显掉质量。

这三个观察直接决定了 SparseD 的设计：

  • 稀疏模式要 按 head 定制。
  • 稀疏模式要 一次计算，多步复用。

  • 在第 T * skip% 步上，计算每个 head 的 sparse attention pattern。
  • 后续所有 denoising steps 复用这个 sparse pattern。

对应论文里的三块组件是：

  • Skipping Sparse
  • Sparse Reusing
  • Isolated Selection

从这篇论文的结果看，原因可能有两点：

  • SparseD 仍然在每个 step 计算当前 attention，只是减少连接数，没有直接跳过某些状态更新。
  • cache-based 方法在 DLM 里引入了“状态陈旧”问题，长上下文时误差会更明显累计。

所以作者把 SparseD 定位成：

相对 lossless，但速度增益没有 cache-based 路线那么激进。

  • early denoising steps 对 DLM 很敏感
  • aggressive sparsification 不应该太早介入

前若干 denoising steps 不做激进采样，等模型进入较稳定阶段后再启用。

方法与框架

现有工作（dLLM-Cache、dKV-Cache、FreeCache、Fast-dLLM）利用相邻解码步 KV 状态几乎相同的观察，将 ARM 的 KV cache 机制适配到 dLLMs：

  • dKV-Cache：实现一步延迟缓存（decoded tokens 在下一步才被缓存）+ 刷新机制
  • FreeCache：仅缓存 prompt tokens 的 KV 状态（基于 mask tokens 对早期 unmasked tokens 贡献迅速衰减的观察）
  • Fast-dLLM：缓存当前解码 block 之外的所有 KV 状态

核心不足：这些方法仅仅引入了 KV cache，但没有进一步分析 cache 内部特性或对其进行稀疏化。它们存储完整的 KV 表示，导致巨大的内存开销，限制了长上下文场景的实际部署。

Sparse-dLLM 是第一个训练无关 (training-free) 的框架，将动态 cache 驱逐与稀疏注意力集成到 dLLMs 中。核心包含两个策略：

  • 动态双向 cache 驱逐：利用 token 显著性的时间一致性，用注意力感知的稀疏模式动态驱逐前缀和后缀 token 的低重要性 KV 条目
  • 延迟 cache 更新：cache 更新故意延迟一步以提高稳定性；切换到新的解码 block 时完全刷新 cache

与 ARM 只能稀疏化前缀 token 不同，Sparse-dLLM 同时针对前缀（当前 block 之前的 token）和后缀（当前 block 之后的 token）进行驱逐。

设 $b$ 为 block 长度，$p$ 为 prompt 长度，$o \in [p, L)$ 为当前 block 首 token 的位置偏移。当前 block 之外的候选 KV 状态：

$$\mathbf{K}_f = \text{Concat}[\mathbf{K}_{:o}, \mathbf{K}_{o+b:}], \quad \mathbf{V}_f = \text{Concat}[\mathbf{V}_{:o}, \mathbf{V}_{o+b:}]$$

通过当前 block 的 query 状态 $\mathbf{Q}_b$ 计算注意力分数：

$$\mathbf{A} = \frac{\mathbf{Q}_b \mathbf{K}_f^T}{\sqrt{d_k}}$$

借鉴 SnapKV，引入 max pooling 聚合局部信息（防止驱逐后数据不完整导致性能退化）。设 $r$ 为保留比，$s$ 为 max pooling 核大小，通过 top-$k$ 选择 pivotal token 索引（$k = (L-b) \times r$）：

$$\text{Indices} = \text{top-}k(\text{MaxPool}(\mathbf{A}))$$

最终 cache 只保留选中的 KV：

$$\mathbf{K}_c = \mathbf{K}_f[\text{Indices}], \quad \mathbf{V}_c = \mathbf{V}_f[\text{Indices}]$$

算法伪代码（Algorithm 1）：

  • 提取当前 block 之外的 KV 状态（前缀+后缀拼接）
  • 计算 block query 的平均值 $\bar{q} = \text{Mean}(\mathbf{Q}_b)$
  • 计算注意力分数 $\mathbf{A} = \text{MatMul}(\bar{q}, \mathbf{K}_f^T)$
  • MaxPool1D 聚合 → TopKIndices → 选出 pivotal token 的 KV
  • 更新 cache
