背景与动机

这篇论文关注 Diffusion Language Models (DLMs) 的推理瓶颈。DLM 与 autoregressive LM 的关键差异是: DLM 通常用 iterative denoising / iterative unmasking，在每个 decoding step 中用双向上下文更新序列状态，因此生成顺序不是固定的 left-to-right。这个性质带来了并行生成、任意顺序生成、多模态和 reasoning 方面的潜力，但也直接破坏了标准 AR 模型中 KV cache 的使用条件。

在 AR 模型里，第 t 步生成只依赖过去 token，历史 token 的 K/V 可以稳定复用；但 DLM 的任意位置 token 都可能在后续 step 被更新，全局 bidirectional attention 会让之前位置的 hidden states 随着上下文变化继续漂移。因此如果每一步都完整重算长度为 N 的序列，复杂度会接近 O(T x N^2)，推理延迟很高。

已有 DLM cache 方案试图只更新部分 token，但存在两个主要问题:

  • update identification 开销大。比如 dLLM-Cache 用 Value states 的漂移来判断哪些 token 需要更新，但需要对整段序列做高维 Value projection 和 cosine similarity，序列变长后这个识别本身会成为瓶颈。
  • update budget 分配僵硬。已有方法常用固定更新比例，例如每一层都更新 25% token。但论文发现不同 layer 的 hidden state drift 频率差异很大: 早层较稳定，中层漂移更强，后层又趋于稳定。统一预算会在稳定层浪费计算，降低预算又会伤害中间不稳定层的质量。

SPA-Cache 的目标就是把这两个问题一起处理: 用低维 singular proxy 降低 update identification 成本，用 layer-wise adaptive budget allocation 把更新预算集中到更需要更新的层。

实验与结论

论文主表很大，下面保留每个任务中 SPA-Cache 与 baseline 的关键数值。总体结论是: SPA-Cache 在大多数任务上保持接近原始 accuracy，同时显著提高 TPS；LLaDA-8B 上最高 8.0x，Dream-7B 上 MMLU-pro 达 6.2x。

| Task | Model | Baseline TPS / Acc. | SPA-Cache TPS / Acc. | Speedup |

|---|---|---:|---:|---:|

| GSM8K | LLaDA-8B | 29.67 / 78.62 | 190.73 / 78.24 | 6.4x |

| GSM8K | Dream-7B | 17.86 / 75.21 | 45.97 / 77.56 | 2.6x |

| GPQA | LLaDA-8B | 20.55 / 29.91 | 39.19 / 30.58 | 1.9x |

| GPQA | Dream-7B | 12.89 / 34.15 | 45.97 / 34.60 | 3.6x |

| MATH500 | LLaDA-8B | 33.35 / 33.18 | 172.19 / 33.44 | 5.2x |

| MATH500 | Dream-7B | 23.08 / 36.16 | 104.23 / 34.84 | 4.5x |

| BBH | LLaDA-8B | 24.85 / 53.49 | 108.31 / 53.72 | 4.4x |

| BBH | Dream-7B | 49.30 / 58.42 | 153.61 / 58.52 | 3.1x |

| MMLU-pro | LLaDA-8B | 20.68 / 37.08 | 124.06 / 36.30 | 6.0x |

| MMLU-pro | Dream-7B | 10.06 / 45.01 | 62.13 / 45.16 | 6.2x |

| MBPP | LLaDA-8B | 5.75 / 39.20 | 46.12 / 39.00 | 8.0x |

| HumanEval | LLaDA-8B | 37.48 / 42.07 | 132.91 / 42.07 | 3.5x |

| HumanEval | Dream-7B | 28.00 / 58.54 | 42.49 / 58.54 | 1.5x |

几个细节值得注意:

  • TTFT 基本不变，因为 SPA-Cache 优化的是 decoding phase，不主要优化 prefill。
  • 在 LLaDA-8B 的 MBPP 上，baseline 只有 5.75 TPS，SPA-Cache 到 46.12 TPS，速度收益最大。
  • Dream-7B 上也有明显收益，但不同任务波动更大。HumanEval 只有 1.5x，说明模型结构、任务长度、GQA Value 维度等都会影响 cache 方案收益。
  • 个别任务 accuracy 有小幅波动，例如 Dream-7B 的 MATH500 从 36.16 到 34.84，但大多数结果接近 baseline。

价值、局限与启发

  • Training-free: 不需要重新训练 DLM，只在推理路径中加入缓存和更新选择。
  • 理论动机比启发式 window update 更强: 通过 Value state stability、FFN Lipschitz bound、SVD similarity preservation 来支撑 update identifier。
  • 同时优化两个瓶颈: singular proxy 降低 token-wise identification 开销，adaptive budget 减少稳定层冗余计算。
  • 与 parallel decoding 正交，可以叠加到 Fast-dLLM 类方法上，最高报告约 28x speedup。
  • TTFT 基本不变但 decoding TPS 大幅提升，适合长生成阶段。
  • 依赖 hidden state transitions 的 temporal smoothness。高温采样如 tau in [1.0, 1.5] 会增加随机性，可能降低 cache 复用准确性。
  • 主要优化 decoding phase，对 prefill / TTFT 帮助有限。
  • 分布式或 tensor-parallel 部署更复杂。partial KV/output cache、scatter/gather、跨设备同步都需要额外工程设计。
  • 当前评估主要基于开放 DLM 的上下文长度限制，尚未验证超长上下文例如 >32k 的效果。
  • adaptive budget 的形状和超参数来自经验拟合。虽然论文称跨 benchmark 固定有效，但换模型、换架构时仍可能需要重新 profile layer-wise drift。
  • 可以把 SPA-Cache 视为 DLM 推理系统中的 layer-local sparse execution primitive，而不是单独的缓存 trick。后续如果实现 diffusion_llm serving，可以先抽象出 select_update_indices -> sparse block forward -> scatter cache 这条接口。
  • 对任何 DLM cache 方法，都应单独 profile update identification overhead。只看 skipped FLOPs 很容易高估收益，尤其当 identifier 本身需要高维 projection/similarity 时。...
