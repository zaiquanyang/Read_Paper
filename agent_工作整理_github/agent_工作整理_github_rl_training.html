Tree Search for LLM Agent Reinforcement Learning

agent arXiv abs PDF Code arXiv 2509.21240
核心思想：Tree-GRPO 的核心贡献是把 agent RL 的 rollout 结构从链改成树，并把树结构同时用于 节省 rollout 预算 和 从 outcome reward 中恢复 step-level process supervision。它特别适合低预算、长程、多轮的 agent 训练场景，本质上是在 agent RL 中把“采样效率”和“过程信用分配”一起做了结构化改造。

问题与动机

作者讨论的是典型 ReAct 风格 agent。一个完整 episode 由多个 Thought-Action-Observation step 构成：

\[\mathcal{H}=\{(\tau_0,\alpha_0,o_0),(\tau_1,\alpha_1,o_1),\ldots,(\tau_{T-1},\alpha_{T-1},o_{T-1})\}.\]

其中：

  • $\tau_t$ 是第 $t$ 步 thought
  • $\alpha_t$ 是第 $t$ 步 action，通常是 tool call
  • $o_t$ 是环境返回的 observation

agent RL 的目标仍然是最大化完整轨迹的期望回报：

\[J(\theta)=\mathbb{E}_{\mathcal{H}\sim p_\theta}\!\left[R(\mathcal{H})\right].\]

问题在于，多轮 agent 任务相比单轮数学/代码 RL 有两个更突出的困难。

方法核心

Tree-GRPO 的核心是：把 rollout 从“多条独立链”变成“若干棵共享前缀的树”。

论文给出的示意图非常直观：

这张图要表达的重点是：

  • chain-based sampling：每条轨迹都从头独立走完整条链
  • tree-based sampling：共享 prefix，只在部分节点继续展开新分支

作者强调，agent 场景下树节点的最佳粒度不是 token/sentence，而是 完整 agent step。也就是每个节点对应一个完整的 $(\tau,\alpha,o)$。这一点很重要，因为：

  • token 级分叉没有明确决策语义
  • sentence 级分叉也会打断 action-observation 的结构完整性
  • agent step 级才真正对应“一个可解释的决策单元”

  • 当前主要围绕 search-based agent，工具类型较单一，泛化到 code execution / browser / GUI / embodied tool-use 还需验证。
  • tree expansion 仍然需要串行迭代，虽然比纯 MCTS 更适合并行推理，但不等于没有系统工程成本。
  • 理论分析使用了较强的 binary preference 假设，更像解释性框架，不是严格覆盖真实复杂 agent 环境的完整理论。

如果从你关心的 agent 方向来看，这篇 paper 有几个很实用的启发：

  • 可以把“共享前缀 rollout”看成 agent RL 的一类基础采样优化，不只是 Tree-GRPO 独有技巧。

对任何多轮、前缀重复率高的 agent 任务，都值得考虑。

  • 过程监督不一定非要显式 PRM。

只要轨迹结构本身有层级，很多时候可以从 outcome reward + branching structure 里反推出局部 preference。

  • credit granularity 要和 agent 原生 step 对齐。

这点对 browser agent、tool agent、code agent 都很重要。过细到 token，反而可能破坏 action semantics。

Agent Learning via Early Experience

agent arXiv abs PDF arXiv 2510.08558
核心思想：这篇论文最值得记住的点是：在 agent 训练里，即使没有 reward，模型自己的动作所引发的 future states 也已经构成了高价值 supervision。 IWM 利用它学习环境动态，SR 利用它学习决策理由，两者共同把 imitation learning 推向更接近真实 experience-driven agent 的阶段。

问题与动机

语言 agent 的一个长期目标，是像 AlphaGo 一样通过自身经验不断变强，而不是永远停留在“模仿人类演示”的阶段。但现实里的很多 agent 环境并不满足标准 RL 的前提：

  • 一类环境根本没有可验证 reward，比如真实网页、复杂网站工作流。
  • 另一类环境即使有 reward，也往往需要很长的交互链条才能得到，rollout 成本太高，比如多轮工具调用。

因此，当前很多 agent 训练依赖 expert demonstrations 和 imitation learning / SFT。问题在于，expert data 的覆盖面很窄，只展示“正确轨迹”，几乎不展示“做错之后环境会怎样”。这会带来两个直接后果：

  • 模型容易受到 distribution shift 影响，一旦部署时偏离 expert 轨迹，就可能进入训练中没见过的状态。
  • 模型不知道错误动作的后果，因此恢复能力、纠错能力和泛化能力都有限。

这篇论文提出的核心观点是：在“完全依赖 expert 数据”和“完全依赖 reward-driven RL”之间，其实存在一个中间地带，即 early experience。它指的是：

> 由 agent 自己提出动作、与环境交互后得到的未来状态，这些未来状态本身就能成为 supervision，即使没有显式 reward。

这个 framing 很重要。论文不是单纯提出某个 trick，而是在 agent 训练范式上提出一个桥接层：

  • 从 human data era 走向 experience era；
  • 从 imitation learning 逐步过渡到 reinforcement learning；
  • 在 reward 不可用或很贵时，先用“未来状态”替代 reward 提供训练信号。

上图给出的直觉很清楚：传统 imitation learning 只看 expert action；early experience 则额外观察 agent 自己尝试其他动作后环境发生了什么变化，因此学习信号更丰富。

Complementary Reinforcement Learning

llm arXiv abs PDF arXiv 2603.17621
核心思想：

问题与动机

这一部分当前还没有补到更细的整理。

方法核心

现有利用经验的方法存在一个根本问题：将经验视为静态资源。

  • 离线经验：预先从历史轨迹构建经验库，训练中保持不变。初始有优势，但随着 actor 能力增长，经验逐渐过时（stale），收益衰减。
  • 静态在线经验：训练过程中由固定提取器动态维护经验库，但提取器不更新。无法适应 actor 的演化，导致分布错位（distributional misalignment），经验与 actor 当前能力脱节。
  • 自反思方法：依赖模型自身生成反思，但弱模型容易产生幻觉，不可靠。
  • 复杂启发式方法：多阶段检索、专门数据结构等，增加了工程复杂度。

关键洞察：经验提取和 agent 学习应该协同演化（co-evolve），而非各自独立处理。

  • Actor-Extractor Co-Evolution：actor 和 extractor 必须在训练中互相适应，持续塑造彼此
  • Experience Consolidation：经验库必须自动构建和维护，蒸馏可迁移经验，解决冲突和冗余
  • Training-Distillation Coordination：actor 训练和经验蒸馏必须高效协调，不能引入阻塞延迟

Complementary RL 包含两个互补模型：

  • Actor $\pi_{\theta}$：与环境交互，通过 outcome-based reward 优化，受检索到的经验指导
  • Experience Extractor $\pi_{\phi}$：从轨迹中蒸馏经验，维护持续演化的经验库 $\mathcal{M}$

两者都通过 RL 优化：actor 用结果奖励，extractor 用其蒸馏经验对 actor 成功的效用作为奖励。

为了避免 actor 训练被经验蒸馏阻塞，设计了完全异步的双轨架构：

主训练循环（Primary Training Loop）：

  • Actor $\pi_{\theta}$ 持续与环境交互收集 rollout
  • 通过 outcome-based reward 优化策略

后台轨道（Background Track）：

  • Experience extractor $\pi_{\phi}$ 处理完成的轨迹
  • 蒸馏经验并向 $\mathcal{M}$ 发出结构化操作

两者通过集中式 ExperienceManager $\mathcal{H}$ 协调，承担两个角色：

1. Experience Consolidation（经验巩固）：

  • $\mathcal{H}$ 维护内部队列 $\mathcal{Q}$ 接收蒸馏请求
  • 后台进程持续出队并转发给 $\pi_{\phi}$ 蒸馏
  • $\pi_{\phi}$ 发出三种结构化操作：Add（新增）、Update（更新）、Return（无操作）
  • 在 writer lock 下应用操作，防止状态冲突
  • Periodic Merge：定期触发合并操作，处理 group-based RL 中同一任务并行产生的冗余经验

2. Experience Retrieval（经验检索）：

  • 查询批处理：$\mathcal{H}$ 将并发查询累积为 micro-batch
  • Embedding 缓存：group-based RL 中多个环境共享相同任务描述，缓存命中率高
  • 并行搜索：$W$ 个并行搜索 worker 在 reader lock 下执行语义相似度搜索...

价值、局限与启发

现有利用经验的方法存在一个根本问题：将经验视为静态资源。

  • 离线经验：预先从历史轨迹构建经验库，训练中保持不变。初始有优势，但随着 actor 能力增长，经验逐渐过时（stale），收益衰减。
  • 静态在线经验：训练过程中由固定提取器动态维护经验库，但提取器不更新。无法适应 actor 的演化，导致分布错位（distributional misalignment），经验与 actor 当前能力脱节。
  • 自反思方法：依赖模型自身生成反思，但弱模型容易产生幻觉，不可靠。
  • 复杂启发式方法：多阶段检索、专门数据结构等，增加了工程复杂度。

关键洞察：经验提取和 agent 学习应该协同演化（co-evolve），而非各自独立处理。

  • 协同演化范式：首次在 RL 训练中实现 actor 与经验提取器的联合优化，两者形成闭合的互相增强循环
  • 子组 advantage 估计：experience-guided/experience-free 分组 + 组内独立 advantage 计算，有效防止 over-reliance 和 advantage 偏差
  • 完全异步架构：actor 训练和经验蒸馏解耦，不引入阻塞延迟
  • 模块化设计：ExperienceManager 统一管理经验的增删改查，并发控制清晰
  • 实用性强：无 KL 正则化、无额外 SFT 阶段、无复杂启发式，训练配置精简
  • 任务扩展性好：3-task 到 6-task 混合，收益从 +6.6% 增长到 +8.1%
  • 丰富的经验分析：展示了蒸馏出的结构化经验，具有可解释性
  • Self-Distillation 集成失败：自蒸馏后期训练崩溃，原因未完全调查清楚
  • Actor-Critic 增加延迟：虽然提升早期表现，但引入非平凡延迟开销，不适合默认启用
  • 提取器 off-policy 问题严重：蒸馏的经验可能在很久之后才被检索，policy lag 大，需要专门的稳定性技巧
  • 评估环境有限：主要在 MiniHack、WebShop、ALFWorld 和 SWE-Bench 上评估，工业级场景验证不足
  • 辅助奖励探索失败：困惑度降低奖励的五种归一化策略均未奏效
  • Extractor 必须独立参数：共享参数导致梯度冲突，增加了显存开销...

问题与动机

当前 LLM Agent 主流范式 ReAct 存在根本性的探索瓶颈：Agent 在每一步只能执行一个动作、观察一个反馈，从狭窄的线性视角构建环境认知。这导致：

  • 探索多样性不足：多次采样的轨迹倾向于收敛到相同动作选择，无法覆盖环境的多样动态
  • 环境理解片面：单路径推理使得 Agent 对环境的认知不完整且有偏差，导致复杂任务中的次优决策

核心问题：能否让 Agent 同时与多个并行环境交互，共享跨环境经验，从而构建更全面的环境认知？

  • 探索多样性不足：多次采样的轨迹倾向于收敛到相同动作选择，无法覆盖环境的多样动态
  • 环境理解片面：单路径推理使得 Agent 对环境的认知不完整且有偏差，导致复杂任务中的次优决策

核心问题：能否让 Agent 同时与多个并行环境交互，共享跨环境经验，从而构建更全面的环境认知？

DPEPO 采用两阶段训练范式：

  • SFT 冷启动：用 DeepSeek-V3.2 标注的并行探索轨迹（~500 条 ALFWorld / ~1000 条 ScienceWorld）微调 Agent，使其具备基本的并行推理和动作生成能力
  • RL 层次化奖励优化：基于 GRPO 框架，引入轨迹级 + 步级的层次化奖励信号

方法核心

受人类技能习得过程的启发（从"看说明书操作"到"肌肉记忆自主执行"），本文提出一个新问题：能否将 skills 直接内化到模型参数中，使得推理时完全不需要任何 skill 检索？

图：(a) 传统 Skill 增强方法 vs (b) SKILL0 的 Skill 内化方法

SKILL0 是一个 In-Context Reinforcement Learning (ICRL) 框架，核心思想是：训练时提供 skills 作为 in-context 指导，但通过动态课程逐步撤除，最终在推理时实现完全 zero-shot 自主执行。

框架包含三个核心组件：

  • (a) Relevance-Driven Skill Grouping（离线阶段）
  • (b) In-Context Reinforcement Learning（训练循环）
  • (c) Dynamic Curriculum Learning（自适应课程）

图：SKILL0 方法总览

课程设计分为两个层面：

(a) 离线阶段：Relevance-Driven Skill Grouping

  • 将验证集按技能需求划分为 $N$ 个子任务 $\{\mathcal{T}_k\}_{k=1}^N$
  • 每个 $\mathcal{S}_k$ 对应一个专用验证子任务 $\mathcal{T}_k$，用于评估其有用性

(b) 在线阶段：Helpfulness-Driven Dynamic Curriculum

将训练分为 $N_S$ 个阶段，每阶段 skill 预算 $M^{(s)}$ 线性衰减：

\[M^{(s)} = \lceil N \cdot (N_S - s) / (N_S - 1) \rceil\]

每 $d$ 步执行一次 Helpfulness 评估：

  • 在子任务 $\mathcal{T}_k$ 上分别评估"有 skill $\mathcal{S}_k$"和"无 skill"的准确率
  • 计算 helpfulness $\Delta_k = \text{Acc}_k^{\text{w/skill}} - \text{Acc}_k^{\text{w/o skill}}$
  • Filter：只保留 $\Delta_k > 0$ 的 skills
  • Rank：按 $\Delta_k$ 降序排列
  • Select：取 top-$M^{(s)}$ 个

当模型已将某个 skill 内化到参数中后，$\Delta_k$ 趋近于 0，该 skill 被自动过滤掉，形成自定步调课程。

Evolving-RL: End-to-End Optimization of Experience-Driven Self-Evolving Capability within Agents

agent arXiv abs PDF Code arXiv 2605.10663
核心思想：Evolving-RL 的核心贡献不是又做了一个带 skill 的 agent，而是把“经验提炼”和“经验利用”这两个本来割裂的阶段，真正放进同一个 RL 闭环里共同优化，并且用跨任务迁移效用来定义 skill 的价值。

问题与动机

这篇工作讨论的是一个很具体、也很关键的问题：

experience-driven self-evolving agent 到底该怎么训？

现在很多 self-evolving agent 都会做类似流程：

  • 先跑任务
  • 从轨迹里提炼经验
  • 把经验注入到后续任务中
  • 靠这些经验提升 test-time adaptation

但作者认为，现有工作大多停留在“系统设计层面”：

  • 经验如何表示
  • memory / bank 怎么管理
  • retrieval 怎么做

而真正更底层的问题是：

> base model 本身有没有足够强的能力去提炼出“可迁移经验”，以及在后续任务里“真正用好这些经验”？

作者指出一个核心缺陷：

  • 一些最近的 RL 方法确实开始训练“experience utilization”
  • 但几乎都没有把 experience extraction 和 experience utilization 当成一个统一闭环去共同优化

结果就是：

  • extractor 还依赖 heuristic filtering 或更强外部模型
  • solver 再去学怎么消费这些 skills

这种 decoupled 设计的问题在于：

  • skill 质量直接决定 downstream RL 的方差和有效性
  • skill 如果 noisy，solver 最稳定的策略往往不是“学会用 skill”，而是“学会忽略 skill”

所以这篇 paper 的目标非常明确：

把 experience extraction 和 utilization 放进同一个 shared policy 里，用一个 unified RL loop 让它们共同进化。

方法核心

这篇 paper 最想说明的是：

  • skill extraction 和 skill utilization 不是两个独立模块
  • skill 的质量必须由其“跨任务迁移价值”来定义
  • 如果只训练 solver，不训练 extractor，模型最后会倾向于忽略 skill
  • co-evolution 不只是 self-evolution 的改进，也是一种 experience-augmented RL

这一点很重要，因为它把 paper 放到了你关心的 agent / RL 视角里：

  • 它不是简单 memory engineering
  • 而是把“经验的生成质量”直接纳入 policy optimization

Evolving-RL 的框架很清楚，可以概括成一句话：

先在线生成 skill，再在多个相关下游任务上验证 skill 的迁移效用，然后把这个验证过程同时拿来训练 extractor 和 solver。

整个系统里有两个角色：

  • Extractor
  • Solver

但它们不是两个模型，而是：

共享同一组 policy 参数的两个角色视角

这一点跟很多“单独训练 skill generator / 单独训练 executor”的工作不同。

尤其适合参考的点有：

  • extractor / solver shared policy
  • downstream-transfer-oriented reward
  • skill-conditioned trajectories reused for solver optimization
  • co-evolution stability control

核心思想：ActGuide-RL 的核心贡献是把“动作轨迹引导”系统化为一种最小干预的 agentic RL 训练机制，在不依赖重 cold-start SFT 的前提下，显著提升了弱到中等基座在困难 agent 任务上的可学习性与最终性能。

问题与动机

这篇论文讨论的是 agentic RL 的一个核心难点：可达性屏障（reachability barrier）。

作者认为，在长程 agent 任务里，RL 信号只会出现在当前策略“能力可达区间”内；一旦任务奖励状态落在能力边界之外，策略采样不到成功轨迹，group-based advantage 就会塌成零梯度，训练卡死。

典型做法是 SFT 冷启动再 RL，但这会带来：

  • 强依赖大规模 warm-start 数据。
  • 训练流程复杂，难扩到新环境。
  • 可能牺牲 out-of-domain 泛化。

论文提出：利用已有的“动作数据”（action trajectories）做训练期引导，而不是再依赖大量高质量 CoT/SFT。由此得到方法 ActGuide-RL。

论文强调一个关键结论：即使不做 cold-start SFT，ActGuide-RL 也能接近 SFT+RL 的 in-domain 表现。

而在同样有 SFT cold-start 的情况下，继续加 ActGuide 仍有额外收益。

这意味着 action guidance 可以部分替代重 SFT 依赖，形成更轻量的 agentic RL 路线。

方法核心

ActGuide-RL 的核心是把 action data 当作“参考计划”（plan-style guidance）注入训练 rollout：

  • 先跑一批无引导 rollout。
  • 若整组都失败（零奖励），再触发 guidance fallback。
  • 动态选择“最小足够引导强度”。
  • 把 guided 和 unguided 轨迹一起做 mixed-policy 优化，把引导期学到的探索能力内化回无引导策略。

价值、局限与启发

  • 提出并实证验证了 reachability barrier 视角，解释了 agentic RL 卡死根因之一。
  • 用可扩展 action data 替代部分重 SFT 依赖，工程上更轻。
  • 动态最小干预 + 混合优化设计完整，且跨模型稳定收益。
  • 当前实验主要在 search-agent 场景，跨 GUI/CLI/embodied 泛化还需更多验证。
  • 对 action data 质量仍敏感，高噪声下会退化。
  • 理论单调假设在复杂现实任务中未必总成立。
  • 先判断训练失败是“采样预算不足”还是“可达性屏障导致的结构性失败”。
  • 如有现成动作轨迹数据，优先尝试训练期 fallback guidance，而非直接堆更重 SFT。
  • 关键不是 guidance 越强越好，而是“最小足够”并动态匹配任务难度。

LLMs Improving LLMs: Agentic Discovery for Test-Time Scaling

agent arXiv abs PDF Code arXiv 2605.08083
核心思想：这篇工作提出 AutoTTS：把 test-time scaling 策略设计从“人手写 branching / pruning / stopping 启发式”改写成“人构造可回放环境，coding agent 自动发现控制器”的问题。具体到 width-depth TTS，它预采样推理轨迹和 probe 信号，让 agent 在离线 replay 环境里低成本搜索控制器；最终用约 39.9 美元和 160 分钟发现的策略，在多数组合上优于手工 TTS baseline 的 accuracy-cost Pareto frontier。

问题与动机

论文把 adaptive TTS 建模成一个可控推理过程。对每个问题 q，controller 可以管理多个 reasoning branch：

  • BRANCH: 创建新分支，并生成第一个固定长度 interval。
  • CONTINUE(i): 让第 i 个活跃分支继续生成一个 interval。
  • PROBE(i): 读取当前分支在当前深度的中间答案信号 omega_{i,k}。
  • PRUNE(i): 放弃某个活跃分支。
  • ANSWER: 终止推理，并通过聚合规则输出最终答案。

状态定义为：

```text

s_t = (q, m_t, I_t, l_t, Z_t, Omega_t)

```

含义：

  • q: 当前问题。
  • m_t: 已创建分支数。
  • I_t: 当前仍活跃的分支集合。
  • l_t: 每个分支当前深度，单位是固定 token interval。
  • Z_t: 每个分支已经生成的 prefix 序列。
  • Omega_t: 已 reveal 的 probe feedback。

计算成本：

```text

Cost(s_t) = sum_i l_{t,i} + kappa_probe * |Omega_t|

```

如果 probe 成本相对生成可忽略，则 kappa_probe = 0。

目标是找到一个 code-defined policy：

```text

pi(. | s, beta)

```

其中 beta 是单一 trade-off 参数，用来控制整个策略的预算倾向。优化目标是准确率与推理成本之间的 trade-off：

```text

maximize E[ 1{answer correct} - gamma * cost ]

```

这意味着 AutoTTS 搜索的不是一个固定推理算法，而是一族由 beta 控制的策略曲线。

方法核心

TTS 的基本想法是在推理时给模型更多计算，例如采样多条 reasoning trajectory、延长推理链、做 self-consistency、早停、剪枝、probe 中间状态等。但论文强调，性能不只取决于总计算量，还取决于计算如何在不同分支和深度之间分配。

现有方法多是人工设计：

  • Self-Consistency 固定采样很多条轨迹，再 majority vote。
  • ASC / ESC 做启发式 early stopping。
  • Parallel-Probe 利用跨分支 probe 信息决定继续、剪枝或停止。
  • ST-BoN / DeepPrune 等方法也本质上是人手写控制策略。

这些方法都可以看作 width-depth 控制空间中的某条人造轨迹：width 是探索多少分支，depth 是每条分支走多深。

价值、局限与启发

这篇工作提出 AutoTTS：把 test-time scaling 策略设计从“人手写 branching / pruning / stopping 启发式”改写成“人构造可回放环境，coding agent 自动发现控制器”的问题。具体到 width-depth TTS，它预采样推理轨迹和 probe 信号，让 agent 在离线 replay 环境里低成本搜索控制器；最终用约 39.9 美元和 160 分钟发现的策略，在多数组合上优于手工 TTS baseline 的 accuracy-cost Pareto frontier。

  • 范式贡献清晰：不是提出又一个手工 TTS 策略，而是把策略设计改成环境驱动的 agentic discovery。
  • 离线 replay 让搜索可行：高频评估不再需要反复调用 base LLM。
  • beta parameterization 很实用：让策略天然成为一条 budget curve，并降低过拟合风险。
  • trace feedback 符合 agent 工作方式：coding agent 更擅长从具体执行轨迹中诊断程序，而不是只看标量分数。
  • 发现的 controller 有可解释机制：CMC 的 EMA stopping、width-depth coupling、alignment-aware allocation、conservative abandonment 都有明确行为意义。
  • 实验覆盖较好：跨 Qwen 模型规模、held-out benchmark、DeepSeek-R1-Distill-Llama-8B、GPQA-Diamond。

论文自己也指出两个主要限制：

  • 当前环境只覆盖 width-depth TTS control

Action set 主要是 branch / continue / probe / prune / answer。更复杂的 tree search、verifier-guided refinement、tool-use reasoning、multi-agent debate 等还没有被统一进来。

  • 依赖 frontier coding agent

实验中 explorer 是 Claude Code。是否开源 coding agent 也能稳定发现同等级 controller，是后续问题。

RetroAgent: From Solving to Evolving via Retrospective Dual Intrinsic Feedback

RetroAgent arXiv abs PDF Code arXiv 2603.08561
核心思想：标准 agent RL 只优化环境外部奖励，agent 容易收敛到次优策略且无法复用过往经验。RetroAgent 在 episode 结束后做 hindsight self-reflection，同时产出 intrinsic numerical feedback（奖励"虽未成功但有进步"的探索）和 intrinsic language feedback（提炼可复用 lesson），通过 SimUtil-UCB 检索机制反哺后续训练，让 agent 从"学会做题"进化为"持续成长"。

问题与动机

  • Exploitation 过度：标准 RL 只看 extrinsic reward，agent 探索不足，容易收敛到次优策略。
  • 经验浪费：失败轨迹中的有价值探索没有被显式提炼和复用，下次遇到相似任务无法直接借鉴。
  • 核心判断：agent 不仅要"做成一件事"，更要像人一样回顾过去、提炼经验、识别有潜力但尚未成功的探索，并在后续任务中持续进化。

方法：Retrospective Dual Intrinsic Feedback

每次 episode 结束后，reflection 模块回看整条轨迹，输出 reflection tuple $(\phi, c, l)$：

  • $\phi$（potential score）：估计 subtask completion 程度，用于构造 intrinsic numerical feedback——只有比历史最好水平更"有潜力"的轨迹才获额外奖励。
  • $c$（success prediction）：判断轨迹成功/失败，用于监督反思质量。
  • $l$（retrospective lesson）：从轨迹中提炼可复用经验，写入 memory buffer，形成 intrinsic language feedback。

Reflection 有两种实现：(1) In-context variant——用 pairwise induction，给当前轨迹配一个 outcome 相反的 reference trajectory 做对比反思；(2) RL-trained variant——反思能力与决策 policy 联合训练。

Memory 检索使用 SimUtil-UCB，同时平衡三个维度：semantic relevance（任务相似度）、reflection utility（历史有效性）、exploration coverage（UCB bonus 防止过拟合到少数经验）。

优点与局限

优点

  • 问题定义清晰：从"学会做题"到"持续进化"的视角提升
  • 双 intrinsic feedback 设计自然，数值信号与语言信号各司其职
  • SimUtil-UCB 显式处理 relevance/utility/exploration 三者平衡
  • 实验覆盖 4 类任务（embodied/web/planning/logic），泛化性强

局限

  • Memory 仍是 lesson-level text buffer，尚未覆盖更复杂的结构化表示
  • Intrinsic reward 依赖 reflection 产出的 potential score，自评质量影响训练
  • 主要在 7B/8B 模型上验证，更大模型或复杂真实 agent system 的扩展待确认

定位：agent RL + 经验回放的交叉点。与 Complementary RL（actor-extractor co-evolution）互补——RetroAgent 侧重 hindsight reflection 驱动的 dual intrinsic feedback，Complementary RL 侧重经验提取与策略的异步协同演化。与 Evolving-RL 的 self-evolving capability 也有对比价值。
