CUA-Gym: Scaling Verifiable Training Environments and Tasks for Computer-Use Agents

本地总结 arXiv RLVRprogrammatic rewardmock web apps
CUA-Gym 把 GUI/CUA 的 RLVR 数据构造成 verified tuple $(t,s_\text{init},s_\text{gold},r)$：任务、初始环境、目标状态和程序化 reward 必须一起生成、一起验证。

核心机制

  • Generator 生成环境状态和 golden state，Discriminator 在信息隔离下写 reward.py，Orchestrator 负责验证与过滤。
  • 使用五个 agreement conditions，例如 $r(V_\text{gold})=1$、$r(V_\text{init})=0$、reward 不含 forbidden patterns。
  • VLM judge 不直接作为 RL reward，而放在离线 filter 阶段检查程序 reward 与视觉结果是否一致。
  • CUA-Gym-Hub 合成可注入状态的 mock web apps，让同一环境支持大量任务。

关键结论

最终生成 32,112 个 verified tuples 和 110 个环境；GSPO 训练后在 OSWorld-Verified 和 held-out WebArena 上都有收益。它最值得借鉴的不是某个 policy trick，而是“环境工厂 + reward 工厂 + 数据工厂”的系统化范式。
