一句话概括：异步 RL 中，rollout 来自行为分布 $q$，trainer 却用当前策略 $p$ 计算 score；当 $q\ne p$ 时，score 在真实采样分布下不再零均值，reward 的平均值会被错误地转成一个持续的参数更新方向。Score Centering（SC）直接减去行为分布下的平均 score，恢复 baseline invariance；如果还需要把行为分布校正到目标分布，再与 importance sampling 组合。

1. 背景：为什么一个 RL 系统会有两个 policy

LLM 强化学习的一轮训练通常拆成两段。Generator / sampler / inference engine 根据当时的模型和推理设置生成回答或完整轨迹，并按这次生成实际使用的分布采样 token；Trainer / training engine 稍后读取轨迹，用当前参数重新计算 log-prob，再进行反向传播。

理想的同步实现中，这两个分布相同。但工程系统常把它们拆开以提高 GPU 利用率，因而会出现两类 mismatch：

  • 数值/实现 mismatch：即使加载相同权重，训练和推理也可能使用不同 kernel、batch shape、浮点精度、量化方式或 KV cache，最终 logits 只有细微差异。
  • 异步 staleness：rollout 生成期间 trainer 继续更新，generator 只周期性同步权重；长 episode 中，同一条轨迹的不同 token 甚至来自不同 checkpoint。

下面记 generator 的行为分布为 $q$，trainer 当前用于计算梯度的策略为 $p_\theta$。关键问题不是“两个模型差多少”这么简单，而是偏差是否会在训练闭环中持续累积。

2. 从 score function 推导 policy gradient

固定一个 prompt 或 prefix $x$，模型从离散分布 $p_\theta(a\mid x)$ 采样 action $a$。对 LLM 来说，action 可以是下一个 token，也可以代表一段完整回答。目标是最大化期望 reward：

\[J(\theta)=\mathbb E_{a\sim p_\theta}[R(a)].\]

reward 可以是不可微的，例如正确答案给 1、错误答案给 0。对期望展开并使用 $\nabla p=p\nabla\log p$：

\[\begin{aligned}\nabla_\theta J(\theta)&=\sum_a R(a)\nabla_\theta p_\theta(a)\\&=\sum_a p_\theta(a)R(a)\nabla_\theta\log p_\theta(a)\\&=\mathbb E_{a\sim p_\theta}\left[R(a)\,\underbrace{\nabla_\theta\log p_\theta(a)}_{s_\theta(a)}\right].\end{aligned}\]

$s_\theta(a)$ 就是 score function：它不是 reward 分数，而是“改变参数后，这个 action 的 log-prob 会朝哪个方向变化”的梯度。$R(a)$ 决定样本应该被鼓励还是抑制，$s_\theta(a)$ 决定参数如何改变该样本的概率。PPO、GRPO 等方法在此基础上加入 token-level 分解、advantage、importance ratio 和 clipping，但核心方向仍包含 $\nabla_\theta\log p_\theta(y_t\mid y_{<t})$。

3. On-policy 时 score 为什么是零均值

固定一个 prefix，令 $v$ 遍历当前词表中的所有候选 token，模型对每个 token 输出 logit $z_\theta(v)$。logit 不是概率，它可以是任意实数；softmax 用指数函数把它转换成归一化分布：

\[p_\theta(a)=\frac{e^{z_\theta(a)}}{\sum_v e^{z_\theta(v)}}.\]

分母是所有候选 token 的指数和，因此保证 $\sum_a p_\theta(a)=1$。对上式取对数，并使用 $\log(u/v)=\log u-\log v$ 以及 $\log e^z=z$：

\[\begin{aligned}\log p_\theta(a)&=\log\left(\frac{e^{z_\theta(a)}}{\sum_v e^{z_\theta(v)}}\right)\\&=z_\theta(a)-\log\sum_v e^{z_\theta(v)}.\end{aligned}\]

这就是图中的公式。第二项 $\log\sum_v e^{z_\theta(v)}$ 是 log-sum-exp 归一化项：它同时依赖所有候选 token，而不是只依赖被选中的 $a$。如果把 $a$ 换成语言模型在时间步 $t$ 生成的 $y_t$，这里的概率就是条件概率 $p_\theta(y_t\mid y_{<t})$。

现在对参数 $\theta$ 求梯度，并记 logit 的参数梯度为 $J_\theta(v)=\nabla_\theta z_\theta(v)$。对归一化项使用链式法则：

\[\begin{aligned}\nabla_\theta\log\sum_v e^{z_\theta(v)}&=\frac{1}{\sum_u e^{z_\theta(u)}}\sum_v e^{z_\theta(v)}\nabla_\theta z_\theta(v)\\&=\sum_v p_\theta(v)J_\theta(v)\\&=\mathbb E_{v\sim p_\theta}[J_\theta(v)].\end{aligned}\]

因此 score function，也就是该 action 的 log-prob 对参数的梯度，为：

\[s_\theta(a)=\nabla_\theta\log p_\theta(a)=J_\theta(a)-\mathbb E_{v\sim p_\theta}[J_\theta(v)].\]

它可以理解为“被选 token 的梯度”减去“按当前策略对所有 token 梯度求的平均值”。如果 action 确实从同一个 $p_\theta$ 采样，那么：

\[\mathbb E_{a\sim p_\theta}[s_\theta(a)]=\mathbb E_{p_\theta}[J_\theta]-\mathbb E_{p_\theta}[J_\theta]=0.\]

这解释了 policy gradient 为什么可以减去只依赖 state 或 prefix、但不依赖具体 action 的 baseline $b(x)$：

\[\mathbb E_{p_\theta}[(R(a)-b(x))s_\theta(a)]=\mathbb E_{p_\theta}[R(a)s_\theta(a)]-b(x)\underbrace{\mathbb E_{p_\theta}[s_\theta(a)]}_{0}.\]

所以 baseline 不改变期望梯度，只降低估计方差。advantage、value baseline 和 GRPO 的 group-relative reward 都建立在这个零均值结构上。

4. Mismatch 如何制造 drift

异步场景中，真实 action 来自 $q$，但 score 仍由 trainer 的 $p_\theta$ 计算：

\[s_\theta(a)=\nabla_\theta\log p_\theta(a),\qquad a\sim q.\]

此时通常有：

\[\bar s=\mathbb E_{a\sim q}[s_\theta(a)]\ne0.\]

原本无害的 baseline 会额外产生 $-b(x)\bar s$。更直观地，把 reward 下的期望更新拆成：

\[\mathbb E_q[R s_\theta]=\underbrace{\mathbb E_q[R]\,\mathbb E_q[s_\theta]}_{\text{drift}}+\underbrace{\operatorname{Cov}_q(R,s_\theta)}_{\text{真正的 reward-token signal}}.\]

drift 只依赖 reward 均值和 sampler 下的平均 score，并不关心哪条轨迹成功。它等价于把 trainer 和 sampler 做了一次交叉熵/蒸馏式拉动：每一步都可能把 trainer 拉向 generator 的偏置；当 trainer 权重又同步回 sampler 时，偏差就会进入下一轮 rollout，形成反馈闭环。

Group centering 为什么不够

GRPO 对同一 prompt 的一组回答减去组均值，使整组 advantage 均值为零，但这不等于每个 prefix 下的 score 期望都为零。接近正确答案的 prefix 可能贡献正的条件期望，已经走错的 prefix 可能贡献负的条件期望，而 drift 恰恰可能集中在这些 prefix 上。因此 group centering 能减小一部分偏差，却不能从原理上消除 mismatch drift。

5. Score Centering：按行为分布重置中心

对固定 prefix，论文定义 behavior-centered score：

\[\tilde s_\theta(a)=s_\theta(a)-\bar s,\qquad \bar s=\mathbb E_{v\sim q}[s_\theta(v)].\]

由于 sample 和中心项都在同一个 $q$ 下取期望：

\[\mathbb E_{a\sim q}[\tilde s_\theta(a)]=\mathbb E_q[s_\theta]-\bar s=0.\]

于是对任意只依赖 prefix 的 baseline，期望更新重新具有 baseline invariance：

\[\mathbb E_q[R\tilde s_\theta]=\operatorname{Cov}_q(R,\tilde s_\theta)=\operatorname{Cov}_q(R,s_\theta).\]

从原始更新中看，SC 删除的正是 $\mathbb E_q[R]\bar s$ 这一项，而保留 reward 与 token score 的关联信号。这里的“中心化”是针对真实行为分布的修正，不是把整个 off-policy 问题都变成 on-policy。

重要边界

on-policy 目标是在 $p$ 下测量 $\operatorname{Cov}_p(R,s)$，SC 剩下的是在 $q$ 下测量的 $\operatorname{Cov}_q(R,s)$。除非 $q=p$ 或满足额外条件，两者一般不相同。因此 SC 恢复的是零均值和 baseline invariance，而不是完整的 trainer-policy gradient。

6. 从 score 向量到可实现的 scalar loss

直接存储每个 token 的 Jacobian 不可行，但只需要构造一个让 autograd 得到目标梯度的 surrogate。对固定 prefix：

\[\log p_\theta(a)-\mathbb E_{v\sim q}[\log p_\theta(v)]=z_\theta(a)-\mathbb E_{v\sim q}[z_\theta(v)].\]

因此可以使用下面的 token loss，其中 $q$ 的系数 stop-gradient：

\[L_{\mathrm{SC}}=-A(a)\left(\log p_\theta(a)-\sum_v\operatorname{sg}[q(v)]\log p_\theta(v)\right).\]

反向传播得到：

\[-\nabla L=A(a)\left(s_\theta(a)-\mathbb E_q[s_\theta]\right).\]

用 logit 形式时，只需计算 selected token 与行为分布加权平均 logits 的差，不需要为了 SC 额外保存完整 log-softmax 分布。这里并不是说模型前向不再需要输出词表 logits，而是 SC correction 本身可以只依赖选中的 token 和可压缩的中心项。

7. Top-k head + rescaled trainer tail

每个 token position 的完整 sampler vocabulary distribution 成本很高：152K 词表下，单个位置的 fp32 概率约 608 KB；若 batch 中有 1,024 条、每条 32K token，仅保存这部分就接近 20 TB。论文因此只记录 sampler 的 top-$k$ log-probs，默认 $k=128$，再近似剩余 tail。

令 $H$ 是 sampler top-$k$ token，$T$ 是其余 token。head 使用 sampler 概率，tail 使用 trainer 概率并重缩放到 sampler 的 tail mass：

\[\hat q_v=\begin{cases}q_v,&v\in H,\\\rho p_v,&v\in T,\end{cases}\qquad \rho=\frac{1-\sum_{v\in H}q_v}{1-\sum_{v\in H}p_v}.\]

利用 trainer 自身完整词表 score 的均值为零，tail 的期望可由 head residual 得到：

\[\mathbb E_{\hat q}[s_\theta]=\sum_{v\in H}(q_v-\rho p_v)s_\theta(v).\]

工程上可按四步实现：

  1. Generator 采样真实 token，记录其 log-prob、每个 prefix 的 top-$k$ token IDs、sampler log-probs、top-$k$ mass 和 tail mass。
  2. Trainer 用当前模型前向，重新取 sample token 和 head token 的 log-prob/logit。
  3. 计算 trainer 与 sampler 的 head/tail mass，构造 stop-gradient 的 head residual 系数。
  4. 将 residual 写入 scalar loss，乘以 advantage 后正常 backward。

与 alternative-token Monte Carlo 的区别

可以在同一 prefix 下额外从 $q$ 抽取若干 alternative token，用 trainer 的 logit 估计 $\mathbb E_q[J_\theta]$；这确实是一个 Monte Carlo estimator，也适合建立直觉。但论文实验主要使用 top-$k$ exact head + rescaled trainer tail，而不是把 $K$ 个 alternative token 做简单均匀平均。两者属于同一中心化目标的不同近似，不能混称为论文默认实现。

在线与离线 mismatch 的诊断

8. 与 Importance Sampling 组合

如果已经有 IS 权重 $w_v=f(p_v/q_v)$，论文不是简单地“先 IS、再套 vanilla SC”，而是对加权 score做中心化：

\[R\left(w_a s_\theta(a)-\mathbb E_q[w_v s_\theta(v)]\right).\]

精确 IS 取 $w=p/q$ 时，$q$ 下的加权 score 均值已经等于 $p$ 下的 score 均值，即为零，因此额外 SC correction 消失。这是一个重要 sanity check。实际训练常使用 truncated 或 masked IS（TIS/MIS），裁剪权重会重新引入偏差，所以 SC 与 IS 可以互补。

在 top-$k$ tail 模型中，tail ratio 常是常数 $1/\rho$，因此 correction 可以主要在 head 上计算，并推导出相应的闭式系数。SC 负责去除行为分布下的 drift，IS 负责校正行为分布和目标分布之间的差异。

9. 实验设置与核心结果

9.1 Offline 与 online 诊断

作者在 Qwen3-1.7B Countdown 上人为制造 sampler 与 trainer 的权重偏差，对比 offline/online 训练和不同 reward 编码。offline 训练在非负 $+1/0$ reward 下相对稳定；online RL 在 mismatch 存在时反而更容易失稳，group-centered reward 相对更稳。解释是在线 sampler 会跟随 trainer 更新，形成持续的 drift 闭环，而固定 teacher 的离线训练没有同样的累积路径。

9.2 人工 weight noise

在 Qwen3-0.6B Countdown 上给 sampler 权重加入固定 Gaussian offset。mismatch 越强，普通 policy gradient 越早 collapse；SC 单独使用或和 TIS/MIS 组合都能延后 collapse。该设置不是完整部署环境，但可以连续控制 mismatch 强度，适合诊断修正项是否真的针对 drift。

9.3 Quantization 与 staleness

在 Qwen3-0.6B 上分别测试量化 sampler 和强制 staleness（inference engine 每 64 个 trainer step 才同步一次）。量化 setting 下 SC 单独或与 TIS/MIS 组合表现最好；staleness setting 下，SC+TIS/MIS 通常优于 vanilla SC。前者主要由数值 drift 驱动，后者还包含明显的 distribution shift。

10. 30B 规模与 Top-k 消融

在 INTELLECT-2 数学数据上，作者训练 Qwen3-30B-A3B-Base，并逐步加重 sampler 量化。FP8 sampler 下未修正 PG 仍可训练，准确率约 58%；KV cache 降到 FP4 后，PG 约 200 step 内 collapse，MIS 后期也会 collapse，而 SC 与 TIS 更稳定，准确率约为 52% 和 51%。在更激进的 INT8 W/A + INT4 KV 设置下，SC 约 30%，TIS 约 12%，其余方法最终低于 5%。

top-$k$ 消融显示，$k=128$ 通常覆盖 sampler 超过 99% 的概率质量；在 30B INT8 W/A + INT4 KV setting 中，平均覆盖约 99.45%，batch 级覆盖约 95.8%。相对 baseline，JAX sampler 的额外耗时约 1%，但论文没有给出与直接 vLLM/SGLang 集成后的实际端到端开销。

11. 结论、边界与实践建议

  • 主要结论：在 generator/trainer mismatch 下，score 的非零均值会把 reward 均值变成与成功轨迹无关的 drift；按行为分布做 SC 能直接删除这项漂移。
  • 方法边界：SC 去除的是 $q$ 下的 score drift，不等于完整 off-policy 校正，也不能自动解决 reward misspecification、credit assignment 或长 horizon 问题。
  • 实现边界：top-$k$ + tail 是高效近似，必须验证 sampler top-k mass、tail scaling 和 $\mathbb E_q[\tilde s]$ 的数值误差；不能把 alternative-token Monte Carlo 误认为论文默认实现。
  • 工程建议：先分别统计 kernel/精度/量化造成的 numerical mismatch 和 checkpoint lag 造成的 staleness；轻度 mismatch 可先用 SC，rollout 较旧或分布差异较大时使用 SC+TIS/MIS。
  • 实验外推：论文主要覆盖 Countdown 和 INTELLECT-2 数学任务，30B 结果部分来自单 seed，不能直接外推到长时程 coding agent 或复杂 reward。
