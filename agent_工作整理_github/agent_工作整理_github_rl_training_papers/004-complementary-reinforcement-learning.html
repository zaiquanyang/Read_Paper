方法核心

现有利用经验的方法存在一个根本问题：将经验视为静态资源。

  • 离线经验：预先从历史轨迹构建经验库，训练中保持不变。初始有优势，但随着 actor 能力增长，经验逐渐过时（stale），收益衰减。
  • 静态在线经验：训练过程中由固定提取器动态维护经验库，但提取器不更新。无法适应 actor 的演化，导致分布错位（distributional misalignment），经验与 actor 当前能力脱节。
  • 自反思方法：依赖模型自身生成反思，但弱模型容易产生幻觉，不可靠。
  • 复杂启发式方法：多阶段检索、专门数据结构等，增加了工程复杂度。

关键洞察：经验提取和 agent 学习应该协同演化（co-evolve），而非各自独立处理。

  • Actor-Extractor Co-Evolution：actor 和 extractor 必须在训练中互相适应，持续塑造彼此
  • Experience Consolidation：经验库必须自动构建和维护，蒸馏可迁移经验，解决冲突和冗余
  • Training-Distillation Coordination：actor 训练和经验蒸馏必须高效协调，不能引入阻塞延迟

Complementary RL 包含两个互补模型：

  • Actor $\pi_{\theta}$：与环境交互，通过 outcome-based reward 优化，受检索到的经验指导
  • Experience Extractor $\pi_{\phi}$：从轨迹中蒸馏经验，维护持续演化的经验库 $\mathcal{M}$

两者都通过 RL 优化：actor 用结果奖励，extractor 用其蒸馏经验对 actor 成功的效用作为奖励。

为了避免 actor 训练被经验蒸馏阻塞，设计了完全异步的双轨架构：

主训练循环（Primary Training Loop）：

  • Actor $\pi_{\theta}$ 持续与环境交互收集 rollout
  • 通过 outcome-based reward 优化策略

后台轨道（Background Track）：

  • Experience extractor $\pi_{\phi}$ 处理完成的轨迹
  • 蒸馏经验并向 $\mathcal{M}$ 发出结构化操作

两者通过集中式 ExperienceManager $\mathcal{H}$ 协调，承担两个角色：

1. Experience Consolidation（经验巩固）：

  • $\mathcal{H}$ 维护内部队列 $\mathcal{Q}$ 接收蒸馏请求
  • 后台进程持续出队并转发给 $\pi_{\phi}$ 蒸馏
  • $\pi_{\phi}$ 发出三种结构化操作：Add（新增）、Update（更新）、Return（无操作）
  • 在 writer lock 下应用操作，防止状态冲突
  • Periodic Merge：定期触发合并操作，处理 group-based RL 中同一任务并行产生的冗余经验

2. Experience Retrieval（经验检索）：

  • 查询批处理：$\mathcal{H}$ 将并发查询累积为 micro-batch
  • Embedding 缓存：group-based RL 中多个环境共享相同任务描述，缓存命中率高
  • 并行搜索：$W$ 个并行搜索 worker 在 reader lock 下执行语义相似度搜索...

实验与结论

环境：MiniHack Room, WebShop, ALFWorld, SWE-Bench

模型配置：

  • Actor $\pi_{\theta}$：Qwen2.5-7B-Instruct（SWE-Bench 用 Qwen3-4B-Instruct-2507）
  • Experience Extractor $\pi_{\phi}$：Qwen3-4B-Thinking-2507
  • Embedding 模型：Qwen3-Embedding-0.6B

训练配置：AdamW, lr=1e-6, 不使用 KL 正则化，4 个并行搜索 worker + 4 个并行 embedding worker

Complementary RL 在所有四个任务上一致优于无经验 baseline：

  • MiniHack Room 和 ALFWorld（需策略探索和环境理解）：获得 1.3x 性能优势
  • SWE-Bench：获得 +3.0% 提升

效率提升：Complementary RL 不仅成功率更高，而且完成任务需要的动作更少：

  • MiniHack Room：1.5x 更少动作
  • ALFWorld：2x 更少动作

核心发现：

  • Static Online Exp. 即使在测试时使用经验也低于 baseline（差距 >10%），原因是分布错位——固定提取器无法适应演化中的 actor
  • Complementary RL 在有/无经验测试时均一致优于 baseline（平均 +7% 和 +2%），说明协同演化训练将有用经验内化到了 actor 自身
  • 仅训练 extractor（Exp. Only）效果差（Avg. 0.33），说明经验质量本身不足以弥补 actor 基础能力的不足...

价值、局限与启发

现有利用经验的方法存在一个根本问题：将经验视为静态资源。

  • 离线经验：预先从历史轨迹构建经验库，训练中保持不变。初始有优势，但随着 actor 能力增长，经验逐渐过时（stale），收益衰减。
  • 静态在线经验：训练过程中由固定提取器动态维护经验库，但提取器不更新。无法适应 actor 的演化，导致分布错位（distributional misalignment），经验与 actor 当前能力脱节。
  • 自反思方法：依赖模型自身生成反思，但弱模型容易产生幻觉，不可靠。
  • 复杂启发式方法：多阶段检索、专门数据结构等，增加了工程复杂度。

关键洞察：经验提取和 agent 学习应该协同演化（co-evolve），而非各自独立处理。

  • 协同演化范式：首次在 RL 训练中实现 actor 与经验提取器的联合优化，两者形成闭合的互相增强循环
  • 子组 advantage 估计：experience-guided/experience-free 分组 + 组内独立 advantage 计算，有效防止 over-reliance 和 advantage 偏差
  • 完全异步架构：actor 训练和经验蒸馏解耦，不引入阻塞延迟
  • 模块化设计：ExperienceManager 统一管理经验的增删改查，并发控制清晰
  • 实用性强：无 KL 正则化、无额外 SFT 阶段、无复杂启发式，训练配置精简
  • 任务扩展性好：3-task 到 6-task 混合，收益从 +6.6% 增长到 +8.1%
  • 丰富的经验分析：展示了蒸馏出的结构化经验，具有可解释性
  • Self-Distillation 集成失败：自蒸馏后期训练崩溃，原因未完全调查清楚
  • Actor-Critic 增加延迟：虽然提升早期表现，但引入非平凡延迟开销，不适合默认启用
  • 提取器 off-policy 问题严重：蒸馏的经验可能在很久之后才被检索，policy lag 大，需要专门的稳定性技巧
  • 评估环境有限：主要在 MiniHack、WebShop、ALFWorld 和 SWE-Bench 上评估，工业级场景验证不足
  • 辅助奖励探索失败：困惑度降低奖励的五种归一化策略均未奏效
  • Extractor 必须独立参数：共享参数导致梯度冲突，增加了显存开销...
