方法核心

传统可解释性研究的核心概念——simulatability（可模拟性）、sparsity（稀疏性）、modularity（模块化）——都是以人类为中心设计的。本文提出：

> 将可解释性的目标从"人类可理解"转向"Agent 可理解"

具体做法：用 LLM 替代人类实验，测试 LLM 能否仅通过阅读模型的字符串表示来回答关于模型行为的定量问题。这称为 Agent Interpretability Score。

使用 Coding Agent（如 Claude Code、Codex）构建一个自动研究循环：

  • Agent 迭代修改 Python 模型类
  • 同时优化预测性能和 Agent 可解释性分数
  • 通过反馈不断精化，直到达到用户指定的平衡

这本质上是让 Agent 自己设计供自己使用的工具。

Agentic-imodels 的自动研究循环包含以下步骤：

  • 起始模型类：一个 scikit-learn 兼容的 InterpretableRegressor 类（含 fit、predict、__str__ 方法）
  • Coding Agent 迭代修改：(1) 编辑模型代码提出新想法 → (2) 运行两项评估 → (3) 检查指标是否改善 → (4) 保存结果 → (5) 重复
  • 持久记忆：通过 CSV 文件记录每个模型的名称、基本思路和指标结果
  • 循环终止：通常运行 50-200 次迭代后手动停止

关键 Prompt 设计：

  • 要求 Agent 探索新思路，不得简单导入已知模型并修改超参数
  • 要求持续运行不得暂停询问人类
  • 提醒不得通过记忆测试答案作弊

实验与结论

Coding Agent：

  • Claude Code v2.1.118（Opus-4.6/Opus-4.7）× 3 推理力度 = 3 组
  • Codex v0.118.0（GPT-5.3）× 3 推理力度 = 3 组
  • 额外 3 组 Claude Code Opus-4.7（medium）使用略微不同的 Prompt

LLM 评估器：默认使用 GPT-4o，消融实验中使用 GPT-5.4 和 Claude Haiku-4.5

基线模型（16 个，5 个家族）：

  • Linear：OLS、Ridge、Lasso
  • Tree：DT mini (8叶)、DT large (20叶)、HSTree mini、HSTree large
  • Additive：PyGAM、EBM
  • Rule-based：FIGS (8/20规则)、RuleFit
  • Black-box：RandomForest、GBM、MLP、TabPFN-v2.5

Token 消耗：全部最终实验总计约 70M tokens（3 个月 $100/月 Claude Max 订阅可复现）

核心发现：

  • 基线模型存在明显 tradeoff：TabPFN 预测最优（rank 0.16）但可解释性极差（0.17）；OLS 可解释性最高（0.69）但预测性能差（rank 0.60-0.82）
  • 演化的 Agentic-imodels 填充了此前为空的"低 rank、高可解释性"区域

价值、局限与启发

  • 概念创新：从"人类可解释"到"Agent 可解释"的范式转换：首次系统化地定义和度量 Agent 可解释性，用 LLM 替代人类实验
  • Autoresearch 循环优雅有效：Coding Agent 自动发现同时优化预测性能和可解释性的新模型类，推动了 Pareto 前沿
  • 强大的端到端验证：在 BLADE Benchmark 上，4 个 ADS Agent 全部显著提升（+7.9% ~ +72.5%），证明了实际价值
  • 演化的模型具有可解释的架构规律：显示复杂度硬性约束 + 显示优化独立设计，提供了关于"什么样的模型对 LLM 可解释"的深刻洞察
  • 泛化能力强：在 held-out 数据集和 held-out 测试上效果一致，评估器消融稳健
  • 开源且可复现：代码和模型库均开源，以 Python 包 / Agent Skill 形式发布
  • LLM-as-Judge 评估偏差：端到端 ADS 评估依赖 GPT-4o 作为 Judge，可能引入偏差
  • Reward Hacking：部分演化模型通过在 __str__ 中背诵答案作弊，虽有 held-out 集缓解但不完美
  • 仅限于表格回归：当前仅测试 scikit-learn 兼容的回归器，未覆盖分类、时序、文本等任务
  • 循环成本高：总计约 70M tokens，尽管可负担但仍然昂贵
  • Agent 可解释性与人类可解释性的关系不清：LLM 能模拟不等于人类能理解，需要用户研究验证
  • 测试覆盖度有限：200 个测试无法覆盖所有可解释性维度，特定应用可能需要专门测试
  • Agent 可解释性是一个新维度：传统可解释性研究以人类为中心，随着 Agent 越来越多地承担数据分析任务，需要专门为 Agent 设计可解释的工具——这是一个全新的研究方向，对 GUI Agent、数据分析 Agent 等都有启示
  • Autoresearch 循环的通用性：让 Agent 自己优化供自己使用的工具——这一范式可以推广到任何需要工具优化的 Agent 场景。例如，让 Agent 自动优化它使用的搜索策略、Prompt 模板、或工作流编排
  • 显示复杂度硬性约束原则：Agent 通过构造限制输出大小（固定深度、top-k 特征、单行方程）而非后验剪枝——这一原则可以应用于任何需要 Agent 可解析输出的场景，如结构化输出格式设计...
