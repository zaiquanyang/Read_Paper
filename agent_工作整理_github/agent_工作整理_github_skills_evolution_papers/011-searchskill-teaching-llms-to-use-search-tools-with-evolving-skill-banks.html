SearchSkill: Teaching LLMs to Use Search Tools with Evolving Skill Banks

agent
核心思想：SearchSkill 通过“先选技能、再执行搜索/回答”的显式控制接口，以及可迭代演化的 SkillBank，把搜索行为从粗粒度动作变为技能条件化决策；在多跳 QA 上显著优于多类基线，并在小搜索预算下提升正确率与检索效率。

问题与动机

论文指出现有检索增强/工具调用方法的两类痛点：

  • 很多方法强调“触发搜索”，但较少建模“怎么搜（query formulation）”；
  • 多跳问题中常见失败是直接复制原问题发起搜索，导致检索噪声、冗余调用与后续推理漂移。

因此作者希望把“搜索策略”模块化为可复用技能，并在每一步动作前显式选择技能。

实验与结论

  • 数据集：NQ、TriviaQA、PopQA（单跳）+ HotpotQA、2Wiki、MuSiQue、Bamboogle（多跳）。
  • 模型：Qwen2.5 7B / 3B 的 Base 与 Instruct。
  • 对比：Direct、CoT、RAG、Search-o1、ZeroSearch、SearchR1（GRPO）。
  • 指标：EM（Exact Match）与 7 数据集宏平均。

价值、局限与启发

SearchSkill 通过“先选技能、再执行搜索/回答”的显式控制接口，以及可迭代演化的 SkillBank，把搜索行为从粗粒度动作变为技能条件化决策；在多跳 QA 上显著优于多类基线，并在小搜索预算下提升正确率与检索效率。

  • 技能库构建与演化仍依赖高质量教师与人工规则流程。
  • 技能数量增加后，选择空间与维护复杂度上升。
  • 目前主要在 QA 场景验证，跨任务泛化（如网页操作 agent）仍需进一步实证。
  • 可以把“工具调用前策略决策”作为独立监督目标，而不仅监督最终答案。
  • 在多工具 agent 中，建议把“技能选择”作为显式中间动作，配合可读 skill card。
  • 对于预算敏感场景，优先优化 query planning 指标（复制率、原子跳、预算内正确率），往往比盲目增加搜索步数更有效。

SearchSkill 的核心贡献是把搜索从“黑盒动作”转为“技能条件化的可控过程”。它在多跳 QA 上提供了稳定且可解释的提升，尤其证明了一个实用结论：高质量检索代理的关键不是“搜得更多”，而是“每一步搜得更对”。
