EvoVid: Temporal-Centric Self-Evolution for Video Large Language Models

agent
核心思想：EvoVid 提出一个面向 Video-LLM 的时序中心自进化框架：通过“时序敏感问题奖励”和“时序定位求解奖励”联合训练 Questioner 与 Solver，使模型仅依赖原始无标注视频就能持续提升视频理解与推理能力。

问题与动机

现有视频后训练和 RL 方法大多依赖人工标注的问题、答案或轨迹，扩展成本高。

已有 self-evolving 框架虽然能在文本或图像上通过 Questioner-Solver 自博弈学习，但直接搬到视频时，常常生成“单帧即可回答”的问题，没法显式利用视频最关键的时序结构。

论文的核心判断是：

  • 视频理解的关键不只是视觉内容；
  • 还包括顺序、状态变化、因果关系、跨帧依赖；
  • 如果奖励函数不把这些时序属性显式拉进来，自进化就会退化成静态模态版本。

相较 vanilla self-evolving，EvoVid 生成的问题包含更多时序和推理相关词：

  • frame
  • change
  • reason
  • interaction
  • consider

说明 Questioner 确实逐步从静态视觉问答转向动态视频理解。

方法核心

以 Qwen2.5-VL-7B 为例，平均成绩如下：

  • Base：47.9
  • SFT（有标注）：49.0
  • SFT + Vanilla GRPO（有标注）：51.3
  • Vanilla Self-evolving（无标注）：48.6
  • EvoVid（Iter-3，无标注）：50.0
  • SFT + EvoVid（Iter-3）：51.2

也就是说：

  • 无标注 EvoVid 已经明显超过 vanilla self-evolving；
  • 仅靠原始视频训练，已经逼近有标注的 SFT+GRPO；
  • 若在 SFT checkpoint 上继续用 EvoVid，自进化结果几乎追平监督 RL。

实验与结论

  • 训练数据：来自 LLaVA-Video-178K、STAR、CLEVRER、PerceptionTest、NeXT-QA、Video-Holmes 的原始视频，总计 5,778 个视频。
  • 重要点：训练中 完全不使用这些数据集的标注，只用原始视频。
  • 评测基准：6个视频 benchmark
  • Video-Holmes
  • VSI-Bench
  • VideoMMMU
  • MMVU
  • TempCompass
  • VideoMME
  • 基座模型：Qwen2.5-VL-3B/7B、Qwen3-VL-4B/8B。

价值、局限与启发

EvoVid 提出一个面向 Video-LLM 的时序中心自进化框架：通过“时序敏感问题奖励”和“时序定位求解奖励”联合训练 Questioner 与 Solver，使模型仅依赖原始无标注视频就能持续提升视频理解与推理能力。

  • 伪标签来自多数投票和时间窗口，仍然存在噪声；
  • 时间窗口 supervision 主要覆盖局部片段，复杂跨段依赖可能仍不足；
  • 当前验证集中在 Qwen 系 Video-LLM，跨架构泛化还需要更多证据。
  • 多模态 agent 的自进化奖励必须和模态本质强绑定：视频就该显式奖励时序结构，而不是沿用图像/文本套路。
  • 可以把“训练时的输入采样方式”反过来当作天然伪监督信号，降低标注依赖。
  • Questioner-Solver 共进化不仅是生成训练题，更是在自动构造难度递增课程。
