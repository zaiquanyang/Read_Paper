方法核心

当前 skill 生态的根本问题在于：量大但覆盖碎片化（abundant volume but fragmented coverage）。

绝大多数 skills 是个人为解决特定问题而开发的，设计天然聚焦于局部用例，难以系统性覆盖复杂专业任务的全面功能需求。用户在执行多方面任务时仍然面临功能缺口和集成瓶颈。

本文提出核心问题：Agent 能否自主探索现有 skills 的能力边界并主动扩展，实现 skill 自进化？

将该问题分解为三个子问题：

  • 如何自动生成边界探测任务？ 需要构造具有挑战性和全面性的测试集，既要达到 skill 的能力上限，又要保证系统性
  • 如何实现 skill 自进化？ 从失败探索中提取模式，动态更新 skill 模块，同时确保与现有 skill 生态的一致性
  • 如何有效评估 skill 能力？ 构建鲁棒的评估框架，精确量化 skill 在各维度的表现

Skills-Coach 是一个自动化的 Skill 自进化框架，针对特定 skill，系统地探索其能力边界、分析优化空间、自动生成改进版本，并编译为结构化报告。包含四个核心模块：

  • Diverse Task Generation Module（多样化任务生成模块）
  • Lightweight Optimization Module（轻量优化模块）
  • Comparative Execution Module（对比执行模块）
  • Traceable Evaluation Module（可追溯评估模块）

实验与结论

为评估框架并为社区提供资源，本文引入 Skill-X benchmark：

  • 48 个广泛使用的 skills（来自 ClawHub、Anthropic、Vercel Labs、SkillSh）
  • 两种类型：29 个 instruction-only skills + 19 个 code-inclusive skills
  • 覆盖广泛的实际应用场景，从基础数据处理到复杂逻辑交互
  • 默认 3 个优化 epoch
  • 每个 skill 生成 12 个训练任务 + 8 个测试任务
  • 训练集：6 standard + 6 advanced
  • 测试集：4 standard + 4 advanced
  • Training-Free GRPO：每个 epoch 生成 3 个 rollout 变体（group_size=3）
  • Auto-Fix：最多 2 轮迭代修复
  • 优化/修复组件默认使用 Claude Sonnet 4.6

关键发现：

  • 平均分从 0.378 提升到 0.84（124% 相对增长）
  • 通过率从 33.59% 飙升到 88.02%（+54.43%）
  • Code-inclusive skills 获得最大的相对提升（+0.499），说明框架对需要复杂逻辑推理的任务特别有效
  • Advanced tasks 的改善幅度大于 Standard tasks，表明 Skills-Coach 在处理更具挑战性的问题上有显著优势

价值、局限与启发

当前 skill 生态的根本问题在于：量大但覆盖碎片化（abundant volume but fragmented coverage）。

绝大多数 skills 是个人为解决特定问题而开发的，设计天然聚焦于局部用例，难以系统性覆盖复杂专业任务的全面功能需求。用户在执行多方面任务时仍然面临功能缺口和集成瓶颈。

  • 首个自动化 Skill 自进化框架：闭环地探索能力边界 → 生成改进 → 对比评估 → 保留决策，无需持续人工干预
  • Training-Free GRPO 替代参数优化：训练时间从小时级降到分钟级，数据需求从数千降到几十，同时避免过拟合
  • 大规模实证验证：在 Skill-X 的 48 个 skills 上展示了平均 124% 的性能提升和 +54.43% 的通过率提升
  • 差异化优化策略：针对 instruction-only 和 code-inclusive skills 采用不同的优化路径，提高了针对性
  • 双模式评估（Virtual + Real）：支持快速原型验证和精确评估
  • 51 个离散评估指标：8 维评估体系确保评估的全面性和客观性
  • 依赖 LLM 生成质量：任务生成、指令优化、反思修复都依赖 LLM 能力，当 LLM 产生低质量输出时可能影响优化效果
  • Virtual Mode 精度有限：基于关键字匹配和哈希随机数估计任务完成度，可能与真实表现存在偏差
  • 优化 epoch 数固定为 3：未探索不同 epoch 数对优化效果的影响，可能存在欠优化或过优化
  • 单 skill 优化：当前框架每次优化单个 skill，未涉及 skills 之间的协同优化
  • 评估维度偏文档化：51 个指标中有较多偏向文档质量的维度（结构完整性、清晰度等），对实际功能能力的评估可能不够深入
  • Skill-X 的 skills 主要来自 Claude 生态：可能存在平台偏见
  • Agent Skill 可以自进化：通过"生成边界任务 → 执行测试 → 分析失败 → 迭代修复"的闭环，skills 可以自主改进而无需人类干预。这一思路可推广到任何需要持续改进的 Agent 能力模块...
