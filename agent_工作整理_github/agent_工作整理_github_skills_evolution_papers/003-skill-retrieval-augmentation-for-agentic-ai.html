问题与动机

当前 Agent 系统使用外部技能（skill）的主流方式是在上下文中显式枚举可用技能（如 OpenClaw 的 SKILL.md）。但这种方案存在根本性的扩展性问题：

  • 上下文窗口有限：技能生态正在爆炸式增长——截至 2026 年 4 月，SkillsMP 等平台已托管超过 100 万个技能，无法全部放入上下文
  • 选择精度下降：当大量技能同时出现在上下文中时，LLM 识别正确技能的能力急剧退化

本文提出核心问题：*能否让 Agent 从大规模外部技能库中动态检索、加载和应用相关技能，而非依赖上下文中固定的小规模技能集？*

围绕 SRA 流水线设计了 6 个研究问题：

  • RQ1：SRA 能否提升 Agent 性能？（有效性）
  • RQ2：SR-Agent 对检索噪声的鲁棒性如何？（鲁棒性）
  • RQ3：现有检索方法在技能检索上效果如何？（检索质量）
  • RQ4：检索质量如何影响端到端性能？（检索-任务关联）
  • RQ5：Agent 是否具备相关性感知的技能加载行为？（Relevance-aware）
  • RQ6：Agent 是否具备需求感知的技能加载行为？（Need-aware）

方法核心

  • 上下文窗口有限：技能生态正在爆炸式增长——截至 2026 年 4 月，SkillsMP 等平台已托管超过 100 万个技能，无法全部放入上下文
  • 选择精度下降：当大量技能同时出现在上下文中时，LLM 识别正确技能的能力急剧退化

本文提出核心问题：*能否让 Agent 从大规模外部技能库中动态检索、加载和应用相关技能，而非依赖上下文中固定的小规模技能集？*

  • BM25 惊人地有竞争力：当技能涉及专业术语、公式或代码模式时，稀疏检索依然很强
  • BGE 优于 Contriever：语义匹配场景下密集检索更优
  • 混合检索主要提升候选覆盖率，而非 top-1 排名质量
  • LLM 重排序最强：表明技能检索不仅需要语义相关性，还需要判断候选是否构成"可操作的能力"
  • 检索难度高度依赖任务领域

实验与结论

这一部分当前还没有补到更细的整理。

价值、局限与启发

  • 技能整合机制研究不足：虽然发现了问题，但未提出解决"技能加载幻觉"的具体方法
  • 技能类型偏推理型：SRA-Bench 主要覆盖数学、逻辑、代码、医学计算等推理密集型任务，对日常 Agent 场景（如文件操作、API 调用）覆盖有限
  • 检索方法探索有限：主要对比了 BM25、BGE 等通用检索器，未探索面向技能的专用检索模型
  • 仅研究单轮交互：未涉及多轮对话或迭代式技能加载场景
  • 技能间关系未建模：语料库中技能被独立索引，未考虑技能间依赖、组合或层级关系
  • 结构化技能库：将技能组织为图/层级/聚类结构，支持依赖关系和组合推理
  • 技能质量控制与离线优化：通过执行测试、Agent 自改进循环等手段持续维护技能质量
  • 效用感知检索：从端到端任务反馈中训练检索模型，优化"有用性"而非仅"相关性"
  • 参数化技能增强：将高频技能转化为可加载的参数模块（类似 Parametric RAG），减少上下文开销，实现更深层的能力内化
  • 需求感知的技能加载：训练 Agent 识别自身能力边界，仅在真正需要时加载外部技能
  • 多轮/迭代式技能加载：在推理过程中动态检索和加载技能，而非一次性加载
