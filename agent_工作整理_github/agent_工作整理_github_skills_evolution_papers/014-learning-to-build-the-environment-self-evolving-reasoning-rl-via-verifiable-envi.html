Learning to Build the Environment: Self-Evolving Reasoning RL via Verifiable Environment Synthesis

arXiv 2605.14392
agent arXiv abs PDF arXiv 2605.14392
核心思想：这篇工作最重要的贡献，是把 self-improvement 从“生成更多题”提升到了“生成可复用的训练环境”。EvoEnv 证明了：只要 environment 具备 stable solve--verify asymmetry，模型就有可能在 zero-data reasoning RL 中持续获得有效的 frontier-level reward，而不是被固定分布或 policy-coupled pseudo-label 很快耗尽训练信号。

问题与动机

作者指出，很多 self-improvement / zero-data RL 工作都把问题看成：

  • 生成更多 question
  • 生成更多 rationale
  • 生成更多 hard example
  • 或者用 self-consistency / self-reward 给这些样本打标签

但这种思路有两个结构性问题：

作者在 appendix 里做了一张很有价值的定位表。它区分不同工作的两个轴：

  • self-improvement 合成的基本单位是什么
  • reward source 是否稳定，还是和当前 policy 耦合

在这个框架下：

  • R-Zero / SeRL / SQLM 一类工作：生成的是单个 problem 或 instruction，reward 更 policy-coupled
  • AZR / SCA / Agent0 一类：有 executable grounding，但往往是 per-instance verifier
  • RLVE：环境级训练对象，但环境是 hand-crafted
  • EnvScaler / AutoWebWorld 一类：也是 environment synthesis，但更偏 offline pipeline / tool sandbox

EvoEnv 的独特点是：

  • 合成单位是 reusable environment
  • reward source 是 frozen Python execution
  • 环境 admission 是 on-policy + solver-calibrated + novelty-controlled

方法核心

作者提出一个很强的 thesis：

self-improvement 的基本单位不该是单个 problem，而应该是 environment。

也就是说，模型不只是生成一道题，而是生成一个可执行环境。这个环境里至少包含：

  • sampler：采样 latent task instance
  • oracle：生成 reference answer
  • renderer：把 instance 渲染成自然语言 prompt
  • scorer：对 solver 的回答打分

这样一个 environment 一旦通过验证并进入环境池，它就不再依赖模型当前采样答案，而是通过执行代码提供稳定 reward。

EvoEnv 是一个 single-policy dual-role 框架：

  • 同一个 policy 既充当 generator，又充当 solver
  • generator 负责提议新的 Python environments
  • solver 负责在被接受的 environment pool 中解题

环境不是生成出来就直接用，而是只有在通过多层 admission 之后，才会进入 active pool。

作者强调，环境进入 pool 之前必须满足四类约束：

  • 可执行
  • 语义对齐
  • 难度贴近当前 solver 前沿
  • 环境池足够多样，不发生模板坍缩
  • Qwen3-4B-Instruct: 49.2 -> 53.1
  • Qwen3-4B-Thinking: 72.4 -> 74.8
  • Nemotron-Cascade-8B: 71.0 -> 73.2

这说明方法不是只对某个 model family 偶然有效。

价值、局限与启发

EvoEnv 训练时只依赖自生成 environment，但对外部 benchmark 仍有提升，例如在 Qwen3-4B-Thinking 上：

  • GPQA: 65.2 -> 70.2
  • LiveCodeBench: 59.0 -> 63.2

这说明它学到的不是单纯的 template memorization，而是更 transferable 的 reasoning behavior。

虽然这篇实验设定更偏 reasoning RL，不是典型 tool-use agent，但它对 agent 方向很有启发。

这篇工作也有比较明显的边界。
