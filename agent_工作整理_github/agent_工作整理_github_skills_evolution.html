RE-TRAC: REcursive TRAjectory Compression for Deep Search Agents

agent arXiv abs PDF arXiv 2602.02486
核心思想：这篇论文最有价值的地方，不是单纯提出了一个“多跑几轮”的 agent trick，而是把 deep research agent 的核心瓶颈明确归因为 线性 ReAct 对长程分支搜索的承载不足，并用 trajectory compression + recursive state passing 给出了一个非常实用、易扩展、还能蒸馏到小模型中的解决方案。

问题与动机

这篇论文关注的是 Deep Research / web search agent 在长轨迹任务里的一个很具体但很致命的问题: 模型明明在前面规划过若干搜索分支，但随着 ReAct 轨迹不断变长，后面往往会忘掉这些分支，只沿着单一路径越走越深，最后错过真正有用的信息源。

作者把这个现象总结为 incomplete branch exploration。它不是单纯的“模型不会推理”，而是：

  • 任务本身需要多分支探索、回溯、交叉验证。
  • ReAct 的执行形态却是线性的 action-observation 链。
  • 当上下文极长、工具调用密集时，早期计划会被后续 observation 淹没。
  • 最终失败往往来自“本来该查的分支没查完”，而不是一点思路都没有。

论文对失败轨迹做了分析，在 BrowseComp 上统计到：

Model失败轨迹中存在 incomplete branches 的比例
GLM-4.793.0%
DeepSeek-V3.292.7%
Tongyi-DeepResearch83.4%

这组数字很关键，因为它说明现有 deep research agent 的失败，大量是“搜索管理失败”，而非“能力完全缺失”。

同时，作者还发现很多模型的 Pass@8 明显高于 Pass@1，这意味着模型并不是完全答不出来，而是在单次 rollout 中没有把搜索空间探索到位。

上图想表达的核心结论是：模型其实有潜力在多次尝试中找到正确答案，但传统的 independent rollouts 彼此隔离，无法复用经验，也会带来大量重复搜索。

方法核心

作者提出的方法叫 RE-TRAC，全称是 REcursive TRAjectory Compression。它不是再造一个复杂 agent 框架，而是在 ReAct 之上加了一个“跨 rollout 的经验压缩层”。

最核心的操作只有一句话：

\[S_t \leftarrow \mathrm{Compress}(\tau_t, S_{t-1}; \mathcal{C})\]

其中：

  • $\tau_t$ 表示第 $t$ 轮 rollout 的完整轨迹。
  • $S_{t-1}$ 表示上一轮累计下来的结构化状态。
  • $\mathcal{C}$ 表示固定的 compression specification。
  • $S_t$ 表示新的压缩状态，会被喂给下一轮 agent。

这背后的直觉是：

  • 不要把上一轮完整的超长轨迹原样塞回去。
  • 只保留对下一轮搜索真正有用的“高价值状态”。
  • 让后续 rollout 既知道“已经确认了什么”，也知道“还有哪些未完成分支值得继续查”。

对大模型，RE-TRAC 可以直接当作 inference-time prompting strategy 来用，不需要额外训练。作者把它用于：

  • o4-mini
  • o3
  • GPT-5-medium
  • DeepSeek-V3.2
  • GLM-4.7

然后和几种经典 test-time scaling 方案对比：

  • RT@n: RE-TRAC 跑 $n$ 轮后的最终答案
  • MV@n: $n$ 个独立 rollout 的多数投票
  • WV@n: 带自评置信度的加权投票
  • Best@n: 选自评置信度最高的答案

在 BrowseComp300 上，主要结果如下：

  • 保持现有 ReAct agent 不变。
  • 每轮 rollout 结束后，用固定模板生成三段式状态：
  • conclusions
  • verified evidence
  • unresolved branches
  • 下一轮把这份状态作为新的初始上下文输入。
  • 对比单轮 ReAct、Best-of-N、RE-TRAC 风格递归 rollout 的成功率与工具调用成本。

  • 一个 branch coverage 指标，统计“计划过但未执行”的分支比例。

SkillRL: Evolving Agents via Recursive Skill-Augmented Reinforcement Learning

问题与动机

方法核心

现有 memory-based 方法主要将原始轨迹直接存入外部数据库，存在以下问题：

  • 冗余和噪声：原始轨迹冗长，包含探索性动作、回溯和冗余步骤，信息密度低
  • 缺乏抽象：仅模仿过去的解决方案，无法蒸馏核心原则或将经验内化为策略
  • 上下文膨胀：在有限的 context window 中，原始轨迹占用大量 token 却贡献有限
  • 静态记忆：记忆库作为静态资源，无法随 agent 能力增长而演化

SkillRL 包含三大核心组件：

  • Experience-based Skill Distillation：将冗余轨迹蒸馏为简洁、可操作的知识
  • Hierarchical Skill Library (SkillBank)：分层组织蒸馏出的技能，支持高效检索
  • Recursive Skill Evolution：在 RL 训练中动态精炼技能库，使其与 agent 策略协同演化

问题与动机

方法核心

当前 skill 生态的根本问题在于：量大但覆盖碎片化（abundant volume but fragmented coverage）。

绝大多数 skills 是个人为解决特定问题而开发的，设计天然聚焦于局部用例，难以系统性覆盖复杂专业任务的全面功能需求。用户在执行多方面任务时仍然面临功能缺口和集成瓶颈。

本文提出核心问题：Agent 能否自主探索现有 skills 的能力边界并主动扩展，实现 skill 自进化？

将该问题分解为三个子问题：

  • 如何自动生成边界探测任务？ 需要构造具有挑战性和全面性的测试集，既要达到 skill 的能力上限，又要保证系统性
  • 如何实现 skill 自进化？ 从失败探索中提取模式，动态更新 skill 模块，同时确保与现有 skill 生态的一致性
  • 如何有效评估 skill 能力？ 构建鲁棒的评估框架，精确量化 skill 在各维度的表现

Skills-Coach 是一个自动化的 Skill 自进化框架，针对特定 skill，系统地探索其能力边界、分析优化空间、自动生成改进版本，并编译为结构化报告。包含四个核心模块：

  • Diverse Task Generation Module（多样化任务生成模块）

问题与动机

终端 Agent 任务：$\tau = (\mathcal{E}, s_0, g, V)$，Agent 从初始状态 $s_0$ 在环境 $\mathcal{E}$ 中达成目标 $g$。

场景与技能抽象：

  • 场景 (Scenario) $\sigma_t$：决策点上观察的语义抽象，是到该步交互历史的充分统计量

学习目标：

\[\mathcal{J}(\pi) = \sum_{\sigma \in \Omega} p_{\mathcal{D}}(\sigma|g) \sum_{\kappa \in \mathcal{K}_\sigma} p_{\mathcal{D}}(\kappa|\sigma,g) \log \pi(\kappa|\sigma,g)\]

问题与动机

这篇论文关注的是 Vision-Language Models 在复杂视觉推理中如何处理中间视觉状态。很多视觉问题不是“看一眼图然后文字推理”就能解决的，例如几何题需要辅助线，棋盘/游戏状态需要更新，空间关系题需要局部放大、标注、连线或区域定位。现有路线大致有三类，但各自都有明显代价。

第一类是 unified models，直接生成中间像素级图像。这种方式直观，但需要图像解码和再编码，训练和推理成本都高，还常常需要复杂架构。第二类是 agentic visual reasoning，让模型生成代码或工具调用去操作图像，比如画线、裁剪、标注。这保留了可解释性，但每次操作都要跳出 autoregressive loop，调用外部模块，带来上下文切换、工具执行延迟和长代码输出。第三类是 latent visual reasoning，把中间推理压到隐藏状态或 latent tokens 里，效率更好，但通常依赖额外 latent supervision、重建目标或非标准 recurrent computation，与现有大规模 autoregressive 并行训练不完全兼容。

ATLAS 的核心想法非常简洁：把一个视觉操作压缩成词表里的一个普通离散 token。这个 token 既像 agentic operation，因为它表示“画线、标注、区域操作、箭头、文本”等可解释动作；又像 latent reasoning unit，因为它不会真的调用外部工具或生成图像，而是在模型内部作为一个紧凑的视觉推理单元。论文标题里“One Word is Enough for Both”说的就是这个：一个“词”同时承担 agentic 和 latent 两种角色。

从 agentic 角度看，ATLAS 把外部工具调用内部化了。传统 agentic visual reasoning 会生成代码或工具调用，例如裁剪、画线、标注、调用视觉模块；ATLAS 则把这些操作抽象为普通 token，避免工具执行延迟和不可微外循环。但它仍然保留 agentic 的可解释性，因为 <|Line|>、<|Shape|> 这样的 token 明确告诉我们模型在进行哪类视觉操作。

从 latent 角度看，ATLAS 把中间视觉状态压缩到离散符号，而不是连续 hidden state。它不需要 image reconstruction supervision，也不引入 recurrent latent dependencies，因此更兼容标准 autoregressive parallel training。缺点是 functional token 的表达能力被 5 类粗粒度操作限制，复杂视觉操作可能需要更多 token 类型或组合机制。

形式上，ATLAS 将完整词表定义为：

\[\mathcal{V} = \mathcal{V}_{\mathrm{text}} \cup \mathcal{V}_{\mathrm{spec}} \cup \mathcal{V}_{\mathrm{func}}\]

其中 $\mathcal{V}_{\mathrm{text}}$ 是自然语言 token，$\mathcal{V}_{\mathrm{spec}}$ 是原 VLM 的特殊 token，例如 image placeholder，$\mathcal{V}_{\mathrm{func}}$ 是新加入的 functional token 集合：

\[\mathcal{V}_{\mathrm{func}} = \{\texttt{<|Manip|>},\texttt{<|Shape|>},\texttt{<|Line|>},\texttt{<|Arrow|>},\texttt{<|Text|>}\}\]

价值、局限与启发

ATLAS 的主要优点是把一个工程上很麻烦的问题变成了 tokenizer-level 的简单改动：新增几个 functional tokens，然后用普通 SFT/GRPO/auxiliary token loss 训练。它保留了标准 VLM 架构，不需要图像生成器、外部工具执行，也不需要连续 latent reasoning 模块。这使得它在效率和可扩展性上很有吸引力。

它的限制也清楚。第一，functional token 的实际操作是“内部想象”的，并没有真实执行视觉变换，因此在需要精确几何构造或像素级验证的问题上可能不如真实工具可靠。第二，ATLAS-178K 的构造依赖从 image-construction code 中抽取操作并用 Gemini-2.5-Pro polishing，数据管线仍有一定工程成本。第三，目前只用了 5 个 functional tokens，虽然简洁，但可能难以覆盖更复杂的视觉操作空间。第四，reward design 比较敏感，尤其 $r_{\mathrm{func}}$ 如果没有 $p_{\mathrm{spam}}$ 会导致 reward hacking。

对 agent 方向的启发是：不是所有“agentic action”都必须真的调用外部工具。对于一些频繁、简单、可抽象的操作，可以把 action internalize 成模型词表中的离散 token，让模型在标准生成过程中完成“轻量 agentic reasoning”。这也为更通用的 agent 设计提供了一个思路：外部工具调用可以分层，低成本、常见动作内部化为 functional tokens，高成本、需要真实环境反馈的动作再交给外部工具。

问题与动机

方法核心

  • 昂贵的多重 rollout：GRPO 需要采样多个 rollout 来估计优势，训练成本高（每 epoch 约 17 小时，8×A800）
  • 困难样本的稀疏信号：当所有 rollout 都未命中目标时（二值奖励全部为 0），梯度为零，模型无法从失败中学习

On-Policy Self-Distillation (OPSD) 提供了一种有前景的替代方案：

  • 使用同一模型同时作为 teacher 和 student，通过不对称上下文产生差异
  • Teacher 拥有 student 无法访问的特权信息（如参考答案、验证信号），产生更可靠的输出分布
  • 通过 token 级 reverse KL 散度 提供密集的逐 token 监督信号
  • 只需单次 rollout，训练效率大幅提升

GUI-SD 由两个互补组件组成：

  • Visual Privileged Guidance（视觉特权引导）：用视觉特权上下文替代文本特权，使 teacher 保持信息丰富的软分布
  • Entropy-Guided Optimization（熵引导优化）：用自适应 token 加权替代均匀 reverse KL，在最有影响力的坐标 token 上集中优化

GUI-SD 框架：(a) Teacher 分支接收目标边界框 + 高斯软掩码 + hint prompt 的特权上下文。(b) 基于数位权重和熵门控的加权 reverse-KL 目标

用视觉特权上下文替代文本特权信息，让 teacher 接收目标感知引导而不直接获取精确坐标。

具体做法：

  • 红色边界框：在 teacher 输入图像的目标区域上绘制红色边界框
  • Hint Prompt：附加文字提示 "Hint: The answer is located within the red rectangle."
  • 高斯软掩码：对距离目标边界框越远的像素进行渐进式衰减，模拟"放大"效果
\[\alpha(x, y) = \exp\left(-\frac{d^2}{2\sigma^2}\right)\]

其中 $d$ 是像素 $(x, y)$ 到目标边界框最近边的距离（框内 $d=0$），$\sigma$ 根据目标大小自适应缩放（含最小下界以防止小目标被过度遮蔽）。

MMSkills: Towards Multimodal Skills for General Visual Agents

agent arXiv abs PDF arXiv 2605.13527
核心思想：这篇论文最核心的贡献，是把 visual agent 的 skill 从“文本步骤”升级成“带有状态判别与多视角视觉证据的多模态 procedure package”，再通过 branch loading 避免上下文污染，让这些 skill 真正在 GUI 和游戏环境里变成可调用、可验证、可迁移的外部知识单元。

问题与动机

这篇工作的核心问题是: 现有 agent 的“skill”大多是文本 prompt、代码片段、执行脚本或抽象动作模板，但对于真正依赖视觉感知的 agent，这类 skill 只告诉模型“做什么”，却没有充分编码“当前画面是否处在该 skill 应该被调用的状态”“应该观察哪些视觉线索”“什么时候可以验证已经完成”。因此，传统 text-only skill 很难稳定支持 GUI agent、game agent 这类需要持续看图决策的系统。

作者把这一缺口概括为 multimodal procedural knowledge。也就是说，视觉 agent 需要复用的不只是步骤文本，还包括与步骤绑定的视觉状态、局部证据、状态转移前后对比，以及完成验证线索。文章的目标不是再做一个更大的 memory bank，而是提出一套适合 visual agent 的可复用技能表示、自动生成流程以及推理时的调用机制。

从问题设定上，这篇文章比“长时记忆”“经验回放”更聚焦于 skill packaging。它关心的不是把历史轨迹完整存下来，而是从公开轨迹中抽取出可迁移的、结构化的、多模态 procedural unit，并在运行时以低污染方式送给主 agent 使用。

方法核心

作者的方法 MMSkills 由三部分组成:

  • Multimodal Skill Package: 定义视觉 agent skill 的结构化表示。
  • Skill Generation Pipeline: 从公开的、非测试集轨迹中自动生成 skill 库。
  • Branch-loaded Multimodal Skill Agent: 在推理时通过“分支加载”方式调用 skill，避免把整包多模态内容直接塞进主上下文。

上图对应论文的总框架图。它非常清楚地表达了作者的主张: skill 不再只是文本 procedure，而是“文本 procedure + 状态卡片 + 多视角关键帧”；这些 skill 由 Generator 从公开轨迹中抽出来；运行时主 agent 不直接吃完整 skill，而是先开一个 branch 去筛选相关 state card 和 visual evidence，再把压缩后的 guidance 返回主 agent。

作者先给出整体执行范式。Generator 把公开轨迹集合 $\mathcal{T}=\{\tau_i\}$ 映射成 skill 库 $\mathcal{M}=\{M_i\}_{i=1}^{N}$。测试任务开始前，系统会根据 instruction 先召回候选 skill 集合 $\mathcal{C}_I \subset \mathcal{M}$。在线执行时，主 agent 有两种模式:

\[\begin{aligned} \text{direct}: \quad & A_t = \pi_{\text{main}}(O_t,H_t,\mathcal{C}_I), \\ \text{branch}: \quad & G_t = \text{Branch}(O_t,H_t,M_t), \quad A_t = \pi_{\text{main}}(O_t,H_t,\mathcal{C}_I,G_t). \end{aligned}\]

这里 $O_t$ 是当前视觉观测，$H_t$ 是短历史，$M_t \in \mathcal{C}_I$ 是当前选择咨询的 skill，$G_t$ 是 branch 返回的压缩指导信号。关键点在于: branch 不直接替主 agent 执行动作，而是输出结构化 guidance，再由主 agent 结合实时画面决定最终动作。

branch 输出被写成:

\[G_t = (\text{applicable}_t,\text{subgoal}_t,\text{plan}_t,\text{do\_not\_do}_t,\text{verify}_t)\]

这 5 个字段分别对应:

  • 当前 skill 是否适用
  • 当前局部子目标是什么
  • skill-conditioned 计划是什么
  • 当前不该做什么
  • 如何验证已经完成

这比简单把一段长 procedure 塞回主上下文更像“受控中间推理接口”。

核心思想：这篇工作最重要的贡献，是把 self-improvement 从“生成更多题”提升到了“生成可复用的训练环境”。EvoEnv 证明了：只要 environment 具备 stable solve--verify asymmetry，模型就有可能在 zero-data reasoning RL 中持续获得有效的 frontier-level reward，而不是被固定分布或 policy-coupled pseudo-label 很快耗尽训练信号。

问题与动机

作者指出，很多 self-improvement / zero-data RL 工作都把问题看成：

  • 生成更多 question
  • 生成更多 rationale
  • 生成更多 hard example
  • 或者用 self-consistency / self-reward 给这些样本打标签

但这种思路有两个结构性问题：

作者在 appendix 里做了一张很有价值的定位表。它区分不同工作的两个轴：

  • self-improvement 合成的基本单位是什么
  • reward source 是否稳定，还是和当前 policy 耦合

在这个框架下：

  • R-Zero / SeRL / SQLM 一类工作：生成的是单个 problem 或 instruction，reward 更 policy-coupled
  • AZR / SCA / Agent0 一类：有 executable grounding，但往往是 per-instance verifier
  • RLVE：环境级训练对象，但环境是 hand-crafted
  • EnvScaler / AutoWebWorld 一类：也是 environment synthesis，但更偏 offline pipeline / tool sandbox

EvoEnv 的独特点是：

  • 合成单位是 reusable environment
  • reward source 是 frozen Python execution
  • 环境 admission 是 on-policy + solver-calibrated + novelty-controlled

方法核心

作者提出一个很强的 thesis：

self-improvement 的基本单位不该是单个 problem，而应该是 environment。

也就是说，模型不只是生成一道题，而是生成一个可执行环境。这个环境里至少包含：

  • sampler：采样 latent task instance
  • oracle：生成 reference answer
  • renderer：把 instance 渲染成自然语言 prompt
  • scorer：对 solver 的回答打分

这样一个 environment 一旦通过验证并进入环境池，它就不再依赖模型当前采样答案，而是通过执行代码提供稳定 reward。

EvoEnv 是一个 single-policy dual-role 框架：

  • 同一个 policy 既充当 generator，又充当 solver
  • generator 负责提议新的 Python environments
  • solver 负责在被接受的 environment pool 中解题

环境不是生成出来就直接用，而是只有在通过多层 admission 之后，才会进入 active pool。

作者强调，环境进入 pool 之前必须满足四类约束：

  • 可执行
  • 语义对齐
  • 难度贴近当前 solver 前沿
  • 环境池足够多样，不发生模板坍缩
  • Qwen3-4B-Instruct: 49.2 -> 53.1
  • Qwen3-4B-Thinking: 72.4 -> 74.8
  • Nemotron-Cascade-8B: 71.0 -> 73.2

这说明方法不是只对某个 model family 偶然有效。

作者在 appendix 里做了一张很有价值的定位表。它区分不同工作的两个轴：

  • self-improvement 合成的基本单位是什么
  • reward source 是否稳定，还是和当前 policy 耦合

在这个框架下：

  • R-Zero / SeRL / SQLM 一类工作：生成的是单个 problem 或 instruction，reward 更 policy-coupled
  • AZR / SCA / Agent0 一类：有 executable grounding，但往往是 per-instance verifier
  • RLVE：环境级训练对象，但环境是 hand-crafted
  • EnvScaler / AutoWebWorld 一类：也是 environment synthesis，但更偏 offline pipeline / tool sandbox

EvoEnv 的独特点是：

  • 合成单位是 reusable environment
  • reward source 是 frozen Python execution
  • 环境 admission 是 on-policy + solver-calibrated + novelty-controlled

GenEvolve: Self-Evolving Image Generation Agents via Tool-Orchestrated Visual Experience Distillation

agent arXiv abs PDF Project arXiv 2605.21605
核心思想：GenEvolve 不再把 open-ended image generation 看成“改写一次 prompt”这么简单，而是把整条生成过程重写成 agent trajectory：什么时候去搜索事实、什么时候找参考图、什么时候调用内部生成技能、最后如何把这些信息拼装成可执行的 prompt-reference program。真正的新意在于，它不仅用 GRPO 优化最终结果，还从同一请求下的 best/worst trajectories 中提炼 structured visual experience，再蒸馏回 student policy。

问题与动机

作者关心的是一个比“文生图提示词优化”更大的问题：复杂图像请求往往同时需要外部事实检索、视觉参考筛选、内部绘图知识调用、约束绑定与失败规避，因此本质上更像多步 agent 决策，而不是单轮 prompt engineering。

  • 外部信息需求：人物、地点、产品、年份、品牌等事实经常需要 search 才能补齐。
  • 视觉锚点需求：用户常常并不只要语义对，还要特定姿态、材质、构图与风格。
  • 生成知识需求：文本渲染、空间布局、attribute binding、数量计数等 failure mode 需要专门的 skill guidance。

因此论文的关键判断是：如果只给最终图像一个 scalar reward，模型很难知道究竟是 search query 写坏了、reference 选错了，还是 prompt 没把 layout / text rendering 约束绑定进去。

方法核心

GenEvolve 把一次图像生成轨迹建模成 tool-orchestrated visual trajectory。agent 在多轮交互里调用三类工具：文本 search、image search，以及按需查询内部 generation knowledge。最终输出不是普通 prompt，而是一个 prompt-reference generation program：

  • gen_prompt：面向 generator 的最终指令。
  • reference_images：按角色组织的参考图，而不是无结构图片堆叠。
  • selected_skills：显式激活 text_rendering、spatial_layout、attribute_binding 等内生绘图知识。

训练上分两层：

  • SFT 冷启动：先把模型教会基本的 tool orchestration 和 program 输出格式。
  • GRPO + experience distillation：同一 prompt 下采样多条轨迹，用图像奖励和文本程序充分性奖励做 group-relative optimization；再把 best / worst trajectory 的差异抽象成五类 visual experience，如 search、reference、knowledge、prompt 与 failure avoidance。

实验与结论

论文的实验重点不是单纯比较“谁生成得更好看”，而是比较 agent 是否真的学会了更好的工具编排、参考图使用和 failure-aware prompt synthesis。奖励也不是只看图像，而是图像质量与最终程序充分性共同决定。

  • 图像奖励：综合 factual faithfulness、visual correctness、text accuracy 与 aesthetics，其中 visual correctness 和 text accuracy 权重最高。
  • 文本奖励：检查最终 program 是否充分编码了 grounding facts、reference role、generation knowledge 与 executable constraints。
  • 核心收益：GenEvolve 学到的不是更会“润色 prompt”，而是更会在轨迹层面做决策，尤其体现在更合理的 search、reference 绑定和 skill routing 上。

最值得记住的实验信息是：作者把 best/worst trajectories 之间的结构性差异提炼成 teacher-only visual experience，再做 token-level distillation。这样 student 学到的不是抽象的“高分偏好”，而是更接近过程监督的具体决策经验。

价值、局限与启发

  • 价值：把 image generation 从黑盒 prompt optimization 推进到了真正的 agent post-training 场景，工具调用、参考图组织和内部绘图知识第一次被统一到同一个轨迹优化框架里。
  • 方法启发：best-vs-worst trajectory comparison 很适合视觉任务，因为最终图像 reward 很难直接分解到每一步，而 visual experience distillation 给出了一条可解释的中间桥梁。
  • 局限：系统仍然依赖 reward 设计和 teacher trajectory 质量；如果 search / image retrieval 本身不稳，后续蒸馏也可能学到噪声。
  • 阅读重点：这篇论文最该看的不是某一张定量表，而是“为什么单次 prompt rewrite 不够”以及“experience 槽位化后如何进入 distillation”这两个结构性设计。
