Terminal-World: Scaling Terminal-Agent Environments via Agent Skills

arXiv 2605.20876
agent arXiv abs PDF arXiv 2605.20876
核心思想：Terminal-World 的核心贡献，是把 agent skill 从“人给 agent 的执行说明”提升为 terminal-agent 数据合成的中心原语，并围绕它联合构建任务、环境与轨迹，从而以很低的数据量和成本，训练出比现有 terminal-agent 合成数据方法更强、更高效的模型。

问题与动机

这篇论文关注的是 terminal agent 的训练数据瓶颈。

和 API agent 不同，terminal agent 不是在固定工具列表里选一个 API 调一下，而是真正在命令行环境中执行 shell 命令、读写文件、安装依赖、跑测试、启动服务、调试环境。作者认为，这类 agent 的训练难点不只是“缺任务”，而是同时缺三样彼此强耦合的东西：

  • 任务指令：到底要 agent 完成什么；
  • 可执行环境：文件、依赖、初始状态、服务配置是否真实可运行；
  • 高质量轨迹：teacher 是否给出了有效、简洁、少走弯路的交互过程。

已有自动化数据构建方法，大多从某种 partial source 出发，比如：

  • 人工种子关键词或短描述；
  • GitHub 仓库；
  • 单一环境组件。

然后再让 LLM 去“把剩下的补完”。作者认为这种思路有三个根本问题：

  • 任务分布受限：因为起点本身很窄，最后合成出的任务也集中在少数种子分布里；
  • 环境和任务不对齐：任务语义和环境不是从一开始共同定义出来的，而是后补的，所以常常 fragile；
  • teacher 轨迹低效：teacher 在没有明确 procedural guidance 的情况下，只能自己探索，容易产生冗余命令和低质量路径。

论文的核心主张是：终端任务的数据构造，不应该从“半成品种子”出发，而应该从 agent skill 出发。

方法核心

作者把 agent skill 当作 terminal-agent 数据合成的中心原语。原因是 skill 天然同时编码了三件事：

  • what：要完成什么能力；
  • when：什么前提条件、环境状态下适用；
  • how：应该怎样执行。

这恰好对应 terminal-agent 训练样本最需要的三部分：

  • 任务指令；
  • 环境构造；
  • 教师轨迹。

所以 Terminal-World 的想法不是“先有任务，再补环境，再让 teacher 去试”；而是：

从 skill 出发，自顶向下联合生成 task instruction、environment blueprint 和 execution guideline，再把它们实例化成可执行 sandbox，并收集 teacher trajectory。

上图左边是方法总览，右边是性能概览。整篇工作的 pipeline 可以概括成四步：

  • Agent Skill Collection
  • Task Generation
  • Environment Building
  • Trajectory Collection

作者还进一步把 skill 扩展成：

  • single skills：单技能；
  • skill teams：同一子类中的多技能、多角色协作；
  • skill graphs：跨子类技能组合成更长的工作流。

因此它不是只在“单任务模板”层面扩数据，而是在 能力组合图 上扩展 terminal task 空间。

实验与结论

论文在 6 个 benchmark 上评估：

  • Terminal-Bench 2.0
  • AIME24
  • AIME25
  • DABench
  • TableBench
  • BIRD

其中 Terminal-Bench 2.0 是 terminal-native 编码 benchmark，其余几个被转换成 terminal-based task。

主结果表里最值得抓的，是和 Nemotron-Terminal 以及其他 <100B 开源 terminal-agent 模型的对比：

我觉得这张表最重要的不是“又提升了几分”，而是两层更深的结论：

  • 极高的数据效率

Terminal-World-32B 只用了 5.7k 训练样本，而 Nemotron-Terminal-32B 用了 490.5k。也就是前者只用了后者大约 1.2% 的数据。

  • 终端能力与跨任务泛化兼得

论文强调 Nemotron-Terminal 还混入了大量辅助样本，而 Terminal-World 只用 terminal-style trajectories，却仍能在非终端 benchmark 上匹敌甚至超过它。

这意味着作者构造的 skill-grounded trajectory，不只是“对 terminal bench 刷得准”，还学到了某种更通用的问题解决模式。

价值、局限与启发

虽然这篇工作很强，但我觉得也有一些自然限制：

  • skill source 仍然决定了能力边界

如果上游技能库本身偏向某些能力，合成出来的 terminal worlds 也会继承这种偏置。

  • LLM-as-a-Judge 与 GVR 本身也带来额外偏好

最终保留下来的任务，可能更偏向易于被 judge / verifier 描述和检查的任务类型。

  • 目前还是偏 SFT 式利用

虽然这篇的数据构造对 RL 很有潜力，但论文主要还是展示用这些轨迹做 SFT 的效果。

  • 环境构建质量对整体很敏感

如果 sandbox 或 verifier 质量不好，会把噪声传到 teacher trajectory 和 student 学习中。

这篇工作对 agent 方向很有启发，尤其是你现在经常看的那些 agent RL / agent data synthesis 论文里，它提供了一个很清楚的视角：

  • agent 数据的瓶颈不是只有 task instruction

更关键的是 task、environment、trajectory 三者的联合构造。

  • 真实技能文档可以成为训练数据原语

skill 文档比 seed keyword 或 repo 名更“结构化”、更贴近实际工作流。

  • persona 是数据多样性的廉价放大器

对同一技能注入不同 persona，可以很低成本地拓展使用场景。

  • 失败轨迹不是垃圾

对 terminal agent 来说，失败过程里的局部正确行为非常有学习价值。

Terminal-World 的核心贡献，是把 agent skill 从“人给 agent 的执行说明”提升为 terminal-agent 数据合成的中心原语，并围绕它联合构建任务、环境与轨迹，从而以很低的数据量和成本，训练出比现有 terminal-agent 合成数据方法更强、更高效的模型。
