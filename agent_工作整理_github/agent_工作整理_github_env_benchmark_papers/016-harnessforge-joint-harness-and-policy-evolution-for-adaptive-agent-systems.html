核心思想：把 agent 的外部执行框架 harness 与内部 policy 视为一个配对系统：先根据失败轨迹修改规划、动作和记忆接口，再用成功轨迹训练模型去执行新接口，从而缩小 executable compatibility gap。

1. 问题：框架变好了，模型就能执行好吗？

单独搜索 workflow 默认执行模型固定，单独训练 policy 默认交互接口固定。但复杂 harness 可能超出小模型的执行能力，强模型也可能受不合适的动作格式、状态表示和记忆接口限制。HarnessForge 因而将优化单元从单个模块改为可执行的 harness–policy pair。

\[\mathcal G=(\mathcal H,\mathcal R_\delta),\qquad \mathcal H=(\mathcal P,\mathcal A,\mathcal M).\]

$\mathcal P,\mathcal A,\mathcal M$ 分别是 planning、action、memory 组件；$\mathcal R_\delta$ 是在基座模型上通过 adapter 适配的执行策略。所谓 compatibility，关注的就是模型能否遵守这些接口并完成任务。

2. 框架：先改 harness，再让 policy 跟上

\[(\mathcal H^{(r)},\mathcal R^{(r)})\longrightarrow(\mathcal H^{(r+1)},\mathcal R^{(r)})\longrightarrow(\mathcal H^{(r+1)},\mathcal R^{(r+1)}).\]

每轮维护若干系统候选，执行以下闭环：

  1. 定位失败。Meta-agent 读取 rollout、执行统计和评测结果，将问题归因到 planning / action / memory，而不是笼统判断“模型推理差”。
  2. 借鉴历史经验并改写。Archive 保存历史设计、fault report 和评测向量；检索相关且表现好的案例，形成改进建议，再生成受约束的可执行代码 / 配置候选。
  3. 验证与筛选。Smoke test 检查可执行性并修复；按表现、token 消耗和延迟进行 Pareto 过滤。默认每轮 8 个提案，经两阶段 half-selection 保留 2 个。
  4. 适配执行模型。继承 parent policy，针对 survivor harness 训练增量 adapter，形成下一轮的系统配对。

Planning任务分解、重规划触发、验证步骤、终止条件和控制顺序
Action工具描述、参数 schema、路由、合法性检查和重试策略
Memory状态字段、写入条件、检索规则、摘要格式及暴露给模型的信息

搜索限制在 harness 内部，不修改数据集、evaluator、benchmark runner 或后端模型定义；这使结果仍能在固定任务与评分标准下比较。

3. Policy alignment：学习执行当前 harness

Harness 筛选时已经产生 rollout，训练直接复用其中的成功轨迹，拆成逐步决策对 $(z_t,y_t)$。输入包含任务、新 harness 规范、观测历史、当前记忆和可用动作；目标是下一步推理、工具调用、记忆写入或最终回答。

\[\mathcal L_{\mathrm{SFT}}=-\sum_{(z_t,y_t)\in\mathcal D_{\mathcal H_k}}\log p_{\mathcal R_{\mathrm{parent}}\oplus\Delta\delta_k}(y_t\mid z_t).\]

这里的 $z_t$ 表示决策输入，不是 logit。执行模型沿 parent lineage 继承，再用 harness-specific LoRA 增量适配。目标是学会当前接口的执行规范，而不只是提升通用推理能力。

主实验默认 SFT，原因是可以复用评估轨迹、节省额外交互；框架也支持 preference / RL-style 训练。因此，这篇工作的核心是结构与行为的联合适配，而不是某一个特定 optimizer。

4. 实验：联合适配的收益来自哪里？

基座为 Qwen3-4B / 8B，meta-agent 为 GPT-5.5；默认演化 3 轮。评测覆盖 ToolHop、HotpotQA、2Wiki、TMDB 和 API-Bank，其中 HotpotQA 与 2Wiki 在主表中归入 SearchQA。

消融：两边都要改，但 harness 侧贡献更大

4B 第 3 轮 ToolHop 为 52.82；去掉 harness evolution 降至 46.67，去掉 policy evolution 降至 50.26。SearchQA 则从 42.00 分别降至 37.00 和 39.00。结构调整带来主要收益，但不让 policy 跟进仍会损失性能。

Rollout 预算优势来自评估与训练复用同一批轨迹。更换为 RL-style alignment 可继续改善部分指标，但论文的训练目标分析也显示更高交互成本，不能把“默认 SFT 较省 rollout”理解为整体系统没有 meta-agent 成本。

5. 核心结论与边界

值得记住的是适配单元：agent 能力取决于框架提供什么接口，以及当前 policy 能否执行这些接口。故障定位 → 结构修复 → 策略对齐，比只把失败归为模型能力不足更有针对性。

  • GPT-5.5 参与诊断、生成和修复，真实成本还包含 meta-editing，而不只是 rollout 数量。
  • 搜索空间主要是单个 harness 的 planning/action/memory，尚不能据此推出复杂跨应用、多 agent 组织结构上的同等收益。
  • 默认训练只使用成功轨迹，失败反例和罕见错误的监督仍有进一步利用空间。
