实验与结论

论文在 related work 里对比了很多已有 benchmark，包括 HotpotQA、BrowseComp、WebQA、GAIA、WebShop、MMDocRAG、LoCoMo、EgoLifeQA 等。作者强调，HippoCamp 的独特点不在于“又多了一个多模态 benchmark”，而在于它同时具备三件事：

  • User Profile: 任务围绕具体用户展开，而不是公共知识库
  • File-System: 证据分散在真实文件系统，而不是单个网页或单个文档
  • Multimodal: 支持 text / image / document / video / audio 五类模态

因此它更接近一种 personalized multimodal memory benchmark，而不是普通的 retrieval benchmark。

价值、局限与启发

  • 规模仍然有限: 只有 3 个 archetypal profiles，尽管很深，但横向覆盖仍有限。
  • LLM-as-a-judge 仍有主观性: 作者做了 human audit，但 judge-based evaluation 还是可能引入偏差。
  • 环境不完全等于真实 OS 交互: 虽然是 device-scale file system，但仍然是 benchmark 化、受控化的环境。
  • 方法对比里产品级 agent 有系统性优势/限制混杂: 不同 agent mode 的 tool policy、系统接口、时间预算并不完全等价。

如果把这篇放在你现在的 agent 阅读脉络里，它的启发很强，尤其适合和 memory agent、OS agent、multimodal retrieval agent 连起来看。

从 benchmark 的标注结构看，一个很自然的后续方向是做：

  • file node
  • evidence node
  • entity node
  • temporal relation
  • support graph

也就是把个人文件系统转成可推理的 evidence graph，而不是只做 top-k retrieval。

HippoCamp 的核心贡献不是“又做了一个 agent benchmark”，而是第一次比较系统地把 personal file-system 上的个性化多模态记忆与推理 变成可诊断、可分解、可量化的 benchmark，并证明当前 agent 的主要短板不在检索本身，而在 检索后的证据理解、实体绑定、跨文件综合和最终验证。
