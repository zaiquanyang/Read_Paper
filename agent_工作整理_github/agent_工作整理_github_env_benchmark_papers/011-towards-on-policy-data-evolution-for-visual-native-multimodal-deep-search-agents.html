问题与动机

这篇 paper 关注的是 multimodal deep search agent。这类 agent 不是只做单轮 VQA，也不是简单把图像喂给模型直接回答，而是要在开放世界里连续调用工具，完成：

  • search
  • browse / visit
  • visual search
  • image manipulation
  • computation

最后再把跨模态证据汇总成 grounded answer。

作者认为当前多模态 deep search 系统有两个核心瓶颈：

  • 中间视觉证据不会“留在工作区里”继续被后续工具消费
  • 搜索、浏览、裁剪、旋转这些工具虽然会返回图像，但很多现有系统把这些图像当作“一次性观察结果”
  • 后续工具不能像处理文本上下文那样继续引用这些中间图像
  • 所以 agent 的视觉链式推理经常被截断在原始输入图像上
  • 训练数据构建是静态 recipe，不会随着 agent 能力变化而自适应
  • 现有做法大多先设计好一个数据合成流程，再规模化生成
  • 但 target agent 训练到不同阶段，需要的数据难度、能力覆盖、轨迹模式并不一样
  • 静态合成很难对齐当前 policy 的 learning frontier

方法核心

作者的主张不是只改模型，也不是只改数据，而是把问题看成一个 workspace + data generator + policy 的协同设计问题：

  • 在交互层面，先造一个 visual-native harness
  • 在数据层面，再用 ODE 做闭环、按 policy 状态演化的数据构造

换句话说，这篇文章的切入点很 agentic：它不是单纯提高模型视觉能力，而是提高 agent 使用视觉证据工作的能力，以及让训练数据随着 agent 的短板动态演化。

论文方法由两部分组成：

  • Visual-Native Agent Harness
  • 给 agent 一个支持持久化视觉状态的工作区
  • 核心是 image bank reference protocol
  • ODE: On-policy Data Evolution
  • 用当前 rollout 的反馈反过来更新下一轮的数据生成配置
  • 同时支持 SFT 数据和 RL 数据

图里左边是 visual-native harness，右边是 ODE 闭环。这个总图基本概括了全文。

这里的“on-policy”不是传统意义上的只说 RL，而是说：

  • 数据是否保留
  • 难度是否上调/下调
  • 哪个阶段该怎么修改

都由 当前 rollout policy 暴露出的失败模式 来决定。

因此它不是静态 recipe，也不是纯人工数据工程，而是 policy-conditioned data generator。

这点很漂亮。很多工作会把 SFT data curation 和 RL task generation 分成两套系统，而本文是在同一套框架下做 mode-specific rubric 和 policy-specific adaptation。

价值、局限与启发

  • 问题定义很到位
  • 把 multimodal deep search 的核心困难拆成“工作区设计 + 数据演化”两个层面，而不是只盯模型 backbone
  • 方法结构完整
  • harness、data generator、rubric、SFT、RL 串成了一个闭环
  • 实验扎实
  • 有主结果
  • 有 harness 消融
  • 有 static vs evolution 对比
  • 有机制分析
  • 对 agent 社区很有启发
  • 这篇 paper 不只是一个 benchmark 上提分，更像是在提出一种 multimodal agent training recipe
  • 系统很重
  • 9 工具 + graph organization + rubric analysis + config optimization
  • 训练和数据构建成本都不低
  • 对 LLM judge / analyzer 依赖比较强
  • rubric 打分、failure attribution、config update 都要靠强模型
  • 这意味着方法质量部分依赖 judge 的稳定性
  • 更多展示的是 recipe effectiveness，而不是理论解释
  • 为什么某些 rubric 组合最好、为什么某些配置更新最优，并没有更深层理论
  • 可迁移性仍有待验证
  • backbone 主要是 Qwen3-VL
  • harness 和 ODE 是否能无痛迁移到更多 agent stack、更多工具生态，还需要更多证据

如果你关心的是 agent / VLM / OPD 的细粒度数据构造，这篇 paper 有几个很直接的启发：

  • 可以把“可复用视觉记忆”看成 agent state design，而不是 prompt 技巧
  • 对 VLM agent 来说，memory 不一定只是文本 memory，也可以是 image-bank memory
  • on-policy 不一定只优化 policy，也可以优化 data generator
  • 这和你前面一直在看的 OPD 系列是有呼应的
  • 这里只不过把 on-policy 的对象从 answer distribution 扩展到了 task distribution...
