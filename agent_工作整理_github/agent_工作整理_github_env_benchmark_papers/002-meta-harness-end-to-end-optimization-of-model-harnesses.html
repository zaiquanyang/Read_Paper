Meta-Harness: End-to-End Optimization of Model Harnesses

agent arXiv abs PDF arXiv 2603.28052
核心思想：附录最后给了不少非常实用的经验，我觉得值得记：

问题与动机

很多人默认“harness 很重要”，但仍把它当工程经验；这篇则把它形式化成了明确的 outer-loop search problem。

方法核心

整体流程如下图所示。

外层循环非常简单：

  • proposer 读取 filesystem 中所有历史候选 harness 的代码、分数和执行日志；
  • proposer 写出新的 harness 候选；
  • 系统评估这个 harness；
  • 把新代码、得分和执行轨迹再写回 filesystem；
  • 重复迭代。

注意这里最关键的点不是“做了 evolution”，而是 proposer 有能力主动浏览一个持续增长的经验库，而不是被动吃一段预先压缩好的 prompt。

Meta-Harness 和很多 optimizer 最本质的区别不是有没有 Pareto frontier，也不是有没有 population，而是：

  • 它把完整历史暴露给 proposer；
  • proposer 可以跨很多旧候选去看原始代码和 execution trace；
  • proposer 不必局限于某个 parent，也不必只看最近一步。

附录里给了一个很有说服力的统计：

  • 在 TerminalBench-2 的一次搜索中，proposer 每轮中位数读取 82 个文件；
  • 其中 41% 是 prior harness source code；
  • 40% 是 execution traces；
  • 只有 6% 是 score/summary files。

这说明 proposer 并不是“装作能看 filesystem，实际上只在本地小修小补”，而是真的大量使用原始历史进行非马尔可夫式诊断。

作者刻意把 outer loop 设计得非常简洁，只保留：

  • population；
  • evaluation；
  • logging；
  • Pareto frontier。

它没有像很多方法那样手工设计：

  • parent selection heuristics；
  • mutation operator；
  • critique schema；
  • reflection template。

作者的观点是：这类控制结构越多，越像在把“如何诊断和改 harness”重新手工编码一次。Meta-Harness 反而把这些判断交给 proposer agent 自己做。

这背后的隐含立场很明确：

  • 如果 coding agent 足够强，外循环应尽量 minimal；
  • 真正重要的是让 agent 访问足够丰富的 raw experience；
  • agent 自己会学会怎样从这些经验里形成因果假设。

实验与结论

作者在三个任务域上验证：

  • 在线文本分类
  • 检索增强数学推理
  • agentic coding（TerminalBench-2）

这三个域共享的核心不是任务本身，而是都存在“harness 设计空间”：

  • 文本分类里，harness 决定 memory 如何组织；
  • 数学推理里，harness 决定 retrieval policy；
  • 代码 agent 里，harness 决定启动信息、状态流和完成逻辑。

价值、局限与启发

如果把这篇放到 agent 主题下，我觉得它最重要的启发是：

  • agent 的提升不一定来自更强模型，也可以来自更强 harness；
  • harness 自身可以作为一等公民被自动搜索，而不是只能靠人手工写；
  • 对 agent system 来说，execution traces 往往比 summary 更值钱；
  • coding agent 不仅可以 solve task，也可以当 “system optimizer”，去反过来优化自己运行的那套外部程序；
  • 未来很可能出现“模型权重 + harness 代码 + memory 结构”一起 co-design / co-evolve 的范式。

附录最后给了不少非常实用的经验，我觉得值得记：

  • skill text 非常重要；
  • search set 要足够难，不然没东西可优化；
  • 日志要 machine-readable、便于 grep；
  • 最好提供小 CLI 帮 proposer 看历史；
  • full eval 前要做 lightweight validation。

这些建议都很 agent engineering，而不是纯理论。

这篇工作最大的价值，在于它把“代码级 agent harness 本身可以被自动搜索优化”这件事做成了一个可信、可执行、跨任务域的范式。它不是简单把 LLM 用来写 prompt，而是让 coding agent 真正通过 filesystem 访问原始经验，去做程序级别的诊断、归因和改写。

如果只记三句话，我会记：

  • harness 和 model weights 一样重要，甚至在某些 benchmark 上更重要；
  • 对 harness engineering 来说，execution traces 这种原始经验比压缩 summary 更关键；
  • 足够强的 coding agent，已经可以开始自动做 “system-level agent optimization” 了。
