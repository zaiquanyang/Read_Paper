问题与动机

作者对 ByteDance Lark 平台上 154 个真实任务场景 进行深入分析，发现：

  • AI Agent 已能解决 GUI 导航和多轮工具调用等表层任务
  • 但在处理大规模、碎片化的文档工作空间时严重失败
  • 商业场景中撰写定制化提案需要跨十多个内容相关文件进行多文件协调
  • 现有 Agent 频繁出现关键信息遗漏、逻辑不一致、事实不准确

方法核心

Workspace-Bench 填补核心空白：单个 Agent 知识工作空间的关系结构。超越静态文件提供，系统评测 workspace reasoning 的六维度能力：

  • Workspace Exploration（工作空间探索）
  • Task-Supporting Files Utilization（任务支撑文件利用）
  • Result-Providing Files Utilization（结果提供文件利用）
  • Content Relations Understanding（内容关系理解）
  • Lineage Tracing（版本溯源）
  • Semantic Heterogeneous File Understanding（语义异构文件理解）

Workspace-Bench 包含三大模块：

  • 工作空间构建：5 个角色工作空间，74 种文件类型，20,476 个文件（最大 20GB）
  • 任务构建与标注：388 个任务，7,399 条评估 rubric，25 名标注者
  • 评估框架：双并行加速 + Agent-as-a-Judge

完整评估框架：Agent 初始化、双并行加速、多策略文件提取、BFS 回滚、Agent-as-a-Judge

实验与结论

论文将现有 Agent Benchmark 分为四类，逐一分析其局限：

Prompt-Driven（如 OneMillion-Bench、CL-Bench）：所有信息嵌入自然语言指令中，零外部文件交互，完全跳过办公工作流的核心媒介。

Open-Source/Environment-Driven（如 OSWorld、GAIA、WebArena）：需通过工具与动态环境交互，但主要聚焦 Action Grounding 或 API 编排，忽略本地文件生态系统中的导航与推理。

Task-File-Driven（如 OfficeQA-Pro、GDPVal）：引入真实文件处理，但直接将任务相关文件打包提供给 Agent，跳过了从复杂文件系统中独立搜索和筛选信息的挑战。

Workspace-Relevant（如 OfficeBench、TheAgentCompany、SWE-bench）：最接近现实，构建了文件系统环境，但存在三大瓶颈：

  • 单一风格文件系统，缺少角色多样性
  • 文件格式覆盖 <10 种，缺少 50+ 种真实办公格式
  • 任务设计缺乏对文件间协同关系的显式评测（聚合、语义关联、版本溯源）

测试 Agent Harness（4 个）：

  • OpenClaw：解耦双环执行架构，高层认知规划与底层工具调用分离，结构化知识存储 + 语义路由层实现跨会话共享记忆
  • Claude Code：高密度推理与深度工作空间集成，原生使用 MCP 和 SKILLs，混合状态控制策略（CLAUDE.md + 动态压缩算法）
  • LangChain DeepAgent：基于 LangGraph 持久 DAG 架构的白盒 Harness，解耦控制流与 LLM，内置规划工具（write_todos）确保执行路径透明可追踪
  • Hermes：内置学习循环的开源 Agent，四层解耦记忆引擎（静态身份指令 + 动态状态文件 + SQLite FTS5 档案），自学习机制将试错经验持久化为本地技能库

测试基础模型（7 个）：Opus-4.7、GLM-5.1、GPT-5.4、Gemini-3.1-Pro、Kimi-2.5、MiniMax-M2.7、Seed-2.0-Code

评估设置：Workspace-Bench-Lite（100 任务），Seed-2.0-Lite 作为 Judge LLM，标准化执行和评估 Prompt。

28 种配置（4 harness × 7 LLM）的评估结果：

  • Pass Rate 范围：27% ~ 67%
  • 平均 Pass Rate：47.4%
  • 最佳配置：OpenClaw + Opus-4.7（~67%），其次是 ClaudeCode + Opus-4.7、Hermes + Opus-4.7
  • 人类基线：80.7%，显著超越所有全自动 Agent...

价值、局限与启发

论文将现有 Agent Benchmark 分为四类，逐一分析其局限：

Prompt-Driven（如 OneMillion-Bench、CL-Bench）：所有信息嵌入自然语言指令中，零外部文件交互，完全跳过办公工作流的核心媒介。

Open-Source/Environment-Driven（如 OSWorld、GAIA、WebArena）：需通过工具与动态环境交互，但主要聚焦 Action Grounding 或 API 编排，忽略本地文件生态系统中的导航与推理。

Task-File-Driven（如 OfficeQA-Pro、GDPVal）：引入真实文件处理，但直接将任务相关文件打包提供给 Agent，跳过了从复杂文件系统中独立搜索和筛选信息的挑战。

Workspace-Relevant（如 OfficeBench、TheAgentCompany、SWE-bench）：最接近现实，构建了文件系统环境，但存在三大瓶颈：

  • 单一风格文件系统，缺少角色多样性
  • 文件格式覆盖 <10 种，缺少 50+ 种真实办公格式
  • 任务设计缺乏对文件间协同关系的显式评测（聚合、语义关联、版本溯源）
  • 首个系统评测 Workspace Learning 的大规模 Benchmark：填补了从原子化任务到工作空间级依赖推理的评测空白，六维度全面覆盖
  • 真实规模工作空间：5 个角色画像、74 种文件类型、20,476 个文件（最大 20GB），远超现有 Benchmark 的规模和多样性
  • 细粒度评估体系：7,399 条 rubric（平均每任务 19.1 条），覆盖 Foundation/Process/Result 三种类型，不仅评估最终结果也评估中间决策
  • 完整的评估基础设施：双并行加速（工作空间级 + 任务级）、多策略文件提取、并行 BFS 回滚、Agent-as-a-Judge，构成端到端自动化评估流水线
  • 深度实验分析：28 种配置 × 5 个发现 × 错误分析，揭示了 Agent 能力瓶颈的多个维度
  • Workspace Learning 五阶段理论框架：从 L0 到 L4 的演进框架和 Data Association Gap 概念，为未来研究提供了清晰的路线图
  • Workspace-Bench-Lite：100 任务子集保持分布一致性，降低 70% 评估成本，便于快速迭代...
