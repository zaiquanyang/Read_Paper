方法核心

当前 Agent 训练数据的来源存在显著局限：

  • 人类示范数据：高质量但成本极高、覆盖窄，无法规模化
  • 合成任务生成（SWE-bench、Terminal-Bench 等）：局限于特定领域（代码修复），任务通常是孤立的，缺乏丰富的上下文环境
  • WebArena 等环境：提供了交互界面但缺乏用户特定的持久化文件系统和工作历史
  • 核心差距：现有方法提供的是"任务"而非"工作环境"——没有真实的文件层次、项目历史、协作者关系和累积的工作状态

整个流水线包含三个核心阶段：

  • Synthetic Computer Creation：从 persona 创建用户特定的计算机环境
  • Long-Horizon Productivity Simulation：在合成计算机上运行数周的工作模拟
  • Experience Extraction & Skill Creation：从仿真轨迹中提取经验信号并转化为可改进 Agent 的 skills

价值、局限与启发

当前 Agent 训练数据的来源存在显著局限：

  • 人类示范数据：高质量但成本极高、覆盖窄，无法规模化
  • 合成任务生成（SWE-bench、Terminal-Bench 等）：局限于特定领域（代码修复），任务通常是孤立的，缺乏丰富的上下文环境
  • WebArena 等环境：提供了交互界面但缺乏用户特定的持久化文件系统和工作历史
  • 核心差距：现有方法提供的是"任务"而非"工作环境"——没有真实的文件层次、项目历史、协作者关系和累积的工作状态
  • 首个大规模合成计算机方法论：从 persona 创建完整的用户特定计算机环境，包含丰富的文件系统、项目历史和协作者关系，填补了 Agent 训练数据在"真实工作环境"方面的空白
  • 长期仿真规模惊人：每次仿真平均 2,272 turns、8.59 小时、31 次协作通信，远超现有 benchmark 的任务时长
  • 内容丰富的 artifact：生成的文件不是空占位符——DOCX 平均 14.6KB、PPTX 平均 593.7KB，Office 格式占 67.8%
  • 经验信号的有效性：从仿真轨迹提取的 skills 在域内（83% 胜率，+7.0pp）和域外（GDPVal 上 105 胜 67 负，p=0.002）都显著改进了 Agent 性能
  • 跨模型迁移：从 Sonnet 仿真提取的 skills 对 Haiku 和 Opus 也有正面效果
  • 可扩展的自改进循环：随着仿真数量增加，skill 质量持续提升（100→500→900 台训练计算机，胜率从 64% 升至 83%）
  • 详细的失败模式分析：跨文档一致性、协作者反馈遗漏、空白消息、版本混乱等系统性失败模式为 Agent 改进提供了明确方向
  • Artifact 视觉风格过于统一：当前 artifact 的内容虽然丰富，但视觉风格和格式跨计算机过于一致，缺乏用户或组织特定的设计偏好
  • 文件系统过于"干净"：真实计算机包含临时下载、重复草稿、废弃文件、截图、过时材料等噪音，合成计算机缺乏这种自然积累的历史
  • 协作者过于被动：当前模拟协作者主要是响应式的，而真实协作者有自己的工作、文件、会议、截止日期和演变状态...
