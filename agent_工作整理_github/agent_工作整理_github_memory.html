问题与动机

方法核心

文本记忆范式的根本限制：每个 token 占据相同的预算单元，无论其语义重要性如何。

  • 辅助性细节（背景、解释）与关键证据消耗相同的 token 预算
  • 保留更多辅助细节必然减少关键证据的空间
  • 无法选择性地降低次要信息的分辨率

如 Figure 1(b) 所示：要保留 100 tokens 的关键信息，系统被迫同时保留约 900 tokens 的辅助细节。

提出从 1D 文本记忆到 2D 视觉记忆的范式转换——将历史表示为图像而非 token 流。

核心优势：自适应信息密度（Adaptive Information Density）

  • 关键证据：通过标题、加粗、大字号等高视觉显著性布局呈现
  • 辅助细节：压缩到视觉上更小的文本区域
  • 总体预算通过分辨率控制（降采样）灵活调节

MemOCR 包含两阶段记忆生命周期：

Stage 1: Memory Drafting（文本域）

  • Agent 增量编辑持久化的 rich-text 记忆（Markdown）
  • 分配视觉优先级：结构化格式（标题层级、缩进、加粗、字号）
  • 与预算无关：生成单个 rich-text 记忆，内部的显著性结构在渲染后实现非均匀预算分配

Stage 2: Memory Reading（视觉域）

  • 轻量级渲染器将 rich-text 转换为 2D 记忆图像
  • 记忆成本按视觉 patch token 数量而非文本长度衡量
  • Agent 读取记忆图像生成答案

价值、局限与启发

范式一：Raw History Memory（原始历史记忆）

  • 检索并注入原始历史片段（如过去的对话）
  • 问题：检索到的片段可能冗余或有噪声，稀释信息密度

范式二：Textual Summary Memory（文本摘要记忆）

  • 将历史交互压缩为紧凑文本摘要，通过增量更新维护
  • 问题：线性 token 缩放 + 均匀信息密度
  • 范式创新：首次将 agent 记忆从 1D 文本流转换为 2D 视觉画布，实现自适应信息密度
  • Budget-agnostic drafting：生成一次 rich-text 记忆，通过渲染时分辨率控制适配不同预算，无需重新生成
  • 低预算下优雅降级：16 tokens 时仍保持 62.2%（vs MemAgent 31.6%），8x token 效率
  • 三个互补训练目标：Standard + Augmented Memory + Augmented Question 全面覆盖不同预算和精度需求
  • 7B+RL 超越 72B：预算感知训练比单纯 scale 模型更有效
  • 计算开销可控：理论复杂度与文本记忆相同，渲染器每 sample 仅 ~0.175s
  • 开源代码
  • 依赖视觉/OCR 鲁棒性：VLM 在极端降采样下可能产生幻觉或遗漏证据
  • 布局策略可能任务特定：为 QA 优化的显著性分配可能不直接迁移到规划、工具使用等场景
  • 额外计算开销：VLM 引入额外延迟，尤其在较短上下文时
  • 训练成本高：64×H800 训练 14 天（~21k GPU-hours/variant）
  • 仅在 QA 上评估：未测试规划、工具调用等更广泛 agent 场景
  • 失败模式：比较推理和容量溢出场景下仍有问题
  • Renderer 依赖：需要 FastAPI + Playwright + Chromium 的渲染管线
  • 视觉记忆是 agent 记忆压缩的新范式：对于长时程 agent，将文本记忆渲染为图像可实现自适应信息密度，比纯文本压缩更高效
  • Budget-agnostic + Resolution-adaptive 的解耦设计：生成时不管预算，使用时通过分辨率适配，这个设计模式可推广到其他需要多粒度信息保留的场景...

问题与动机

上：有限上下文窗口下 Agent 无法捕获偏好。下：受前额叶→海马体启发，解耦记忆为 Memory Guideline（组织）→ Agent Memory（更新）

方法核心

  • 静态工作流方法（Mem0、A-Mem、LightMem 等）：依赖手工设计的提取规则和更新模板，无法从交互反馈中学习，难以适应动态用户行为
  • RL-based 记忆 Agent（MemAgent、MEM-α 等）：将记忆操作建模为序列决策问题并用 RL 优化，但：
  • 仅依赖稀疏的结果级奖励（最终答案正确性），缺乏过程级监督
  • 记忆更新涉及自由形式的编辑（写什么/忘什么），动作空间巨大
  • 长程优化困难，训练不稳定，数据需求大

受记忆图式理论（Memory Schema Theory） 启发，本文提出将记忆机制解耦为两个维度：

  • 前额叶区域（Prefrontal regions）：根据当前上下文动态选择和配置合适的图式，塑造期望和注意力优先级 → 对应 How：记忆应该如何被组织
  • 海马体区域（Hippocampus regions）：实例化图式，编码具体的经历细节 → 对应 What：应该存储和更新什么信息

这种分离的优势：维持一个稳定的图式级组织先验来引导注意力和结构化，同时允许海马体系统在该框架内灵活编码上下文特定的经历细节。

核心问题：

> 能否构建一个基于图式的 Agent 记忆系统，其组织和更新机制以类似于人类大脑的方式演化？

MemCoE 是一个两阶段优化框架：

  • Stage 1: Memory Guideline Induction (MGI)（模块 ♣）：优化全局自然语言指导方针（模拟前额叶）
  • Stage 2: Guideline-Aligned Memory Policy Optimization (GMPO)（模块 ♠）：在固定指导方针下优化记忆演化策略（模拟海马体）

图：MemCoE 两阶段优化框架——MGI 迭代精炼自然语言指导方针，GMPO 使用指导方针定义结构化过程奖励并执行多轮 GRPO

MemLens: Benchmarking Multimodal Long-Term Memory in Large Vision-Language Models

agent arXiv abs PDF Code arXiv 2605.14906
核心思想：这一部分当前还没有补到更细的整理。

问题与动机

MemLens 关注的是 agent 场景里非常核心但经常被简化的问题：一个多模态助手经过很多轮、多 session 的交互后，能不能记住过去的图文证据、更新用户状态、跨 session 推理，并在证据缺失时拒答？

作者认为当前有两条主流路线。第一是 long-context LVLM，把完整图文历史直接塞进模型上下文窗口，让模型通过长上下文 attention 自己找证据。第二是 memory-augmented agent，把历史压缩、索引、存入外部 memory store，查询时检索相关内容再回答。问题是，之前没有一个 benchmark 能在同一多模态、多 session、长度可控的设置下系统比较这两条路线，而且很多所谓多模态记忆 benchmark 存在 text-only shortcut，即不看图也能答对。

这篇论文的核心贡献就是提出 MemLens：789 个问题，覆盖五类 memory abilities，提供 32K、64K、128K、256K 四档标准上下文长度，并且显式要求很多问题必须依赖视觉证据。作者评估了 27 个 LVLM 和 7 个 memory-augmented agents，最后结论很直接：long-context LVLM 短上下文更强，但上下文变长会退化；memory agent 长度更稳定，但因为存储时压缩图像而丢失视觉细节；两者都没有真正解决多模态长期记忆。

MemLens 最重要的质量控制是防止 text-only shortcut。作者使用 entity abstraction：先选择一个视觉 anchor，比如 Golden Gate Bridge，然后把文本里的实体名替换为“the bridge shown in <image>”。这样文本保留事实上下文，但实体身份必须从图像识别出来。

价值、局限与启发

这篇工作的局限主要有四类。

第一，MemLens 是 synthetic multi-session dialogue，虽然 filler 来自 ShareGPT/UltraChat，evidence sessions 经过人工审查，但仍不等同真实用户长期对话分布。

第二，agent 与 direct LVLM 的输入接口不完全对称。Direct LVLM 看原始图像，而许多 memory agents 只能看 BLIP-2 captions 或 embeddings。因此论文比较的是“当前公开 agent pipeline 的实际表现”，不是 memory-augmented architecture 的理论上限。

第三，评测依赖 LLM-as-Judge，尽管做了交叉验证，但全量 73,784 次 judge calls 中人工/交叉验证只覆盖一部分。

第四，数据集使用 4,695 张 public web images。作者有 negative-content filtering、watermark/stock-logo filtering、隐私策略、per-image provenance、takedown mechanism 和 frozen version tags，但这类 web-sourced image benchmark 天然存在版权与分布偏差问题。

MemLens 给 agent 方向的启发很明确：长期记忆不能只做“文本摘要 + 向量检索”。对于多模态 agent，memory store 必须保留足够的视觉证据，至少要能在查询时回到原图或高保真视觉片段，而不是只保存 caption 或低维 embedding。

另一个启发是，long-context attention 和 external memory 不是替代关系。Long-context LVLM 能直接 grounding 原图，但会随上下文变长退化；memory agent 长度稳定，但存储压缩导致视觉失真。下一代架构更可能是 hybrid：短期/中期用 long-context attention 保留原始图文，长期用结构化 memory 做索引和筛选，但 retrieval 返回的应该是可重新视觉 grounding 的 evidence package。...

MemRouter: Memory-as-Embedding Routing for Long-Term Conversational Agents

agent arXiv abs PDF Code arXiv 2605.00356
核心思想：> 决定"是否存储这一轮"是否真的需要一次完整的自回归生成？还是可以在嵌入空间中更廉价地完成？

MemRouter 的核心思想：将记忆准入决策从自回归解码解耦为嵌入级分类——写入端只做轻量级的前向推理，回答端保持独立的 LLM 生成。

问题与动机

这一部分当前还没有补到更细的整理。

方法核心

当前主流方案（Memory-R1、AgeMem、MemGPT 等）使用 LLM 本身作为记忆管理器，存在两个根本问题：

  • 每轮自回归解码成本过高：每个对话轮次需要一个或多个完整的 LLM 生成调用来做准入决策。以 Memory-R1 为例，每轮需要两次生成调用（事实提取 + 记忆管理器），一个 600 轮的对话需要约 1,200 次生成调用——在回答任何问题之前。对于每天处理数百个对话的系统，写入端开销可能主导总服务预算。
  • 与回答骨干耦合：写入端策略通常与下游回答模型联合训练或依赖其奖励定义，导致准入策略与特定回答骨干纠缠。升级到更新/更大的 QA 模型可能需要重新训练记忆管理策略。

> 决定"是否存储这一轮"是否真的需要一次完整的自回归生成？还是可以在嵌入空间中更廉价地完成？

MemRouter 的核心思想：将记忆准入决策从自回归解码解耦为嵌入级分类——写入端只做轻量级的前向推理，回答端保持独立的 LLM 生成。

  • 每轮自回归解码成本过高：每个对话轮次需要一个或多个完整的 LLM 生成调用来做准入决策。以 Memory-R1 为例，每轮需要两次生成调用（事实提取 + 记忆管理器），一个 600 轮的对话需要约 1,200 次生成调用——在回答任何问题之前。对于每天处理数百个对话的系统，写入端开销可能主导总服务预算。

  • 极致的写入端效率：记忆管理 p50 延迟从 970ms 降至 58ms（17×），端到端吞吐量提升 11×，证明嵌入级路由在实际部署中的巨大价值
  • Backbone 无关的设计：Router 仅 12M 可训练参数（0.17%），与回答骨干完全解耦。在 Qwen2.5-7B 上训练的 Router 可直接迁移到 Qwen3.5-35B-A3B 而无需重训
  • 全面优于 LLM Manager：在控制变量的 matched harness 下，每个问题类别都优于 LLM-based 准入，95% CI 不重叠
  • 优雅的监督训练：不需要 RL，仅用教师模型生成的 ADD/NOOP 标签做监督训练，10 分钟完成。RL 反而因冷启动和稀疏奖励失败
  • 选择性存储的价值随预算紧缩而增大：在 45.9% 存储率时差值达 11.4 F1，说明 Router 在资源受限场景下最有价值
  • 逐字存储的实证优势：发现存储原始对话文本优于 LLM 提取的结构化事实，因为保留了与 gold answer 匹配的措辞
  • 开放域性能不足：MemRouter (7B) 在开放域 F1 (27.1) 远低于 Memory-R1-GRPO (46.9)，归因于冻结回答 Agent 的推理能力

PREPING: Building Agent Memory without Tasks

agent
核心思想：PREPING 提出一种“无任务先验”的预训练式记忆构建框架：先在合成练习中分离地学习“出题策略记忆”和“解题执行记忆”，上线时仅携带 solver memory，即可在多个 agent 基准上显著提升初始性能并降低部署成本。

问题与动机

  • 现有 agent memory 方法大多依赖任务数据（task-informed），而真实部署前往往拿不到目标任务分布。
  • 直接上线在线探索（如 ACE-Online）成本高、回合长、早期试错重。
  • 需要一种 pre-task memory 方案：在“还没有正式任务”的阶段，就把工具调用、环境交互、可行性判断等能力沉淀到记忆中。

方法核心

PREPING 在预部署阶段循环执行三角色：

  • Proposer：基于 proposer memory 生成下一批合成练习任务。
  • Solver：基于 solver memory 执行任务并产出轨迹。
  • Validator：判断任务/解答可行性并给出筛选信号。

核心是不对称更新：

  • proposer memory（M_prop）接收所有结果信号，用于改进“练什么”；
  • solver memory（M_sol）只用 validator 判定可行的数据更新，用于提升“怎么做”；
  • 部署时保留 M_sol，M_prop 可丢弃或冻结。

价值、局限与启发

PREPING 提出一种“无任务先验”的预训练式记忆构建框架：先在合成练习中分离地学习“出题策略记忆”和“解题执行记忆”，上线时仅携带 solver memory，即可在多个 agent 基准上显著提升初始性能并降低部署成本。

  • 合成任务分布与真实任务仍可能存在偏移；
  • validator 质量影响最终记忆纯度；
  • 多轮预构建会带来额外离线算力与设计复杂度。

可拓展方向：

  • 学习型 validator（不只规则过滤）；
  • 跨环境共享 proposer 先验；
  • 与在线方法结合（PREPING warm-start + 少量在线自适应）。
  • 如果我们有奖励模型或评分器，可把 PREPING 思路改成“离线自博弈 + 评分门控写入 memory”；
  • memory 不必单体，可拆为“探索记忆（提案）/执行记忆（部署）”两路；
  • 在成本受限系统中，优先把高风险探索迁移到离线阶段。

MeMo: Memory as a Model

agent
核心思想：MeMo 把“新知识注入”从“重训主模型”改成“训练一个独立 Memory 模型 + 主模型多轮查询”，在不改主模型参数、可接闭源 API 的前提下，兼顾跨文档知识整合、噪声鲁棒性与可扩展更新。

问题与动机

作者关注 LLM 知识更新难题：

  • 预训练后知识静态，易过时；
  • 全量重训代价高且有灾难性遗忘风险；
  • RAG 检索受上下文窗口、跨文档整合能力和噪声干扰限制；
  • 一些“潜在记忆”方案又高度绑定特定模型，不易跨模型迁移。

核心目标是：在不改主模型权重的条件下，让系统获得可更新、可迁移、可抗噪的新知识能力。

方法核心

MeMo 包含两个角色：

  • Main model $\mathcal{M}_\theta$：冻结，负责推理和最终回答；
  • Memory model $\mathcal{M}_\phi$：专门训练，参数化编码目标语料知识。

推理时由 main model 通过结构化多轮协议向 memory model 提问并整合答案。

价值、局限与启发

MeMo 把“新知识注入”从“重训主模型”改成“训练一个独立 Memory 模型 + 主模型多轮查询”，在不改主模型参数、可接闭源 API 的前提下，兼顾跨文档知识整合、噪声鲁棒性与可扩展更新。

  • 强依赖高质量反思数据合成流程，前处理复杂；
  • memory 训练本身仍有成本；
  • 合并更新虽省算力，但当前性能损失还较大。
  • 可把长期知识维护拆成“专用 memory model + 通用 reasoning model”的双模型架构；
  • 对生产系统可先部署小 memory 快速迭代，再按收益扩容；
  • 若场景噪声文档多、上下文超长，多轮 memory 查询协议比一次性大上下文拼接更可控。
