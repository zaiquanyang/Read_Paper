总览：GUI Agent 正在从“点哪里”走向“如何可靠地使用一个计算机环境”

这些工作可以看成四条互相咬合的线：一是把 GUI 状态转移和历史经验显式记下来；二是提升点击坐标、局部视觉变化、状态歧义这些低层感知能力；三是让 agent 在 GUI action 和 tool/API/CLI 之间做路径编排；四是用可验证环境和 trajectory-aware judge 给长程任务提供稳定反馈。

记忆与自进化

GUI-explorer、EchoTrail、UI-Mem、UI-Voyager、OSExpert 都在回答：agent 能不能先熟悉环境，把可复用经验变成后续任务的资产。

Grounding 与感知

GUI-SD、ScreenSearch、DiffSpot 把坐标、局部视觉差异、相似屏幕歧义拆开看，避免把所有问题都塞进端到端 token 预测。

GUI + Tool 混合

ToolCUA 和 WeaveBench 的核心共识是：现代 CUA 不该是纯 GUI，也不该是纯 API，而要在同一条轨迹里编排多种接口。

可验证反馈

CUA-Gym 把训练样本变成 $(t,s,r)$ 的联合生成问题，WeaveBench 则强调只看最终产物会高估 agent，需要审计过程证据链。

综合启发：如果要做更强的 GUI Agent，最好别只盯着“模型点得准不准”

这一批工作拼起来，其实给出了一条相当清晰的路线：先让 agent 建立环境地图和经验记忆，再把坐标/区域/工具调用这类异质动作接到可验证后继状态上，最后用低噪声 reward 和 trajectory-aware judge 做闭环训练。

可以组合成的训练路线

  • 探索层：用 ScreenSearch/OSExpert/GUI-explorer 先熟悉环境，生成 state graph、transition memory、unit skills 和失败边界。
  • 记忆层：用 EchoTrail/UI-Mem 把成功轨迹、workflow、failure patterns 组织成可检索、可更新、可参与 RL 采样的 memory。
  • 动作层：对 click/bbox/drag 这类视觉参数，用 GUI-SD 的熵门控蒸馏和 ScreenSearch 的 outcome-level consistency 降低噪声。
  • 工具层：用 ToolCUA 的 next-state grounding 和 path reward 学 GUI/tool switching，而不是简单把 tool call 当文本模仿。
  • 反馈层：用 CUA-Gym 式 programmatic reward 做主训练信号，用 DiffSpot/WeaveBench 式视觉与轨迹审计做离线过滤或评测。

一个比较务实的判断

GUI agent 的下一个瓶颈很可能不是单纯“更强 VLM”，而是工程化地组织环境经验、动作后果和可验证反馈。换句话说，模型需要的不只是看屏幕，而是拥有一套关于屏幕如何变化、工具何时可靠、任务怎样闭环的外部记忆和训练基础设施。
