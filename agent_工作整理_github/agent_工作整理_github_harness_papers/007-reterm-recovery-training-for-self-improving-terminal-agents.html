核心思想与问题

让 agent 学会继承自己弄坏或只完成一半的环境，再把任务救回来。失败历史与环境状态共同构成新的训练起点，模型需要审计、保留、修复或舍弃已有进展。

Terminal agent 的错误会留下文件、依赖、进程和端口等残留。只保留聊天记录却重置环境，无法忠实训练恢复。ReTerm 更新的是执行任务的模型参数；harness 提供 Bash、快照、恢复、分叉与验证能力，本文没有训练程序编辑 proposer。

方法核心：恢复 SFT + 在线恢复 RL

  • ReTerm-10K：Qwen3.5-9B 在 TMax-15K 上自然失败，先保存环境快照、再运行 verifier，避免验证副作用进入恢复起点。DeepSeek-V4-Pro 从该状态与历史继续执行，不获得隐藏测试的详细失败信息。
  • 恢复 SFT：经成功、格式、合规和效率过滤，公开数据共 9,712 条轨迹；只监督 teacher 的恢复后缀，失败前缀和工具 observation 不计生成 loss，训练时仅保留简短恢复提示。
  • ReTerm-GRPO：当前策略持续产生失败；每个含失败的原始组随机保留一个失败起点，放入近期优先队列。从同一个失败快照建立独立环境，分别采样恢复续写。
\[\widehat A_i^c=\frac{R_i^c-\operatorname{mean}_j R_j^c}{\operatorname{std}_j R_j^c+\delta},\qquad c\in\{O,R\}.\]

原始组与恢复组分别在同一任务起点内计算优势，再联合更新同一策略。每批 8 个 original 组 + 2 个 recovery 组，每组 16 次独立尝试，共 160 条；恢复奖励只优化本次恢复续写，不回灌给导致失败的旧动作。

采用 clipped GRPO 式目标，论文与已核验配置均未使用 KL 项。全成功或全失败组仍无区分优势；恢复内部没有逐步过程奖励。

价值、局限与启发

值得借鉴的是verifier 前快照、真实失败状态独立分叉、恢复后缀监督与近期失败队列。它把失败现场显式转成训练对象，也给 harness 研究提供了同状态比较不同干预的思路。

  • 公开训练代码需要外部 task environment factory；文件、进程、服务与会话的忠实恢复及分支隔离仍是主要工程工作。
  • 缺少快照、存储、CPU 与 wall-clock 的完整等预算对照；队列策略、混合比例与自然/人工错误的控制消融有限。
  • 五类错误是事后行为标签，不是 harness 模块归因；部分恢复案例只展示局部修复，不能扩大为最终任务成功证据。
  • Self-improving 指训练时利用自身失败更新参数，不代表部署时每个任务在线更新模型。

原笔记已静态核验公开代码，未运行训练或完整 benchmark。若用于 harness proposer，需要另行加入代码修改与 controller state 兼容设计。
