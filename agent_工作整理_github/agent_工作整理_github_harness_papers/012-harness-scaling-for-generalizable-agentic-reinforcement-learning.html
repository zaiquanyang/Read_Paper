一句话概括：预先构造多种结构化 Harness，让同一个 agent policy 用 PPO/GRPO 在不同执行接口和流程上训练，从而提升对未见 Harness 组合及外部黑盒 Harness 的泛化；Harness 本身固定，不是被在线生成或修改的对象。

1. 核心思想与定位

普通 Agent RL 往往固定 system prompt、工具接口、观察格式、上下文管理和 workflow。策略可能学会适应这套接口，一旦换到另一套 Harness，原有任务能力就不一定迁移。本文把“如何执行”作为训练分布的一条独立 scaling 轴。

作者的目标是训练更能适应接口变化的执行模型，而不是寻找一套所有任务都最优的 Harness。训练和评测时 Harness 都由配置预先构造并固定，不存在推理时 proposer 动态改程序。

2. 五维 Harness 空间

Harness 被因子化为 \[h=(S,T,O,C,W)\]：system prompt、tool interface、observation、context management 和 workflow。每个模块各有 3 种实现，完整空间为 35=243 个组合。

  • S：直接规则、产品/UI 语境、叙事或角色化表达。
  • T：原始工具 schema、语义别名加干扰工具、不透明标识加干扰工具。
  • O：原始输出或加入不同类型的运行元数据。
  • C：完整历史、早期摘要加最近轮次、短历史加外部总结文件。
  • W：自由执行、先规划、规划并周期性检查进度。

有限预算下不穷举全部空间，而是选取 18 个训练配置：每个取值边际均衡，每一对模块取值也均衡出现。每个任务先分配一个 anchor Harness，再配一个 Hamming 距离较近的配置，默认每题接触 K=2 个 Harness，形成“全局覆盖 + 局部变化”。

3. 训练与评测

训练对象：Qwen3-4B-Instruct 与 Qwen3-30B-A3B-Instruct 的执行 policy。训练方式：RL，使用 PPO 或 GRPO；本文没有把 Harness proposer 或 Harness 参数作为学习对象，也没有新增 SFT 主线。

Harness Scaling 只改变 task-Harness 实例的采样和安排，PPO/GRPO 的优势估计与 token-level loss 保持不变。训练来自 ClawGym-Task13.5K workspace 数据，评测包含 ClawGym-Bench、JobBench-Easy、PinchBench，以及外部黑盒 Claude Code；另有 OpenClaw 补充结果。

4. 主要结果

下表为三项基准的平均分，单 Harness 与 Scaling 使用相同模型和 RL 算法；每格为 In-Space / Claude Code。

模型与方法ClawGymJobBenchPinchBenchAvg
4B GRPO · Single37.33 / 38.9610.24 / 5.7945.60 / 40.9529.81
4B GRPO · Scaling52.78 / 45.3713.55 / 14.8356.24 / 51.4739.04
30B GRPO · Single48.12 / 46.0214.79 / 10.0554.51 / 50.2537.29
30B GRPO · Scaling58.60 / 49.6215.48 / 14.2058.98 / 59.7842.78

Scaling 在两种模型和 PPO/GRPO 上都提高平均表现。以 4B GRPO 为例，平均分从 29.81 提升到 39.04；外部 Claude Code 上也保持正向收益。与在 OpenClaw 上训练再迁移的 black-box SFT/RL 对照相比，Scaling GRPO 在该设置下也更高，但结论依赖具体任务、接口和预算。

5. 消融与行为分析

  • 配置选择：在固定 18 个配置预算下，边际与二阶结构均衡优于随机选择或只做一阶均衡；完整 243 配置因每个配置获得的训练机会减少，反而低于结构化 18 配置。
  • 每题接触数量：K=2 优于只重复同一个 Harness；K=4 在固定预算下挤压独立任务覆盖，表现回落，说明局部多样性有合适强度。
  • 局部配对：把近邻分配替换为随机分配后下降，说明收益来自全局覆盖和同题局部变化的组合，而不是单纯增加 Harness 数量。
  • 行为指标：Scaling 在 interface handling、observation reading、state tracking、workflow compliance 和 error recovery 等维度多数提高，但这些是 LLM judge 的行为相关指标，不能单独证明模块级因果归因。

6. 边界与启发

本文最适合作为“多 Harness 训练提升策略泛化”的基线：先固定模块空间和训练预算，再用均衡设计与局部替换测试执行模型是否学会适应接口变化。它没有训练 proposer，不包含 rollout 内 Harness 编辑，也没有完成基于配置图的模块 credit assignment。

  • 五个模块和每模块三个实现是人为设计的有限空间，不等于真实框架的全部变化。
  • 不同模块的语义可能交叠，行为分数不能替代严格干预实验。
  • 完整 243 配置对照受固定训练预算影响，不能推出一般性的“配置越多越差”。
  • 论文材料为匿名投稿稿，官方代码、完整数据和复现成本目前未核实。

对 Harness 研究的启发：可以把这种结构化配置图作为 proposer 的候选编辑空间，但还需要真正的编辑干预、版本筛选和模块 credit 评测，才能从“多样性训练”走向“自动 Harness 演化”。
