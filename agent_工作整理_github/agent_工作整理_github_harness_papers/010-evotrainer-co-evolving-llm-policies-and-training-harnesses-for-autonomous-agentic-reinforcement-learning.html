核心思想：让执行模型和指导训练的诊断系统共同进步：Trainer 持续检查 rollout、奖励与行为，修改 RL 训练方案；当已有指标不足以解释结果时，再升级分析脚本、诊断流程和可复用技能。

1. 核心思想与定位

Agentic RL 的失败可能来自能力不足，也可能来自输出截断、奖励缺乏区分度、工具异常或环境泄漏。只看最终分数，很难判断下一轮该改什么；训练推进后，瓶颈还会变化。

EvoTrainer 把“如何观察、解释并指导训练”也变成可演进对象。这里的 Harness 位于训练侧，包括分析器、行为指标、奖励审计、分支比较与经验库。SWE 实验中，各方法的任务工具 scaffold、交互协议和评测 harness 保持固定。

2. 框架：诊断—干预—反思

  1. 收集证据并提出假设：读取轨迹、配置、日志与代码 diff，定位当前瓶颈。
  2. 构建候选版本：在独立 worktree 修改 reward、过滤、数据或训练配置；可行时先用历史轨迹回测。
  3. 训练并比较：同时看任务分数、奖励信号和行为健康度，保留、剪枝、回滚或合并有证据支持的改动。
  4. 补齐诊断缺口：若已有指标解释不了结果，编写新 analyzer、检索外部方法或调整分析程序，再把有效流程存为 Skill。

证据分为四层：Score 看任务表现，Signal 看组内奖励方差与 dead groups，Behavior 看搜索/编辑/测试等实际动作，Version 把结论连接到分支、改动和保留理由。记忆库保存版本谱系、失败案例、技能及检索记录。

3. 谁被训练，如何训练？

执行 policy：Qwen3.5 系列模型通过 RL 更新权重，配方随版本调整。Trainer：Claude Sonnet 4.6 负责实验工程，演进体现在工具、程序和外部记忆；论文没有展示对 Trainer 本身做 SFT / RL 参数更新。

SWE 最终配方采用 GRPO-style 训练，组合正确性 CR、指令遵循 IF、编辑前搜索 SBE 与编辑后测试 ETT：

\[r=\mathrm{CR}+0.1\,\mathrm{IF}+0.1\,\mathrm{SBE}+0.15\,\mathrm{ETT}.\]

配合 Clip-Higher 和组方差过滤等组件，重点是诊断后选出有效组合。StdGroupFilter 的可迁移性来自筛除低方差、缺少比较信号的组。

实际流程仍由人批准训练启动，并确认版本晋级或剪枝。标题中的 autonomous 应结合这一人工审核边界理解。

5. 诊断带来的实际改变

  • 拒绝被泄漏抬高的分数：Git 工具审计发现历史信息泄漏；受污染版本表面达到 48.80，清理后仅 31.04。高分需要行为与环境证据支撑。
  • 让奖励重新产生区分度：SWE 的 dead-group ratio 从 50% 降至 27.5%；新奖励对历史轨迹重评分后，让此前 45% 的 dead groups 重新出现方差。这里的 45% 是信号恢复比例。
  • 先修复可观察的工程瓶颈：Coding 先排查格式与输出截断，将最大输出从 20,480 提升到至少 32,768；Math 后期引入 Code Interpreter，部分收益包含工具能力变化。

6. 成本、局限与复现

可借鉴的结论：把训练分数与可审计的行为、奖励信号、版本历史连接起来，能让自动实验提出更有针对性的干预，也能识别“高分但不可用”的分支。

  • 成本口径：SWE 报告约 92,800 GPU-hours，人工搜索约 140,000；但约 4×108 个 Trainer-agent tokens 未计入 GPU-hours，尚不能据此断言端到端总费用更低。
  • 证据范围：单一训练 seed，验证集参与版本选择，测试任务数有限；任务级 bootstrap 不能替代多 seed 复验。部分版本同时改多项组件，难以拆出各项独立贡献。
  • 公开复现：代码与配方可供研究，但环境封装、StdGroupFilter 和部分分析脚本缺失，部分提示与经验记录脱敏；当前公开快照不足以直接完整复现整个流程。
