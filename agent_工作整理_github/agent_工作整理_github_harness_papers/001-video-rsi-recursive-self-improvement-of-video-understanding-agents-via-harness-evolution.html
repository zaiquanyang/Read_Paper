核心想法

Video-RSI 的改进对象不是模型权重，而是模型外面的 harness。同一个冻结语言模型分别充当 Solver 和 Editor：Solver 回答视频问题，Editor 根据失败轨迹和新增的视频证据修改 prompt、工具、观察处理、记忆与执行控制。每次修改都要经过 gate（决定是否接受新版 harness 的评估关卡），通过后代码才会传给下一轮，因此“递归”指 harness 版本递归继承，而不是无监督地反复训练模型。

  • Active Video Investigation：修改前重新查看训练视频，主动寻找原 trace 没有记录的证据，区分漏采样、感知错误和证据关联丢失。
  • Cost-Aware Harness Evolution：让旧版和新版 harness 回答同一组固定验证题，比较准确率和用帧数，满足接受规则才保留新版。这组验证题与训练集不共享视频（video-disjoint）；Editor 只能收到汇总指标，看不到验证样例、逐题输出和执行轨迹，因此称为“私有 gate”。

整体框架

给定当前 harness $H_t$、视频 $V$、问题 $q$ 和冻结模型服务 $\mathcal{M}$，Solver 执行一次完整任务：

\[ (\hat y,\tau,c)=\operatorname{Run}(H_t,V,q;\mathcal M). \]

其中 $\hat{y}$ 是回答，$\tau$ 是由工具调用、观察和决策组成的 trace，$c$ 记录资源消耗。每轮演化比较两个 harness 版本：当前版本（incumbent）$H_t$ 是此前已被接受、正在使用的版本；候选新版（candidate）$\widetilde H_t$ 是 Editor 根据训练侧证据修改出来、尚待验证的版本。gate 通过则令 $H_{t+1}=\widetilde H_t$，由候选新版接替当前版本；不通过则令 $H_{t+1}=H_t$，继续使用当前版本。两者的区别在于 harness 代码，底层模型权重保持冻结。

Active Video Investigation：先补证据，再改代码

这一阶段要解决的是“当前 harness 为什么答错、应该改哪个环节”。同一个错误答案，可能来自抽帧漏掉动作、视觉模型认错动作，也可能是已识别的证据在摘要或计数中被误用。失败 trace 只包含程序曾经获得的信息，Editor 因此先补看训练视频、核对旧记录，再决定怎样修改代码。

调查循环：逐步缩小失败原因的范围

调查信息集 $\mathcal{I}_0$ 最初包含当前代码、训练执行轨迹、可用标准答案和历史反馈。Editor 根据已有信息发出查询 $u_k$，得到新证据 $o_k$，再将这次查询与结果加入信息集：

\[ \begin{aligned} u_k&=\operatorname{Query}_{\mathrm{Editor}}(\mathcal I_k),\\ o_k&=\operatorname{Investigate}(u_k;H_t,\mathcal D_{\mathrm{tr}},\mathcal M),\\ \mathcal I_{k+1}&=\mathcal I_k\cup\{(u_k,o_k)\}. \end{aligned} \]

新增证据会影响下一步查什么：先检查是否漏看某个动作；如果旧记录已经识别了这个动作，就继续检查摘要和计数环节。查询可以改变观察的时间区间、采样密度或模态（视频、字幕、转录、OCR）。Editor 可以使用训练标签诊断，但发给感知模型的请求不包含标准答案，以免暗示它返回预期结论。

$k$ 是同一次修改尝试内的调查步骤，$t$ 是 harness 的修改尝试编号。调查时当前代码 $H_t$ 保持不变，增长的是 Editor 掌握的证据 $\mathcal{I}_k$；并不是每得到一个新观察，就立即更新一次 harness。

调查之后：把证据转成候选代码，再交给 gate

  1. 形成修改方案：Editor 汇总调查结果，判断更可能出错的环节，提出要修改的通用处理方式、适用条件，以及需要保留的正确行为。调查也可能暂时无法确定原因，并不保证每次都有有效修复。
  2. 生成并调试候选新版：Editor 修改提示词、工具、观察处理、记忆或执行控制代码，形成 $\widetilde H_t$，在训练侧试运行。调查信息集服务于这次代码修改；后续新题复用的是修改后的程序，而不是这道训练题的答案。
  3. 交给后面的 Cost-Aware Selection：评估器让当前版本 $H_t$ 和候选新版 $\widetilde H_t$ 回答同一组私有验证题，比较准确率与用帧数。通过 gate 才用新版作为下一轮起点；否则保留当前版本。

解释性例子（非论文实测案例）：一道“拿起杯子几次”的题，正确答案是三次，当前程序却回答两次。Editor 补看视频后确认第三次动作存在，又查到旧视觉记录其实已识别了三次，只是摘要丢失时间信息，导致两次不同动作被合并。调查因此支持“改进时间信息的保存与事件区分”，而非单纯增加抽帧。Editor 据此修改代码、生成候选新版；即使这道训练题改对了，仍要经过 gate，检查这套规则在其他视频上是否值得保留。

两阶段的衔接：主动调查负责“根据证据提出怎样改”，gate 负责“通过评估决定改动是否保留”。最终目标是得到能用于新视频的 harness，而不是持续扩大调查信息集。

Cost-Aware Selection：准确率和帧成本一起决定继承

gate = 固定验证集 + 接受规则。它回答的是“这次代码修改是否值得保留”。论文将数据分成三部分：

  • 训练集（216 题）：Editor 可以查看视频、标签和执行轨迹，用来调查失败原因、修改 harness。
  • gate 验证集（72 题）：独立评估器在同一组题上运行旧版和新版，汇总准确率和平均用帧数。Editor 无法查看这些验证样例，只能依据汇总反馈决定后续修改；video-disjoint 表示验证集使用的视频与训练集不重合，而不只是题目文字不同。
  • 外部测试集：演化完成、最终 harness 固定后，用其他 benchmark 检验效果。因此 gate 验证集用于选择版本，外部测试集用于报告最终表现。

当前版本 $H_t$（incumbent）在 gate 验证集上的准确率、平均成功视觉调用用帧数分别记为 $A_t$、$C_t$；候选新版 $\widetilde H_t$（candidate）的对应指标记为 $\widetilde A_t$、$\widetilde C_t$。带波浪号的量都对应候选新版，因此 $\Delta A_t=\widetilde A_t-A_t$ 表示“新版准确率减去当前版本准确率”。论文使用以下规则决定是否接受新版：

\[ \begin{aligned} g_t={}&[\Delta A_t>0]\land[\widetilde C_t\le(1+\alpha)C_t]\\ &\lor[-\epsilon\le\Delta A_t\le0]\land[\widetilde C_t\le(1-\beta)C_t]\land[C_t>0]. \end{aligned} \]
  • 准确率提升时，帧成本最多增加 $\alpha=0.1$；
  • 准确率持平或最多下降 $\epsilon=1/72$ 时，至少节省 $\beta=0.2$ 的帧成本；
  • gate 是当前版本上的局部接受规则，不是对所有未来任务的严格 Pareto 保证。

实验结果

演化在 LVBench 的 216 个训练问题上进行，使用 72 个 video-disjoint 问题作私有 gate，共尝试 20 次；其中 Active investigation 接受 5 次，只有轨迹信息的方案接受 3 次。最终 harness 冻结后在外部 benchmark 上评估：

BenchmarkAccuracy (%)Mean frames相对 VideoSeek
MLVU72.961.1+4.8 pp，帧数 −27.2%
LongVideoBench71.141.1+0.2 pp，帧数 −42.8%
Video-MME80.021.6+1.3 pp，帧数 +21.3%
EgoSchema78.242.4+5.0 pp，帧数 −41.4%

演化出的代表性能力包括：$H_{S2}$ Structured perception、$H_{S3}$ Global-64、$H_{S4}$ Relation graph 和 $H_{S5}$ Occurrence tool。结果显示准确率提升和帧数下降通常同时出现，但 Video-MME 是例外，不能概括成所有 benchmark 都更准且更省帧。

消融结论

  • 相对 trajectory-only，加入主动调查后四个 benchmark 的准确率分别提升约 8.2、3.9、6.3、1.6 个百分点；
  • 相对 accuracy-only gate，成本感知选择在 Video-MME 上把平均帧数从 43.1 降到 21.6，同时保持更高准确率；
  • 相对初始 harness，MLVU、LongVideoBench、Video-MME、EgoSchema 的准确率分别提升 10.5、3.4、6.6、6.8 个百分点。

结论与边界

Video-RSI 的核心贡献是把视频 Agent 的“看哪里、如何组织证据、何时调用工具”变成可测试、可继承的程序对象。主动调查弥补 trace 的观测盲区，成本感知 gate 则把候选修改约束在可接受的准确率—帧数折中内。

  • 递归继承的是 harness 代码，不是模型权重；
  • frame 指标只统计成功 visual-model calls 处理的帧，离线调查成本不计入其中；
  • 论文报告的是有限 gate 和外部 benchmark 的实证结果，不能把一次 gate 通过解释为对所有任务的全局保证；
  • 正文没有提供完整 patch diff，因此只能概括行为机制，不能据此虚构具体函数实现。
