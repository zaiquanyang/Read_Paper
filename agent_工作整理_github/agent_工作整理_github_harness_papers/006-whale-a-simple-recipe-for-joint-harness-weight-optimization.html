核心思想与问题

Agent 的表现取决于模型与 harness 的匹配；WHALE 用小段权重训练与程序搜索交替更新这对搭档。权重改变工具使用和推理行为，运行程序改变观察、反馈与终止条件，长期固定一方可能造成条件过优化。

Harness 是围绕模型的可执行程序，涵盖 prompt、工具解析、检索结果处理、历史管理、重试和退出逻辑。部署时保留优化后的模型—harness 配对。

方法核心：先权重，后程序

\[\begin{aligned}\theta_{k+1}&=\operatorname{ModelUpdate}(\theta_k;h_k),\\h_{k+1}&=\operatorname{HarnessSearch}(h_k;\theta_{k+1}).\end{aligned}\]
  • Online RSFT：固定 harness，每题生成 8 条轨迹，保留 verifier 判定成功的轨迹做在线 SFT；只监督模型生成 token，工具返回仅作上下文。实际主实验没有使用 PPO/GRPO。
  • Meta-Harness 搜索：冻结刚更新的模型；固定的 Claude Opus 4.7 proposer 读取源码、得分和轨迹，每次提出 3 个可执行候选，在 256 道搜索题上各采样一次，采用档案中最高分程序。
  • 切换时机：固定调度用每轮权重采样进度 E 与搜索预算 I；Adaptive 依据训练 reward 或搜索最高分的停滞切换，仍需 window、minimum、patience 参数。

E 表示原始 prompt 数据的采样进度；成功轨迹集合只训练 1 个 SFT epoch。搜索迭代 I 是否含初始 harness 评估，在论文伪代码与公开脚本中存在计数差异。

  • 主调度超过各领域最强对照 10.05、6.87、4.15 个百分点；FST 是同一框架的 prompt-only 搜索对照。

  • SearchQA 更依赖检索与控制流程改善；Math 首先需要权重训练缓解截断。候选评估太短会放大噪声，阶段太长也可能过拟合。

价值、局限与启发

最有用的是组件如何协调、何时切换的分析。实际实验可先定位格式、检索、截断与证据理解瓶颈，再决定优先改程序还是训练模型。

  • Math 仅 60 道测试题，缺少多种子误差条；初始 Search/Math harness 仅两轮，收益对强工程 harness 的适用性仍需验证。
  • 成本曲线只统计目标 rollout，排除 proposer compute，未统一 token、工具或训练时间。
  • SearchQA 中间数据未完整发布；公开 launcher 的学习率、迭代计数及 Adaptive 权重早停接线与论文存在差异，尚不能直接保证原样复现。

原笔记包含静态代码核验，未运行训练。建议独立设置 validation/promotion 选择配对，最终 test 单独报告。
