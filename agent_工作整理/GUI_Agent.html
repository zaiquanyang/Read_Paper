GUI Agent 工作整理

围绕 agent 目录中 GUI / Computer-Use Agent / Web Agent 相关论文的手动汇总：从视觉 grounding、环境记忆、自探索，到 GUI+Tool 混合动作和可验证评测。

总览：GUI Agent 正在从“点哪里”走向“如何可靠地使用一个计算机环境”

这些工作可以看成四条互相咬合的线：一是把 GUI 状态转移和历史经验显式记下来；二是提升点击坐标、局部视觉变化、状态歧义这些低层感知能力；三是让 agent 在 GUI action 和 tool/API/CLI 之间做路径编排；四是用可验证环境和 trajectory-aware judge 给长程任务提供稳定反馈。

记忆与自进化

GUI-explorer、EchoTrail、UI-Mem、UI-Voyager、OSExpert 都在回答：agent 能不能先熟悉环境，把可复用经验变成后续任务的资产。

Grounding 与感知

GUI-SD、ScreenSearch、DiffSpot 把坐标、局部视觉差异、相似屏幕歧义拆开看，避免把所有问题都塞进端到端 token 预测。

GUI + Tool 混合

ToolCUA 和 WeaveBench 的核心共识是：现代 CUA 不该是纯 GUI，也不该是纯 API，而要在同一条轨迹里编排多种接口。

可验证反馈

CUA-Gym 把训练样本变成 $(t,s,r)$ 的联合生成问题，WeaveBench 则强调只看最终产物会高估 agent，需要审计过程证据链。

GUI-explorer: Autonomous Exploration and Mining of Transition-aware Knowledge for GUI Agent

本地总结 GUI explorationtransition-aware memorytraining-free
GUI-explorer 的重点不是训练一个新模型，而是让 GUI agent 自主探索应用，把“当前界面、动作、下一个界面”的状态转移知识挖出来，形成可检索的 GUI knowledge base。

核心机制

  • 把知识单元从静态 screenshot 或 action label 提升为 transition tuple：$(observation, action, next\ observation)$。
  • 探索阶段记录动作后果，避免只记“这个按钮在哪”，而不知道“点完会去哪里”。
  • 推理阶段根据当前任务和界面检索相关转移知识，给 agent 提供动态 guidance。

价值与局限

它直接回应了 GUI agent 的一个基础痛点：视觉 grounding 不等于环境理解。缺点是探索质量受初始 agent 和环境覆盖限制，且 transition memory 如果没有去重、版本管理和失败过滤，容易膨胀成 noisy cache。

EchoTrail-GUI: Building Actionable Memory for GUI Agents via Critic-Guided Self-Exploration

本地总结 actionable memoryself-explorationcritic filtering
EchoTrail-GUI 把自探索轨迹变成“可执行记忆”：critic 负责筛掉无效或不可靠探索，保留可复用的成功路径，并在推理时按任务检索注入。

核心机制

  • 先让 agent 在 GUI 环境中自探索，生成大量 candidate trajectories。
  • critic 对轨迹质量、目标相关性和可执行性进行过滤，把经验从“日志”变成“actionable memory”。
  • 推理时检索相似任务或相似界面下的轨迹片段，作为上下文示范，减少从零 grounding 的成本。

和 GUI-explorer 的区别

GUI-explorer 更偏 transition-level environment knowledge；EchoTrail 更像 task trajectory memory。前者回答“这个动作会造成什么状态转移”，后者回答“过去类似任务是怎么完成的”。

UI-Mem: Self-Evolving Experience Memory for Online Reinforcement Learning in Mobile GUI Agents

本地总结 mobile GUImemory-guided GRPOonline RL
UI-Mem 的关键是让 memory 不只在推理时做 RAG，而是直接参与 online RL：用强/弱/无 memory guidance 构造组内差异，为 GRPO 提供更有信息量的 advantage。

核心机制

  • 维护 hierarchical memory，包括 workflow、subtask skill、failure pattern 等多层经验。
  • 在同一任务上用不同强度 memory guidance 采样 rollout，刻意制造 reward variance。
  • 训练后根据新成功/失败经验更新 memory，形成“memory 指导 rollout，rollout 反哺 memory”的闭环。

对 GUI Agent 的启发

它把“记忆”从静态检索模块升级成 RL 数据生成器。对于稀疏 reward GUI 任务，这比盲目多采样更聪明，因为 memory guidance 能主动创造组内可比较的成功/失败轨迹。

UI-Voyager: A Self-Evolving GUI Agent Learning via Failed Experience

本地总结 failed experienceGRSDself-evolving
UI-Voyager 的亮点是把失败轨迹变成训练资产：不是只保留成功示范，而是在成功/失败轨迹分叉处找局部 correction，用 step-level self-distillation 修正策略。

核心机制

  • 先通过 RFT/rollout 收集成功与失败经验。
  • 用 screenshot similarity 等方法定位 fork point：同任务中成功轨迹和失败轨迹从哪里开始走岔。
  • 在 fork point 上用成功动作作为局部 teacher，进行 GRSD 式 self-distillation，而不是把整条失败轨迹丢掉。

价值与局限

它非常适合 GUI 场景，因为 GUI 长程失败常常由一个局部错误动作触发。局限是 fork point 检测依赖状态相似度，如果界面变化大或隐藏状态不同，局部对齐会变得不稳定。

OSExpert: Computer-Use Agents Learning Professional Skills via Exploration

本地总结 professional CUAGUI-DFSskill set
OSExpert 把 CUA 从“临时完成任务”推进到“先学习一个专业软件环境”。它用 GUI-DFS 探索 unit functions，构建成功技能、失败边界和 fine-grained action primitives。

核心机制

  • Bottom-Up Self-Exploration：从顶层界面开始 DFS 探索菜单、工具栏、画布等功能。
  • Skill Set Construction：将通过验证的 plan/action sequence 存成 unit skills，再组合成 composite skills。
  • Fast Planner：用 skill-derived query-plan pairs LoRA 训练小模型，一次前向生成完整 plan，降低 step-wise planning 延迟。
  • Skill Boundary Check：失败技能也进入 skill set，让 agent 知道哪些任务当前能力边界内做不到。

关键结论

在 OSExpert-Eval 中，现有 CUA 在 long-horizon、unseen UI、fine-grained 操作上成功率很低；加入 fine-grained skills 后，GIMP 和 LibreOffice 的精细操作成功率明显提升。它给出的工程信号很明确：复杂坐标/区域控制不要全压给 VLM token decoder，应该外化成可验证 primitive。

Learn where to Click from Yourself: On-Policy Self-Distillation for GUI Grounding

本地总结 arXiv GUI groundingOPSDcoordinate distillation
GUI-SD 是把 OPSD 用到 GUI 坐标 grounding 的代表工作。它发现 naive OPSD 会退化成 SFT，于是用视觉特权上下文和熵引导优化，让 teacher 既强又不过度 one-hot。

核心机制

  • Visual Privileged Guidance：teacher 看到目标 bbox、高斯软掩码和 hint prompt，但不直接拿精确坐标文本。
  • Entropy-Guided Optimization：对坐标 token 做位置信用分配，高位数位权重更大；同时用 teacher entropy 过滤低置信监督。
  • Teacher EMA 更新：让 teacher/student 同源但保持稳定差异。

关键结论

相比 GRPO-Gaussian，GUI-SD 报告约 4x 训练加速，并在多个 grounding benchmark 上取得更高平均精度。它最重要的经验是：GUI 坐标蒸馏不能只把 bbox 当普通文本 token，需要控制 teacher 分布的熵和 token 权重。

ScreenSearch: Uncertainty-Aware OS Exploration

本地总结 arXiv OS explorationpartial observabilitystate graph
ScreenSearch 把 desktop GUI 的“看起来一样但其实不一样”变成可计算问题：用 UIA 结构做 screen retrieval / dedup，再用 matched-action outcome dispersion 估计状态歧义。

核心机制

  • 用 UIA-derived structural features 为 screen 建 canonical state ID，降低 cursor/focus 等无意义变化影响。
  • 维护 deduplicated state graph，让不同 history 中的相同界面共享统计。
  • 用同一 action 在相似 screen cluster 上的后继状态分叉程度定义 ambiguity，再用 PUCT graph-bandit 平衡 novelty 和 ambiguity reduction。

对训练的启发

它提供了区别于 token probability 的不确定性信号：region/action 的质量可以看它执行后进入哪个 state cluster，是否降低歧义。对 bbox、click point、drag region 这类异质动作参数蒸馏很有启发。

DiffSpot: Can VLMs Spot Fine-Grained Visual Differences in Web Interfaces?

本地总结 arXiv Code web interfacevisual diffperception benchmark
DiffSpot 不是训练 agent，而是精准测 GUI/web agent 的局部视觉验证能力：当网页只发生一个 CSS 属性级变化时，VLM 能否发现、定位并说清变化。

核心机制

  • 从真实网页生成 self-contained HTML，然后在 code space 做单元素、单属性 mutation。
  • 用 Grounding Gate 确保变化确实可见、局部、可定位，不让 benchmark 变成模糊图像差分。
  • 加入 no-diff pairs 测 hallucination control，区分“看不见”和“到处都觉得变了”。

关键结论

13 个 frontier VLM 在细粒度 web diff 上仍远未解决，最佳总体准确率也只有约 47.2%。失败更多依赖属性类型，而不是网页 domain，这说明 GUI perception 的瓶颈是 property-level localized visual verification。

ToolCUA: Towards Optimal GUI-Tool Path Orchestration for Computer Use Agents

本地总结 Code GUI-tool hybridMCP toolsonline agentic RL
ToolCUA 的核心判断很锋利：给 agent 工具不等于 agent 会用工具。难点不是“会不会调用”，而是“什么时候该用工具，什么时候必须回到 GUI grounding”。

核心机制

  • 从成功 pure-GUI trajectories 出发，合成 trajectory-aware tool library 和 GUI-tool interleaved trajectories。
  • next-state grounding：工具调用后预测的状态必须和原 GUI 轨迹中的后续 screenshot 对齐，避免幻想 API。
  • Tool-Bootstrapped GUI RFT：先 warmup SFT，再在 GUI/tool critical switching steps 上做单轮 RL。
  • Online Agentic RL：用 Tool-Efficient Path Reward 鼓励合适工具与更短路径，而不是鼓励工具调用越多越好。

关键结论

预实验显示，很多强模型加入工具后成功率反而下降：小模型 underuse，大模型 overuse。ToolCUA-8B 在 OSWorld-MCP 上通过混合路径编排提升到约 46.85%，同时减少平均步骤。它和 OSExpert 很互补：OSExpert 发现技能，ToolCUA 学会在 GUI-tool 空间里编排技能。

CUA-Gym: Scaling Verifiable Training Environments and Tasks for Computer-Use Agents

本地总结 arXiv RLVRprogrammatic rewardmock web apps
CUA-Gym 把 GUI/CUA 的 RLVR 数据构造成 verified tuple $(t,s_\text{init},s_\text{gold},r)$：任务、初始环境、目标状态和程序化 reward 必须一起生成、一起验证。

核心机制

  • Generator 生成环境状态和 golden state，Discriminator 在信息隔离下写 reward.py，Orchestrator 负责验证与过滤。
  • 使用五个 agreement conditions，例如 $r(V_\text{gold})=1$、$r(V_\text{init})=0$、reward 不含 forbidden patterns。
  • VLM judge 不直接作为 RL reward，而放在离线 filter 阶段检查程序 reward 与视觉结果是否一致。
  • CUA-Gym-Hub 合成可注入状态的 mock web apps，让同一环境支持大量任务。

关键结论

最终生成 32,112 个 verified tuples 和 110 个环境；GSPO 训练后在 OSWorld-Verified 和 held-out WebArena 上都有收益。它最值得借鉴的不是某个 policy trick，而是“环境工厂 + reward 工厂 + 数据工厂”的系统化范式。

WeaveBench: A Long-Horizon, Real-World Benchmark for Computer-Use Agents with Hybrid Interfaces

本地总结 arXiv hybrid interfacelong-horizontrajectory-aware judge
WeaveBench 评测的是下一代 CUA 的真实矛盾：agent 必须在同一条长轨迹里把 GUI 侧视觉/交互状态和 CLI/code 侧结构化操作持续编织起来。

核心机制

  • 114 个任务、8 个真实工作域，要求 channel non-substitutability、long-horizon execution、cross-application state。
  • 不是给 GUI benchmark 加 API，而是任务成功条件中 GUI 与 CLI/code 都不可替代。
  • Trajectory-aware judge 审计 final artifact、文件、截图、日志和 action trace，避免 outcome-only 评分高估 agent。

关键结论

interface ablation 中 GUI-only 和 CLI-only 都很低，Hybrid 最高到约 35.1%。trajectory-aware judge 会比 outcome-only 扣掉 10.3 到 20.2 个 PassRate points，说明强模型越来越可能“像成功一样失败”。

WebGen-Agent: Enhancing Interactive Website Generation with Multi-Level Feedback and Step-Level Reinforcement Learning

本地总结 web agentmulti-level feedbackStep-GRPO
WebGen-Agent 更偏“生成交互式网站”的 agent，但它对 GUI agent 很有参考价值：通过截图/交互反馈和 step-level RL，把最终页面质量拆成可局部改进的过程信号。

核心机制

  • 利用多层反馈评估页面，包括视觉外观、交互行为、局部组件和整体任务目标。
  • 通过 Step-GRPO 将长程网页生成的最终质量信号拆到中间步骤，缓解 sparse reward。
  • 对 GUI agent 的启发是：网页/GUI 编辑任务可以把“视觉 diff、DOM diff、交互测试”结合起来，而不是只让 VLM 看最终截图。

连接到 DiffSpot / CUA-Gym

如果 WebGen-Agent 的 feedback 能引入 DiffSpot 式 property-level visual verification，再结合 CUA-Gym 式 programmatic reward，就能更稳地训练 UI editing / website generation agent。

Odysseys: Benchmarking Web Agents on Realistic Long-Horizon Tasks

本地总结 web agentlong-horizonrealistic tasks
Odysseys 代表了 Web Agent 评测从短链路点击走向真实长程任务的趋势。它关注 agent 在复杂网页环境中持续规划、跨页面保持状态、处理现实约束的能力。

为什么放在 GUI Agent 页

Web agent 是 GUI agent 的一个重要子类：DOM/accessibility tree 能提供结构化信息，但用户最终面对的仍是视觉界面和交互状态。Odysseys 与 WeaveBench 的共同点是都在提醒：真实 agent 任务不是单步 grounding，而是长程状态维护和过程合规。

对训练的启发

长程 web benchmark 更适合用 trajectory-aware memory、可验证终态、局部过程奖励共同训练。如果只用最终 success/fail，很难判断失败来自 grounding、页面理解、跨页状态、还是工具使用策略。

综合启发：如果要做更强的 GUI Agent，最好别只盯着“模型点得准不准”

这一批工作拼起来，其实给出了一条相当清晰的路线：先让 agent 建立环境地图和经验记忆，再把坐标/区域/工具调用这类异质动作接到可验证后继状态上，最后用低噪声 reward 和 trajectory-aware judge 做闭环训练。

可以组合成的训练路线

  • 探索层：用 ScreenSearch/OSExpert/GUI-explorer 先熟悉环境，生成 state graph、transition memory、unit skills 和失败边界。
  • 记忆层：用 EchoTrail/UI-Mem 把成功轨迹、workflow、failure patterns 组织成可检索、可更新、可参与 RL 采样的 memory。
  • 动作层：对 click/bbox/drag 这类视觉参数，用 GUI-SD 的熵门控蒸馏和 ScreenSearch 的 outcome-level consistency 降低噪声。
  • 工具层：用 ToolCUA 的 next-state grounding 和 path reward 学 GUI/tool switching，而不是简单把 tool call 当文本模仿。
  • 反馈层：用 CUA-Gym 式 programmatic reward 做主训练信号，用 DiffSpot/WeaveBench 式视觉与轨迹审计做离线过滤或评测。

一个比较务实的判断

GUI agent 的下一个瓶颈很可能不是单纯“更强 VLM”，而是工程化地组织环境经验、动作后果和可验证反馈。换句话说，模型需要的不只是看屏幕，而是拥有一套关于屏幕如何变化、工具何时可靠、任务怎样闭环的外部记忆和训练基础设施。
